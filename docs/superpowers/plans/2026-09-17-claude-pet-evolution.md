### M0 — 完成

核对结论：计划 §2 表格里「已有基础」一栏基本属实，另有几项计划未列但已实现——`waitingOn`
（PermissionRequest 的结构化摘要，5.1 要的「保留权限摘要」已有）、进程存活走内核查询而非时间
戳、黏性完成气泡。

**§2「需复核的代码问题」经确定性序列复现，属实，且比推断更严重。** 三条断言：

1. `Chatter.justFinished` 确实识别出 B 结束
2. `Chatter.next` 因 `mood == .waiting` 直接 `return nil`
3. 冷却期内的完成同样返回 nil

关键在 `AppMain.render()` 的 `lastState = state` 无条件推进，下一帧 `previous` 里 B 已是
idle，`justFinished` 再也看不到它——**事件永久丢失，不是延迟**。

**§4.2「避免共用 .tmp」——修了，但计划描述的后果没能实证。** 8 个 hook 并发写同一 session
共用 `.tmp`，0 个损坏文件、0 个残留。因为 `replaceItemAt` 本身是原子 rename。真实风险是
**一次写入被另一次覆盖丢掉**（B 覆盖 A 刚写的 tmp，A 把 B 的字节 rename 上去），不是产生坏
JSON。唯一 tmp 照修（代价为零），注释按实证改写。

### M1 — 进行中

**§5.2 事件持久化 — 完成。** `Stop` 落一条记录到 `~/.claude/pet/events/`，不再依赖两帧快照
之差。`CompletionQueue` 承载纯规则：解析容错、幂等去重、7 天 / 500 条保留、已读优先清理、

轮次标识用**每会话自增计数**（`turn` 字段），不是 `lastPromptAt`。后者只有秒级精度，同一秒

猜测，也不是随机 UUID。

4 条；去掉「先丢已读」起初**没红**，说明测试构造有盲点（已读的正好是最旧的，两种策略不可
区分），改成已读位于中段后才真正红。

## 1. 目标与执行方式

把 Claude Pet 做成轻量的 Claude Code 桌面值班助手：可靠地告诉用户哪个会话需要处理、哪些回复刚结束、当前正在执行什么，以及如何快速回到对应会话。

按本计划的 M0 → M1 → M2 → M3 → M4 顺序实施。每个里程碑形成独立、可运行、可验证的增量。常规实现选择由执行者结合仓库约定决定；遇到接口缺失时先实现降级，不要伪造数据或把整个计划停在可选能力上。

开始工作时：

- [ ] 阅读仓库中的 AGENTS.md（如有）、README、设计文档和相关实现。
- [ ] 检查工作区已有修改，不覆盖用户工作；记录实际起始 commit SHA。
- [ ] 核对本计划中列出的现有行为，已经实现的项目标记完成，不重复开发。
- [ ] 建立执行清单；每完成一个里程碑更新结果、测试证据和剩余问题。
- [ ] 本计划本身不要求发布、推送或合并；遵循用户另外提供的 Git 工作流。

### 产品约束

1. 保留本地优先、轻量、安静的默认体验；默认不发系统通知、不播放声音。
2. 不增加云端服务、遥测、账号体系，也不为摘要调用模型。
3. 不读取完整对话来实现第一版活动记录；只保存实现功能必需的事件元数据。
4. 宠物不自动批准权限、不代用户输入终端命令、不自动重试任务；操作以查看、跳转、标记和提醒为主。
5. Hook 必须快速、有限时地返回，错误不能破坏 Claude 的执行链。
6. 保留原有配置备份、原子写入、校验和回滚机制；安装、升级和卸载都必须保护用户已有 hooks/statusline。
7. 状态必须如实表达：回复结束不代表任务成功；工具失败不代表任务失败；没有新事件不代表进程卡死。
8. 不要求本轮重新设计角色或制作整套新美术资源；先让现有角色支持清楚的状态表达。

| 范围 | 已有基础 | 本计划补充 |

## 4. M0：基线与数据设计

### 4.1 先核对相关文件

- Sources/PetEmit/HookEmit.swift、SettingsPatch.swift：事件解析和安装配置。
- Sources/ClaudePetCore/SessionState.swift、StateAggregator.swift、GlobalState.swift：状态与聚合。
- Sources/ClaudePetCore/Chatter.swift、HiddenSessions.swift：提醒与静音。
- Sources/ClaudePet/AppMain.swift、SessionWatcher.swift、WebBridge.swift：事件消费及界面更新。
- Sources/ClaudePet/PetPanel.swift、PetHostView.swift、PetMenu.swift：桌面交互。
- Sources/ClaudePetCore/TerminalTarget.swift、TerminalTitles.swift、UsageSnapshot.swift。
- Resources/pet/index.html、pet.js、pet.css，以及 PetLayout.swift。
- Sources/ClaudePetTests、hooks/test-pet-emit.sh、hooks/test-settings-patch.sh。

新增模块名称由执行者决定。纯规则放在 ClaudePetCore，系统权限、文件、进程及窗口操作留在宿主层。

### 4.2 分离三种数据

| 数据 | 目的 | 保存策略 |
| --- | --- | --- |
| 会话快照 | 当前会话状态和当前活动 | 原子替换，兼容旧 JSON |
| 事件记录 | 保证两次界面刷新之间的完成等事件不丢失 | 有界持久化，幂等消费 |
| 用户偏好/已读状态 | 别名、固定、静音、稍后提醒、已读 | 重启后恢复，原子写入 |

仅比较两个快照无法可靠捕捉快速 busy → idle → busy。为关键事件建立可独立消费的本地记录，例如每事件一个原子写入的文件；也可采用经验证的其他轻量方案。不要引入没有明确必要性的数据库或后台服务。

并发要求：

- 同一会话可能同时有多个工具事件；不能用单个“最后写入者”决定全部状态。
- 避免所有写入共用一个 .tmp 文件；临时文件必须唯一。
- 标识事件、会话、本轮、工具调用；关联字段优先使用实际 payload 中存在的稳定标识。
- 自建 eventId 用于消费幂等；重复语义事件仍需按会话/轮次/工具关联去重，不能把随机 UUID 当成重复投递检测。
- 如果事件源没有可靠序号，定义接收顺序、关联规则和迟到事件处理，不宣称能够恢复不可观测的精确顺序。
- 完成事件优先来自确认语义的 Hook，不从“会话消失/被静音/暂停展示”推断。
- 新字段缺失、未知枚举值、坏的可选字段都应降级；旧状态文件仍可读取。

推荐按独立维度建模，而不是把所有信息塞进一个 mood：活动 activity、关注原因 attentionReason、最新异常 lastFailure、展示情绪 mood。父会话与 Claude 内部子任务的事件须关联隔离；这属于 Claude 内部兼容，不扩展其他 Agent 平台。

## 5. M1：需要处理与未读完成

### 5.1 准确识别等待原因

- [ ] 优先使用 Notification 的结构化类型，消息文本只作为旧版本兼容兜底。
- [ ] 区分 permission、question/input、明确异常、普通 idle 通知。
- [ ] 未知通知保留信息，不默认全部升级为审批等待。
- [ ] 保留权限摘要：项目、工具、必要且简短的目标。
- [ ] 已知输入问题应保持待处理，普通回复结束后的空闲不应持续报警。
- [ ] 根据实际版本核对工具失败、异常结束、上下文压缩及输入请求相关事件；只安装支持的事件。
- [ ] 工具失败后仍有后续执行时，展示短暂警示和历史，不持续判为整个任务失败。
- [ ] 压缩状态有开始和结束/恢复规则；不因漏一个可选 Hook 永久停留。
- [ ] 正在执行的并行工具不能覆盖另一项尚未解决的审批等待。

“暂无新事件”显示最后活动时间；不自动写成“已卡死”。具体能力按安装版本与真实 payload 确认；无法可靠识别“思考”时显示“处理中”。

### 5.2 持久化完成队列

- [ ] 捕捉明确的本轮回复结束事件，保存会话、本轮标识、时间、当时显示名称和已读状态。
- [ ] 气泡是否允许展示与事件是否入队分离；冷却只能合并/延迟展示，不能丢记录。
- [ ] 宠物角标显示待处理数、完成未读数；零值隐藏，数量较大可显示 99+。
- [ ] 面板增加“需要我”“本轮已结束”“其他会话”分组。
- [ ] 点击完成记录：支持时尝试跳转，成功后标为已读；失败时保留未读并解释原因。
- [ ] 对无法跳转的记录提供明确的“标记已读”，不要关闭面板冒充成功。
- [ ] 支持逐条/全部标记已读；只打开列表不自动清空。
- [ ] 会话退出后，已经捕捉的完成记录仍保留，并标注会话已关闭。
- [ ] 新一轮开始不自动清除上一轮未读结果；可按会话折叠多个记录。

默认保留最近 7 天、最多 500 条完成记录，优先清理已读记录；达到硬上限或保留期限时可清理最旧未读，但必须显示清理提示，不能无声丢失。重启只恢复队列，不重新弹出全部历史气泡。

### 5.3 静音、稍后提醒与暂停语义

| 操作 | 语义 |
| --- | --- |
| 静音会话 | 不影响宠物情绪、不弹气泡，仍记录事件；隐藏在可展开的静音分组，主角标不计入 |
| 稍后提醒 | 延迟同一个待处理事项的升级/气泡，事项仍可查看 |
| 暂停宠物提醒 | 暂停情绪和气泡提示，仍采集事件；恢复后展示队列，不集中补弹 |
| 标记完成已读 | 只影响完成记录，不代表权限已批准或问题已解决 |

- [ ] 稍后提醒提供 5 / 15 / 30 分钟；保存到期时间。
- [ ] 等待已解决则取消旧计时；同会话出现新的独立待处理事项不能继承旧事项的延后。
- [ ] 到期后只对仍未解决的事项提醒一次，并继续受展示冷却控制。
- [ ] 休眠唤醒后基于当前时间重新计算，不密集补发过期提醒。
- [ ] 保留真实 UserPromptSubmit 自动解除静音的已有行为；增加逐项解除静音。

### 5.4 快捷跳转

- [ ] 提供可配置/可关闭的全局快捷键，默认不强占已有系统组合键。
- [ ] 跳到最早未解决且未静音、未延后的待处理会话。
- [ ] 没有目标时展开面板并显示“暂无待处理会话”，不做无关动作。
- [ ] 沿用现有 Orca/iTerm2 能力；不把增加其他终端支持设为完成 M1 的前提。
- [ ] 权限缺失、终端不存在、跳转失败都反馈明确原因；不向终端发送按键模拟审批。

### M1 必测验收场景

1. A 等审批时 B 结束：A 保持最高优先级，B 进入未读队列。
2. 两个会话在 20 秒内先后结束：两条均保留，可合并气泡。
3. 两次 UI 刷新之间一轮结束又开始下一轮：上一轮记录仍可见。
4. 重复消费同一事件、重启恢复：不产生重复完成条目。
5. 关闭/静音会话或暂停宠物：不生成虚假完成。
6. 一个工具失败但 Claude 继续执行：不显示“任务失败”。
7. 稍后提醒期间事项已解决：到期不再提醒；新事项不被旧计时压住。
8. 用户未授予终端跳转权限：保留未读，给出修复路径。
9. 多工具并发写入：无损坏 JSON，无审批状态被无关 busy 事件覆盖。

## 6. M2：会话识别与活动记录

### 6.1 会话标签

- [ ] 支持会话手动别名；优先级为别名 > 有意义的终端标题 > 项目名和短会话 ID。
- [ ] 展示可选 branch/worktree 标识，同目录多会话仍能区分。
- [ ] 支持固定关注会话；待处理分组优先级高于普通固定会话。
- [ ] 别名/固定按稳定 sessionId 保存；恢复会话时按实际 ID 行为处理，不凭目录名合并。
- [ ] Git 查询在宿主层异步缓存，不能在每次 Hook 内运行；非 Git 目录正常显示。

### 6.2 当前活动

把工具名转成可理解的短语，如“读取 LoginService.swift”“修改 login.spec.ts”“执行 npm test”。未知工具直接显示名称，不推测执行含义。

- [ ] 分开统计本轮运行时长、当前工具时长和距最近事件时间。
- [ ] PostToolUse 后不把已完成的工具继续当成运行中。
- [ ] 并行调用显示“2 个工具执行中”，详情可分别查看。
- [ ] 默认只显示必要目标或脱敏后的命令摘要，不记录完整 tool_input/output。
- [ ] 超长、多行文本截断；项目名、标题、路径全部按纯文本渲染。

### 6.3 最近活动

- [ ] 每个会话展示最近 20 条活动：类型、目标、开始/结束、明确结果。
- [ ] 工具开始/结束通过调用标识归并；标识缺失时采取保守降级。
- [ ] 默认历史保留 24 小时，所有会话总量最多 2000 条，定期有界清理。
- [ ] 提供清除历史；不读取 transcript，不生成基于模型的总结。
- [ ] 命令摘要避免保存 token、密码、环境变量值等敏感参数；优先采用允许字段而非仅靠正则遮盖。

验收：同项目三会话可辨认；连续工具不会共用错误的耗时；并行事件显示一致；名称中的 HTML/脚本字符不能执行；历史清理不删除用户偏好及未读队列。

- [ ] 不读取 OAuth 凭证，不直接请求额度 API。
- [ ] 面板显示模型、上下文比例、五小时/每周额度及数据时间；缺失字段单独降级。
- [ ] 兼容来源仍可独立工作，不为新能力强制安装 claude-hud。

### 7.3 连接健康检查

右键增加“连接状态”，各检查结果使用“正常 / 未配置 / 不支持 / 需要处理 / 未知”。

| 检查 | 展示及行为 |
| --- | --- |
| Claude Code | 检测到的版本和路径；未发现时说明 |
| Hook 配置 | 本项目 Hook 是否存在、安装版本、可执行文件是否可用 |
| 最近事件 | 最近收到时间；明确“尚未收到”不等同安装失败 |
| 当前会话 | 运行进程与已收到事件的区别；提醒新配置可能只对新会话生效 |
| 终端跳转 | 支持类型、最近失败原因、权限处理说明 |
| 额度来源 | 当前来源、时间、缺失或过期原因 |
| 状态文件 | 目录可读写性、坏文件计数；不因单个坏文件崩溃 |

- [ ] 演示模式模拟忙碌、审批、回答、结束、异常和压缩；不写真实会话/未读队列。
- [ ] 明确显示“演示中”，退出恢复真实状态。
- [ ] 可复制简短诊断摘要，去除凭证、完整命令和不必要的个人路径。
- [ ] 健康检查以只读为默认；任何修复动作使用既有安全安装机制，不直接覆盖整个 settings.json。

验收：缺少 claude-hud、旧版 Claude、statusline 字段缺失、过期缓存、无终端权限均可解释；安装→卸载后用户原有配置语义保持一致；已有 statusline 仍正常显示。

## 8. M4：动画、布局与节能

### 8.1 动画语义

| 实际状态 | 动画方向 |
| --- | --- |
| 读取/检索 | 看屏幕、翻文件 |
| 修改代码 | 敲键盘 |
| 工具执行中 | 看进度、等待 |

| 上下文压缩 | 整理文件 |
| 明确异常 | 警示标记 |
| 空闲 | 休息/睡眠 |

- [ ] 保留少量清楚的全局 mood，细活动用于动画变体，避免枚举爆炸。
- [ ] 普通活动切换设最短停留时间，避免高频闪动；新待处理/异常不被动画延迟遮住。
- [ ] 增加尺寸、透明度、减少动态效果、节能设置；设置持久化。
- [ ] 低动态模式保留状态可辨性；动画关闭仍显示角标和文本。
- [ ] 状态演示页复用真实资源，避免复制一份逐渐失效的 UI。

### 8.2 桌面可用性

- [ ] 根据屏幕空间向左或向右展开，气泡同样限制在 visibleFrame 内。
- [ ] 插拔显示器、分辨率变化、休眠唤醒后将宠物恢复到有效位置。
- [ ] 缩放后同步绘制、命中区域、拖动和点击穿透坐标。
- [ ] 面板可滚动；长名称、更多会话和更大的系统文字设置不会遮住关键操作。
- [ ] 不抢当前输入焦点，保持已有全屏及 Spaces 行为，发生变化需明确说明。

### 8.3 性能

README 的“空闲约 4% CPU”仅为历史描述，不是本计划实测基线。先在同一设备、构建类型和采样方法下记录基线。

- [ ] 空闲/屏幕锁定/不可见时暂停或降低不必要动画和定时刷新。
- [ ] 状态未变化不重复构建 DOM；显示计时采用必要的低频更新。
- [ ] 文件监听、进程探测和终端标题查询避免高频重复开销。
- [ ] 比较空闲、单会话执行、10 会话模拟、低动态模式的 CPU/内存及事件响应。
- [ ] 默认交互不明显退化；低动态模式 CPU 应显著低于现有默认空闲基线。报告实际数据，不设跨设备失真的绝对承诺。

视觉验收必须在 macOS 实机完成；纯 Swift 单元测试不能证明 Swift 命中区域和 Web 绘制一致。
