HQ 是什么

同时开着十几个 Claude Code session 时，难的不再是干活本身，而是记住每个 session 在做什么、它问过你什么、你有没有回答。HQ 把这些状态从对话里搬到文件里：

概念是什么存在多久
项目（project）一组相关任务，比如 claude-pet 下的几个功能。在 hq.json 里定义名字和对应的目录长期
任务卡tasks/T-012-xxx/TASK.md：目标、状态、下一步、待办、日志到任务完成
待回应事项（ask）session 问过你、需要你决定或去做的事，记在 asks.jsonl，直到你回应跟随任务
session绑定到某个任务的一条工作线程，随时可以关随你
负责人（lead）可选。负责某一类任务的 agent 角色长期

核心原则：任务卡才是真实状态，对话不是。session 关了没关系，下一个 session 绑定到同一个任务、读卡就能接着做。

开始使用

  1. 安装（一次）：在 claude-pet 仓库里运行 hq/install.sh --root ~/claude-hq（任务卡放在哪个目录都行）。它会先列出要做的每一项改动，确认后才执行；只想要看板、不想动 Claude 的设置，加 --no-hooks。需要 python3。详见安装会改什么。
  2. 打开看板：双击桌宠（再双击收起），或者右键桌宠 → Task Board…。
  3. 在 Sessions 栏给正在跑的 session 选一个任务绑定，或点 + New task 新建任务并顺手绑定。
  4. 之后就在看板上处理 Needs you 里的事情，在 Sessions 栏直接给 session 发消息。

装好 HQ 之前就已经开着的 session，最好重开一次，hook 才会生效。

Today：今天的任务

顶栏左边的 Today | All 切换两个视图（会记住）。Today 是工作台，只放今天挑出来的任务；All 是全局视图，什么都有。

  • 挑任务：顶部搜索框输入编号或标题后点 Add；或者在 All 里点任务行上的 ☆。今天新建的任务自动加入今天。
  • 接着昨天的：上一个有挑任务的日子里还没完成的任务，会在顶部提示，可以逐个 + 或 Bring all；Not today 今天不再提示。
  • 任务卡片直接带着：下一步、这个任务未回应的问题（可直接回应、送达）、未完成的待办（可直接勾）、正在为它工作的 session（👁 看对话、↗ 跳转、后台的 Attach）、▶ New session。点卡片的空白处展开完整的任务详情，再点收起（点输入框、勾选框、按钮、问题卡片或 session 行不会展开/收起，选中文字也不会）。展开后，待办和 session 只在详情里显示一份（详情里的更全：可以新增、看已完成的、绑定 session），卡片上方的简要列表会暂时隐去；✕ 把它移出今天（任务本身不变，可以 Undo）。
  • 右栏只列今天任务的 session，以及还没绑定任务的 session（方便顺手绑定）。
  • 今天的列表存在任务根目录的 focus.json，按日期保存。命令行：hq focus、hq focus add|remove T-012、hq focus carry。

看板上能做什么（All）

顶栏

  • 计数：未回应的 ask、你的待办、进行中的任务、在跑的 session。
  • Filter tasks…：按编号、标题、关联单号过滤任务。
  • Projects：管理项目（见项目）。Categories：增加、改名、删除分类（见分类与工作目录）。
  • + New task：新建任务，选分类，工作目录可以手填或从建议里选（也可以不填，绑定 session 时会自动记上），并可立即绑定一个 session。
  • ↻：立即刷新（平时每 4 秒自动刷新）。Guide：打开本说明。

Needs you（左栏）

  • Asks：所有还没回应的问题，最早的排在最上面。session 把同一个还没回应的问题再问一遍时，不会多出一条。每条四种回应，可以先在输入框写一句说明：
    按钮含义
    Do要做 / 同意，说明里写怎么做
    Drop不做了，不再跟踪
    Ask later要先问别人，之后再说
    No context不了解背景、答不上来，先归档
    送达：提出问题的 session 还在运行、而且在 Orca 或 iTerm2 里时，按钮下方有 send to ‹session› now（session 空闲时默认勾上）：回应会立刻作为一条消息发给它，它马上接着干。不勾、或者 session 不在线时，回应在它下一轮开始时送达。已经发出去的消息无法撤回，Undo 只会重新打开这个问题。
    说明里带图片：在说明框里 Cmd+V 粘贴截图，或把图片拖到这条问题上（PNG / JPEG / GIF / WebP，≤ 20MB），下方显示缩略图（✕ 去掉）；回应时图片路径附在说明后面，Claude 会读取它。
    一个任务有多条问题时一起回应：同一任务下有两条以上未回应的问题时，按钮变成"选择"——点一下高亮（再点取消，可以改选），不会马上发出；每条都选好后，点底部的 Send N answers，全部记下，并合成一条消息发给提问的 session。底部只有一个 send to ‹session› now 勾选框，管这一组。没选的问题留着，下次再答。Undo 会把这一批全部重新打开。
  • Your todos：所有任务里 @me 的待办，最新的在最前，每条标着已经等了多久（超过 3 天变黄）。点方框 = 做完；点 ✕ = 不做。
  • 左栏只有两块，分工是：Asks = 需要你回答的问题；Your todos = 需要你去做的事（所有任务里的 @me 待办）。session 需要你动手时会加 @me 待办，需要你回答时会提 ask。
  • 点条目的文字会打开上下文窗口（见下）；点任务编号标签会在中栏定位到这个任务（所在的项目组折叠着、或被搜索过滤掉时会自动展开、清除）。
  • 点错了可以撤销：勾选、✕、回应、Handled 之后，底部会出现带 Undo 的提示（8 秒）；勾掉的待办还会划线留在列表里 1 小时，旁边有 Undo。更久之后要反悔，点开任务，在方框上再点一下即可恢复；每次改动都记在任务卡的日志里。勾选按待办的文字认准是哪一条：看板刷新前 session 在前面插了新待办也不会勾错；那条待办已被删掉或改写时会提示你刷新。

上下文窗口

回答"这一项到底是什么、从哪来、去哪看"：

  • 问题（ask）：显示提出这个问题的那条 Claude 回复原文，以及是哪个 session 提的；可以直接打开那个 session 的对话。（这个功能上线之前记录的问题没有原文，可以打开对话去看。）
  • 待办：显示任务的状态、下一步、任务卡全文（含日志）。
  • 都会列出这个任务相关的 session：正在运行的可以看对话、跳转；已经结束的也能点 History 查看历史对话。
  • Show task 在中栏定位并展开这个任务；Open card 用编辑器打开任务卡。

Tasks（中栏）

  • 标题旁的 Project | Status 切换分组方式（会记住）：
    • Project（默认）：按项目分组，所有项目都会显示（还没有任务的项目显示"No open tasks"和 + New task，直接在该项目下新建），点整条组标题折叠或展开，拖动组标题调整项目顺序（在任务栏任意位置松手都行，以最近的组标题为准；拖动时各组临时只显示标题；"No project"固定在最后）；勾选 active first（默认勾上）时，有运行中 session 的项目（绑定到它的任务，或在它的目录里干活）排在最前，按最近活动时间倒序，组名旁显示绿点和时间，其余按你拖出的顺序；组名旁显示任务数、未回应问题数（黄）和运行中的 session 数（绿）；组内先按状态（等你 → 阻塞 → 进行中），每行带状态标签。没有项目的任务归在 No project。
    • Status：按 Waiting on you / Blocked / Active 分组，每行带项目标签。
  • Collapse all / Expand all：按项目分组时一键收起或展开所有项目组；按状态分组时一键收起所有点开的任务。
  • 勾 show closed 显示已完成和已放弃。
  • 组内排序：有正在运行的 session 的排最前 → 绑定过 session 的 → 其余；同一档里有未回应问题的靠前，再按最后更新时间。
  • 行尾黄色数字 = 未回应的 ask 数，绿色数字 = 正在为它工作的 session 数。
  • 任务编号的颜色 = 状态（看板上和小猫列表里都一样）：黄 = 等你处理、红 = 阻塞、青绿 = 进行中、蓝 = 已完成、灰 = 已放弃；悬停显示状态名。

Sessions（右栏）

  • 标题旁 List | Project 切换视角（会记住）：List 平铺所有 session，每张卡带项目名（蓝色）；Project 按项目分组、可折叠，顺序与中栏一致。session 的项目：绑定了任务的跟随任务的项目，没绑定的按所在目录匹配。
  • 每张卡三行：状态点（绿色 = 在干活，灰色 = 空闲，黄色 = 等你）和名字，右边是 Bind…（绑定到任务；绑定后显示任务编号，点它定位任务）；项目和状态，右边三个图标；最后一条回复。
  • 后台 session（带蓝色 background 标记）没有终端：Attach（终端图标）在你选的终端里打开 claude attach，就能直接交互；Stop（方块图标，点两次确认）停止它，对话保留，之后 Attach 可以继续。它不能从看板直接发消息。
  • 图标：👁 Peek 打开对话窗口；↗ Jump 跳到它所在的终端；💬 Message 展开消息框（默认收起，写了草稿会保持展开；空着时按 Esc 收起）。
  • 消息：点 Send 才发送，回车只是换行；发送过程中按钮显示 Sending… 并锁定，不会重复发送；效果和你在终端里亲手输入完全一样。session 空闲时，按钮等到 Claude 开始处理（最多 5 秒）才恢复；session 正忙时消息会排队，终端一接收就恢复，提示"Delivered — queued…"（不会干等 5 秒）。图片：在输入框里 Cmd+V 粘贴截图，或把图片拖进输入框（PNG / JPEG / GIF / WebP，≤ 20MB），会显示缩略图（✕ 去掉）；发送时图片存成本地文件、路径附在消息末尾，Claude 会读取它。只支持 Orca 和 iTerm2 里的 session；其他终端的 💬 是灰的，悬停会说明原因。
  • 红色 new 标记 = 小猫的红点：这个 session 干完了一轮，你还没看过结果。下面这些都算"看过"，标记和小猫的红点一起消失：👁 打开对话、↗ 跳到终端、从看板给它发消息（包括回应 ask 时勾了 send to … now）、在终端里直接给它发下一条。只是打开看板、扫到摘要、展开任务卡片不算。

对话窗口（Peek）

  • 显示这个 session 最近 30 条消息，Claude 的回复按 Markdown 排版。点窗口外面或按 Esc 关闭；从上下文窗口打开时，左上角 ← 返回。
  • 复制：选中文字 Cmd+C；每条消息悬停有 Copy；顶部 Copy all 复制整段对话。
  • 链接：网页链接点击用浏览器打开；文件路径（.md、.html、代码文件、目录……）点击用默认程序打开，相对路径按该 session 的目录解析。脚本、可执行文件和 App 只会在访达里定位，不会直接运行。
  • Claude 回复里的 hq-asks / hq-resolved 块显示成"Asked you"/"Answers recorded"列表，里面的链接可以点；普通代码块里的网址也可以点。
  • 底部可以直接回复。已经结束的 session 只能看历史。

和小猫的联动

  • 列表里显示任务：单击小猫弹出的 session 列表，每一行的第二行用暗灰色显示它绑定的任务（"标题 · 编号"），只有任务需要注意时末尾才加一个带颜色的状态词（needs you / blocked / done）。没装 HQ 或没绑定任务时，第二行和以前一样。
  • 问题也会提醒：未回应的问题计入小猫的角标（小猫会做出"有事找你"的样子），并列在小猫列表最上面的 Asks 分组里，点一下打开看板并定位到那个任务；出现新问题时，小猫上方弹出"T-012 asks: …"，点击跳到提问的 session。
  • 每天挑任务：每天第一次看到 session 活动、而今天还没挑任务时，小猫提醒一次"挑一下今天的任务"（会提到上次没完成的有几个）；双击小猫打开看板的 Today。

session 和看板怎么联动

session 绑定任务后，三个 hook 会让它遵守下面的规则：

  1. 先读卡，再干活，干完写回：状态、下一步、待办、日志都写回任务卡。一轮干了两分钟以上却没动任务卡，会被提醒一次去更新。
  2. 需要你确认的事会被记下来：session 把问题放在回复末尾一个 hq-asks 块里，每行一件事。它们会变成看板上的 ask（编号如 T-012.3）。 
    ```hq-asks
- 方案 v2 可以吗？
- 要不要找 Chengjie 要数据集？
```
  3. 没回应的问题不会被当成"不做"：每一轮都会把还没回应的 ask 重新提醒给 session。
  4. 两边都能回应：
    • 在看板上点按钮 → session 下一轮收到"用户在看板上回应了 …"；
    • 在 session 里直接回答 → session 用 hq-resolved 块记下来，看板上那条随之关闭。
  5. 草稿不等于完成：session 替你起草、需要你去发的东西，会变成一条 @me 待办，直到你勾掉。

什么时候用哪边：要看全局、批量处理问题、改状态，用看板；跟某个 session 深入讨论，在它的终端里直接聊，绑定之后它说的、问的同样会出现在看板上。

命令行用法

命令在 ~/.claude/hq/bin/hq。看板上的每个操作背后都是这些命令，所以在终端里或让 Claude 调用，效果完全相同。

命令作用
hq board [--all] [--json]打印看板；--all 含已完成；--json 给程序读
hq show T-012打印任务卡和它未回应的 ask
hq new "标题" [--category rca] [--workdir DIR]新建任务，输出编号
hq bind T-012 [--session ID]把当前（或指定）session 绑定到任务
hq unbind [--session ID] · hq whoami解绑 · 查看当前 session 绑定的任务
hq set T-012 status=blocked "next=等 token"改任务卡字段（status / next / project / category / title …）
hq addtodo T-012 "@me 发回复给 Atul"加一条待办
hq ref add|remove T-012 <网址或 QA-123>增删关联资源
hq todo T-012 2 done|drop|open改第 2 条待办的状态
hq log T-012 "决定先做 Neo4j"往日志追加一行
hq touch T-012标记今天看过（没有别的变化时用）
hq asks [T-012] [--all]列出未回应（或全部）的 ask
hq ask add T-012 "问题"手动加一条 ask
hq ask resolve T-012.3 do|drop|later|archive --note "说明"回应一条 ask
hq ask reopen T-012.3撤销回应，让它重新变成待回应
hq category list · add 名字 · rename 旧 新 · remove 名字 --to 其他管理分类（见下一节）
hq focus [add|remove T-012 …|carry]今天的任务列表
hq scan [--days 60] [--apply-projects --only a,b]从已有对话建议项目、列出 session（只读，除非加 --apply-projects）
hq sessions · hq peek SESSION -n 8在跑的 session（需要 Claude Pet）· 看某个 session 最近的对话（已结束的也可以，按 id 前缀查找本机对话记录）

在 Claude Code 里还可以用三个 slash 命令：/task T-012（绑定，或 /task 新任务标题 新建并绑定）、/board（显示看板）、/hq-onboard（从已有 session 初始化）。

从已有 session 开始

刚装好时，本机通常已经有很多 Claude Code session 和历史对话。两步把它们变成看板：

  1. 项目：Projects 面板里点 Suggest from sessions（看板为空时中栏也有这个入口）。它扫描最近 60 天的对话，按 git 仓库（不在仓库里的按目录）列出候选项目和 session 数，默认一个都不勾，勾选后点 Create。命令行：hq scan（只读）、hq scan --apply-projects --only 名字,名字。
  2. 任务：在任意 Claude Code session 里输入 /hq-onboard。Claude 会读这些 session，起草任务卡（状态、下一步、你的待办、相关链接、置信度），按项目列成表给你确认，确认之前不会创建任何东西；创建后，正在运行的 session 会绑定到对应任务，已结束的记在任务卡上、可以在看板上查看历史。

之后任何地方都能改：在看板上直接改，或者在 session 里让 Claude 改。从推断得来的状态在任务日志里标了"请核实"。

项目

  • 项目是任务的上一层，比如在 claude-pet 里做的几个功能都属于 claude-pet 项目。分类说的是"哪类工作"，项目说的是"属于哪个项目"，两者互不影响。
  • 每个项目有一个名字和若干目录，存在任务根目录的 hq.json 里。
  • 自动归属：新建任务（填了工作目录）或绑定 session 时，按目录归到对应项目；目录嵌套时取最深的那个。之后可以在任务详情里手动改。
  • 顶栏 Projects：新增项目（名字 + 目录）、改名（修改后点 Save，所有任务卡同步更新）、增删目录（+ directory）、拖动 ⠿ 调整顺序、删除（有任务时先选移到哪个项目或"无项目"）；有未归属的任务时，Assign by directory 一键按目录归属。
  • 命令行：hq project list | add 名字 --path 目录 | paths 名字 目录… | rename 旧 新 | remove 名字 --to 其他 | auto | order 名字…。

分类与工作目录

分类

  • 每个任务根目录有自己的分类列表，存在 hq.json 里。新装的默认是一组通用分类：feature、bug、investigation、review、ops、docs、other，可以随意改。
  • 在看板上点 Categories：改名 = 改输入框里的名字后按回车；删除 = 点 ✕；底部输入框回车 = 新增。命令行用 hq category …。
  • 分类只是写在每张任务卡上的一个标签，所以：
    • 改名会同时改写所有用到它的任务卡；
    • 删除没人用的分类直接删；删除有任务在用的分类，必须先选这些任务移到哪个分类（或"不分类"），每张被改的卡都会在日志里记一笔；
    • 手动编辑任务卡写了不在列表里的分类，看板照样显示，并标成"not in list"，可以在 Categories 里一键"Add to list"。

工作目录（workdirs）

不需要手动维护：把 session 绑定到任务时，会自动把这个 session 所在的目录记到任务卡上（不记你的主目录和任务根目录）。新建任务时也可以手填。看板据此在 session 的"Bind to task…"下拉里把相关任务排在前面。

关联资源的链接规则

Resources 里的完整网址直接可点。像 QA-9519、bigtest#3248 这样的简写，在任务根目录的 hq.json 里加 links 规则就能变成链接，适用于任何工单系统（Jira、Linear、GitHub Issues……）。按顺序匹配，第一条命中的生效；$1、$2 是正则里的分组：

"links": [
  {"match": "^([\\w.-]+/[\\w.-]+)#(\\d+)", "url": "https://github.com/$1/pull/$2", "kind": "pr"},
  {"match": "^([\\w.-]+)#(\\d+)",            "url": "https://github.com/your-org/$1/pull/$2", "kind": "pr"},
  {"match": "\\b([A-Z][A-Z0-9]+-\\d+)\\b",      "url": "https://your-site.atlassian.net/browse/$1", "kind": "ticket"},
  {"match": "^(ENG-\\d+)$",                   "url": "https://linear.app/your-team/issue/$1", "kind": "ticket"}
]

添加资源时推荐写成"标题 + 网址"，比如 2026-11 QA AWS key leak – action items https://…：看板只显示标题（截断到两三个词），悬停可看完整标题和网址。绑定的 session 也会按这个格式记录。

kind 决定分组：ticket（工单）、pr、doc（文档）、link（其他）。完整网址会按域名自动分类。

负责人（lead）

把任务根目录下的 templates/lead.md 复制到 .claude/agents/bench-lead.md，写清楚它负责的范围，然后在任务根目录运行 claude --agent bench-lead，跟它说"继续 T-020"。负责人会绑定任务、把重活交给后台 subagent、保持自己的上下文精简，并按固定格式汇报。小任务不需要负责人，绑定的 session 自己就是负责人。

注意事项

  • 只有绑定了任务的 session，提的问题才会进台账。
  • 后台 session 只能在信任过的目录里启动（在那个目录里正常打开过一次 Claude Code 并同意信任即可）；否则看板会提示原因。
  • 看板上的回应：勾选 send now 时立刻送达（Orca / iTerm2）；否则在 session 下一轮送达。
  • 直接发消息支持 Orca 和 iTerm2（第一次发到 iTerm2 时 macOS 会请求授权）。Ghostty、VS Code 等其他终端的输入框会置灰，只能 Jump。
  • Sessions 栏依赖 Claude Pet 的 hook，桌宠安装之前就开着的 session 不会显示。

What HQ is

With a dozen Claude Code sessions open, the hard part is no longer the work — it is remembering what each session was doing, what it asked you, and whether you ever answered. HQ moves that state out of the conversations and into files:

ConceptWhat it isLives
Projecta group of related tasks — say, the features of claude-pet. Defined in hq.json with a name and its directorieslong-term
Task cardtasks/T-012-slug/TASK.md: goal, status, next step, todos, loguntil the task is done
Asksomething a session needs you to decide or do, kept in asks.jsonl until you answerwith the task
Sessiona working thread bound to one task; close it any timeas long as you like
Leadoptional agent role that owns a category of taskslong-term

The one rule: the card is the truth, not the conversation. When a session is closed, the next one binds to the same task, reads the card and carries on.

Getting started

  1. Install once, from the claude-pet repo: hq/install.sh --root ~/claude-hq (any directory for your cards). It lists every change first and asks before doing anything; add --no-hooks to get the board without touching Claude's settings. Needs python3. See What install changes.
  2. Open the board: double-click the pet (double-click again to hide it), or right-click → Task Board….
  3. In the Sessions column, bind a running session to a task — or click + New task to create one and bind it.
  4. From then on, work through Needs you and message sessions straight from the board.

Sessions that were already running when HQ was installed should be restarted once so the hooks load.

Today

Today | All at the top left switches views (remembered). Today is a workbench with only the tasks you picked for today; All is the full board.

  • Pick: type an id or title in the box at the top and Add, or click ☆ on a task row in All. Tasks created today join automatically.
  • Carry on: open tasks from the last day you picked any are offered at the top — add them one by one or Bring all; Not today hides the offer for today.
  • Each task card carries its next step, its unanswered asks (answer and deliver right there), its open todos (tick them), the sessions working on it (👁 conversation, ↗ jump, Attach for background ones) and ▶ New session. click a blank part of the card to open the full task, again to fold it (clicks in a text box, checkbox, button, ask or session row don't fold it, nor does selecting text). Opened, the todos and sessions show once, in the details (which can add todos, show finished ones and bind sessions) — the card's short lists step aside; ✕ takes it off today (the task stays; Undo brings it back).
  • The right column lists only the sessions on today's tasks, plus sessions not on any task yet (to bind them).
  • Today's list lives in focus.json in your task root, one entry per day. From a shell: hq focus, hq focus add|remove T-012, hq focus carry.

What the board does (All)

Top bar

  • Counts: unanswered asks, your todos, open tasks, live sessions.
  • Filter tasks… by id, title or refs. Projects to manage projects (see Projects); Categories to add, rename or remove categories (see Categories and workdirs).
  • + New task: pick a category; type a workdir or pick a suggestion (or leave it — binding a session records its directory); optionally bind a session.
  • ↻ refreshes now (it also refreshes every 4 seconds). Guide opens this page.

Needs you (left)

  • Asks — every unanswered question, oldest first. A session asking the same still-open question again doesn't add a second one. Type an optional note, then answer:
    ButtonMeaning
    Doyes / will do — the note says how
    Dropwon't do, stop tracking
    Ask laterneed to ask someone else first
    No contextcan't answer this — park it
    Delivery: when the session that asked is live in Orca or iTerm2, send to ‹session› now appears under the buttons (ticked while the session is idle): your answer is typed into it as a message and it carries on at once. Unticked, or with the session gone, the answer reaches it at the start of its next turn. A message already sent can't be taken back — Undo only reopens the ask.
    Images in a note: Cmd+V a screenshot into the note box, or drop an image on the ask (PNG / JPEG / GIF / WebP, ≤ 20 MB); a thumbnail shows below (✕ removes it). The image's path goes with your note, and Claude reads it.
    Several asks on one task, answered together: when a task has two or more open asks, the buttons only pick — click to highlight (again to clear, or pick another), nothing is sent yet. When you've picked them all, Send N answers at the bottom records every one and sends them to the session that asked as one message; the single send to ‹session› now box there covers the group. Asks you didn't pick stay open. Undo reopens the whole batch.
  • Your todos — every @me todo across tasks, newest first, each showing how long it has waited (amber after 3 days). Box = done, ✕ = won't do.
  • The left column has just two parts: Asks = questions for you to answer; Your todos = things for you to do (every @me todo). A session that needs you to act adds an @me todo; one that needs an answer raises an ask.
  • Click an item's text to open its context window (below); click the task id chip to find the task in the middle column (its folded project group opens, a search that hides it is cleared).
  • Mis-clicks can be undone: after a tick, ✕, answer or Handled, a toast offers Undo for 8 seconds, and a ticked todo stays in the list, struck through with Undo, for an hour. Later than that, open the task and click the box again; every change is in the card's log too. A tick finds its todo by its text, so a todo a session inserted above it since the board last refreshed can't be ticked by mistake; if that todo was removed or reworded, you're asked to refresh.

Context window

Answers "what is this item, where did it come from, where do I look":

  • An ask: the Claude reply that raised it, and which session — open that conversation directly. (Asks recorded before this feature have no reply attached; open the conversation instead.)
  • A todo: the task's status, next step and the whole card, log included.
  • Both list the task's sessions: live ones open their conversation or jump; ended ones show their history (History).
  • Show task finds and opens the task in the middle column; Open card opens the card in your editor.

Tasks (middle)

  • Project | Status next to the title switches the grouping (remembered):
    • Project (default): one group per project — every project shows, even one with no open tasks (it offers + New task right there) — click the group bar to fold it, drag it to reorder projects (let go anywhere in the column — the nearest header decides; groups fold to their headers while you drag; "No project" stays last); with active first ticked (the default), projects with a live session — bound to one of their tasks, or working in their directory — come first, most recent activity first, with a green dot and the time; the rest keep your dragged order; it shows task count, open asks (amber) and live sessions (green); inside, tasks go by status (waiting → blocked → active) with a status tag. Tasks without a project are under No project.

  • Order within a group: tasks with a live session first, then tasks that had a session, then the rest; ties go to open asks, then the most recently updated.
  • Amber number = open asks, green = live sessions working on it.

  • Background sessions (blue "background" tag) have no terminal: Attach (terminal icon) opens claude attach in your chosen terminal so you can talk to it; Stop (square icon, click twice) stops it — the conversation is kept and Attach resumes it. They can't be messaged from the board.

Conversation window (Peek)

  • The session's last 30 messages, Claude's replies rendered as Markdown. Click outside or press Esc to close; opened from a context window, ← goes back.
  • Copy: select and Cmd+C; hover a message for Copy; Copy all for the whole conversation.
  • Links: web links open in your browser; file paths (.md, .html, source files, folders, …) open in their default app, relative paths resolved against the session's directory. Scripts, executables and apps are only shown in Finder, never run.
  • The hq-asks / hq-resolved blocks in Claude's replies show as "Asked you" / "Answers recorded" lists with clickable links; URLs inside ordinary code blocks are clickable too.
  • Reply from the box at the bottom. Ended sessions are history-only.

With the cat

  • Tasks in the list: in the session list a click on the cat opens, each row's second line shows the task the session is bound to, quietly in grey ("title · id"); a coloured status word is added only when the task needs attention (needs you / blocked / done). Without HQ, or for an unbound session, the line is what it always was.
  • Asks get noticed: unanswered asks count toward the cat's badge (the cat looks for you) and are listed under Asks at the top of the cat's list — a click opens the board at that task; a new one pops up above the cat as "T-012 asks: …", and clicking it goes to the session that asked.
  • Pick today's tasks: once a day, the first time the cat sees sessions at work while nothing is picked for today, it suggests picking (mentioning how many are still open from last time); double-click the cat to open Today.

How sessions and the board connect

Once bound, three hooks make the session follow these rules:

  1. Read the card, work, write back — status, next, todos and log go back to the card. A turn longer than two minutes that never touched the card is sent back once to update it.
  2. Questions for you are tracked — the session ends its reply with an hq-asks block, one item per line; each becomes an ask on the board (T-012.3, …). 
    ```hq-asks
- Approve plan v2?
- Ask Chengjie for the dataset?
```
  3. An unanswered ask is never a "no" — open asks are reminded to the session every turn.
  4. Answer on either side — on the board (delivered next turn), or in the chat (the session records it with an hq-resolved block and the board updates).
  5. Drafts are not done — anything the session drafted for you to send becomes an @me todo until you tick it.

Use the board for the overview, batches of answers and status changes; talk in the session's terminal for a deep discussion — once bound, what it asks there shows up here too.

Start from existing sessions

A fresh install usually meets a machine full of Claude Code sessions and history. Two steps turn them into a board:

  1. Projects: Suggest from sessions in the Projects panel (an empty board offers it too). It scans the last 60 days of transcripts and lists candidate projects — one per git repository, or per directory outside one — with their session counts. Nothing is pre-selected; tick and Create. From a shell: hq scan (read-only), hq scan --apply-projects --only name,name.
  2. Tasks: run /hq-onboard in any Claude Code session. Claude reads those sessions, drafts task cards (status, next step, your todos, links, confidence), shows them per project and creates nothing until you confirm; then live sessions are bound to their tasks and ended ones are recorded on the cards, their history one click away.

Change anything afterwards — on the board, or by asking Claude in any session. Inferred statuses are flagged "verify" in each task's log.

Projects

  • A project is the level above tasks — the features you build in claude-pet all belong to the claude-pet project. Category says what kind of work it is; project says what it belongs to. They are independent.
  • Each project has a name and some directories, kept in hq.json in your task root.
  • Automatic: creating a task with a workdir, or binding a session, puts the task in the project of that directory (the deepest match wins). Change it any time in the task.
  • Projects in the top bar: add one (name + directory), rename it (edit, then Save — every card follows), add or remove directories (+ directory), drag ⠿ to reorder, remove it (if tasks use it, pick where they go or "no project"); while some tasks have no project, Assign by directory sorts them in one go.
  • From a shell: hq project list | add NAME --path DIR | paths NAME DIR… | rename OLD NEW | remove NAME --to OTHER | auto | order NAME….

Categories and workdirs

Categories

  • Each task root keeps its own list in hq.json. New roots start with a generic set — feature, bug, investigation, review, ops, docs, other — change it freely.
  • On the board, Categories: rename by editing a name and pressing Enter; ✕ removes; the bottom box adds. From a shell: hq category ….
  • A category is just a label on each card, so:
    • renaming rewrites every card that uses it;
    • removing an unused one just removes it; removing one that tasks use first asks where those tasks go (another category or none), and every moved card logs the change;
    • a card with a category that is not in the list (say, hand-edited) still shows, marked "not in list" — "Add to list" in Categories adopts it.

Workdirs

They maintain themselves: binding a session to a task records the session's directory on the card (never your home folder or the task root). You can also type one when creating a task. The board uses them to list matching tasks first in a session's "Bind to task…" menu.

Link rules for resources

Full URLs in Resources are clickable as they are. Shorthand like QA-9519 or bigtest#3248 becomes a link once you add links rules to hq.json in your task root — for any tracker (Jira, Linear, GitHub Issues, …). Rules are tried in order and the first match wins; $1, $2 are the regex groups:

"links": [

Cards are plain Markdown — edit them by hand or keep them in git. asks.jsonl is an append-only event log; change it through the board or the CLI only.

Leads

Copy templates/lead.md from your task root to .claude/agents/bench-lead.md, describe its scope, then run claude --agent bench-lead in the task root and say "continue T-020". A lead binds to the task, delegates heavy work to background subagents, keeps its own context small and reports in a fixed shape. Small tasks don't need one — the bound session is the lead.

Good to know

  • Only sessions bound to a task have their questions tracked.
  • A background session can only start in a folder you have trusted (open Claude Code there once and accept); otherwise the board says so.
  • Board answers: with send now ticked they arrive at once (Orca / iTerm2); otherwise at the session's next turn.
  • Messaging works for Orca and iTerm2 (iTerm2 asks for Automation permission the first time). In other terminals (Ghostty, VS Code, …) the box is greyed out — Jump only.
  • The Sessions column relies on Claude Pet's hooks; sessions started before the pet was installed don't appear.

What install changes · uninstall

The pet and HQ are two separate installs:

StepChanges
1. The pet (scripts/install.sh, or install.sh in the release)the app; ~/.claude/pet/; 11 hooks appended to ~/.claude/settings.json (backed up first) so it can see session state.
2. HQ (hq/install.sh, optional)lists every change and asks first: ~/.claude/hq/; your task root (missing files only); the /task and /board commands (--no-commands skips); 3 hooks appended to settings.json (--no-hooks skips).
  • HQ's hooks only act in sessions bound to a task (add the task's rules, record questions, remind it to update the card); elsewhere they read one small file and exit.
  • HQ never edits a global CLAUDE.md — it only puts one in your task root, for that folder.
  • The board's Sessions column reads the transcripts on this machine (~/.claude/projects) to show recent messages. Nothing leaves the machine.
  • Installed with --no-hooks, the board, cards and CLI all work; questions just aren't captured automatically and sessions don't get the task rules.
