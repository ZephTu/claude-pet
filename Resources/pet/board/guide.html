HQ 是什么

同时开着十几个 Claude Code session 时，难的不再是干活本身，而是记住每个 session 在做什么、它问过你什么、你有没有回答。HQ 把这些状态从对话里搬到文件里：

概念是什么存在多久
项目（project）一条工作线：一个目标（有终点，比如"发布 hq-v2"）或一项长期职责（比如"客户 RCA"），不是一个目录。内容写在 projects/<名字>/PROJECT.md，里面的简报会交给它每个任务的 session目标到完成为止；职责长期
任务卡tasks/T-012-xxx/TASK.md：目标、状态、下一步、待办、日志到任务完成
待回应事项（ask）session 问过你、需要你决定或去做的事，记在 asks.jsonl，直到你回应跟随任务
session绑定到某个任务的一条工作线程，随时可以关随你
负责人（lead）可选。负责某一类任务的 agent 角色长期

核心原则：任务卡才是真实状态，对话不是。session 关了没关系，下一个 session 绑定到同一个任务、读卡就能接着做。

开始使用

  1. 安装（一次）：在 claude-pet 仓库里运行 hq/install.sh --root ~/claude-hq（任务卡放在哪个目录都行）。它会先列出要做的每一项改动，确认后才执行；只想要看板、不想动 Claude 的设置，加 --no-hooks。需要 python3。详见安装会改什么。
  2. 打开看板：双击桌宠（再双击收起），或者右键桌宠 → Task Board…。看板开着时，Dock 和 Cmd-Tab 里会出现桌宠图标，像普通窗口一样切回来（点 Dock 图标也行，最小化了也会恢复）；关掉看板图标就消失。菜单栏里 关闭任务看板（Cmd-W）关窗口，退出 Claude Pet 故意不配 Cmd-Q，免得误按把桌宠也退掉。
  3. 在 Sessions 栏给正在跑的 session 选一个任务绑定，或点 新建任务 新建任务并顺手绑定。
  4. 之后就在看板上处理 Needs you 里的事情，在 Sessions 栏直接给 session 发消息。

装好 HQ 之前就已经开着的 session，最好重开一次，hook 才会生效。

三个页面 · Focus：正在关注的任务

顶栏左边的 Focus · All · Needs you 切换三个页面（会记住），每个标签上都带着数字。Focus 是工作台，只放你正在关注的任务——不按天清空，一直留着直到你把它拿掉；All 是所有任务（左）和所有 session（右）；Needs you 是一栏收件箱：上面是还没回答的问题，下面是你的 @me 待办，标签上的数字就是这两样加起来（只有它是亮的橙色，因为只有它在等你）。第四个标签 定时任务 是按时间表自动跑的任务，见定时任务。

  • 加进 Focus：顶部输入框输入编号或标题后点 Add；或者在 All 里点任务行上的 ☆。新建的任务自动加入 Focus。卡片右上角的 ✕（点两下）把它从 Focus 拿掉，任务本身不变。
  • 排序：标题旁的 活跃的在前（和 All 里的是同一个设置，会记住）勾上时，有 session 在跑的任务排最上面，最近有动静的在前；不勾时按你自己的顺序，卡片左上角出现 ⠿，按住拖动就能调整顺序。右边的 session 按「等你 / 在干活 / 后台在跑 / 空闲」分组，每组里最近有动静的在前。后台在跑是这一轮已经结束、但它启动的命令（构建、测试、watcher…）还在后台跑的 session——跑完它还会回来说话；空闲只剩下没有任何东西在跑、也不用等的。任务行和 Focus 卡片标题旁的小标签同理：在干活 › 后台在跑 › 空闲。
  • 任务卡片直接带着：大字的下一步（旁边是 新 session ▾，没有 session 在跑时还有 Resume）、这个任务未回应的问题（可直接回应、送达）、你的待办（可直接勾）；Claude 和别人的待办只显示一句"还有 N 条"，展开看全部。下一步下面一行一个在跑的 session：状态点、名字、在做什么、最后一句话、多久前和 👁——点这一行就打开它的对话窗口（Peek），不用展开卡片再去找。点卡片的空白处展开完整的任务详情，再点收起（点输入框、勾选框、按钮、问题卡片或 session 行不会展开/收起，选中文字也不会）。展开后卡片换成完整的任务详情（和 All 页里展开的一样）；✕ 把它移出 Focus（任务本身不变，可以 Undo）。
  • ⚠ 异常标记：卡片标题下面的橙色 ⚠ 行，是卡片和 session 对不上的地方（来自 hq status，大约每分钟看一次）：卡片落后——session 在卡片最后一次写入 10 分钟以后还在调工具，卡片没跟上；空等——下一步或当前状态说在等某个构建 / 测试 / watcher，但已经 30 分钟没有 session 在干活、在等你或在后台跑任何东西（后台任务不管是多久以前启动的，只要还没结束都算）；太久没更新——没完成的任务 7 天没动；卡片超预算——超过 16 KB、30 个链接或 30 条待办。标记会随情况变化自己消失。（完成的任务离开 Focus，「完成了还有 session 在跑」只在 hq status 里看得到。）
  • 右栏只列 Focus 里任务的 session，以及还没绑定任务的 session（方便顺手绑定）。
  • Focus 列表存在任务根目录的 focus.json（以前按天存的旧文件会自动沿用最近一天的列表）。命令行：hq focus、hq focus add|remove T-012、hq focus order T-3 T-1 …（排序）。

All 与 Needs you

顶栏

  • 顶栏只放能点的东西：左边切换 Focus · All · Needs you · 定时任务（标签上是各自的数字），右边是搜索框、秘书（见秘书）、新建任务、⚙ 设置、? 本说明。看板每 4 秒自动刷新，不需要手动刷新按钮。
  • 底部状态栏：session 有几个（在干活的、等你的），问题和待办各几条（点一下跳到 Needs you），最右边是额度。任务数在标签上。
  • 浅色 / 深色：跟着系统外观走（系统设置 → 外观）。
  • 中文 / English：右键小猫 → Settings → Language · 语言，可选 跟随系统（默认，macOS 首选语言是中文就显示中文）、English、中文。小猫的菜单、列表、气泡，看板，本说明和连接状态窗口一起切换，切换后页面立刻重新加载，草稿不会丢。定时任务页也跟着这个设置走，没有单独的开关。中文界面里 session、todo、ask、Resume 这类术语保留英文。
  • ⚙ 设置（在哪个页面都能打开，Esc / Done / 点窗口外关闭）：Projects 管理项目，Categories 管理分类，Sessions 里是新 session 开在哪、skip permissions、stay on board、active first。
  • 额度：5h 和 week 两条——订阅的 5 小时额度和每周额度用了多少（70% 起变黄、90% 起变红），resets 后面是多久后重置。和悬停在小猫身上看到的是同一份数据。Claude Code 只把额度交给状态栏命令，所以要有状态栏把它存下来：用 claude-hud 的话，在 ~/.claude/plugins/claude-hud/config.json 的 display 里加 "externalUsageWritePath": "<你的主目录>/.claude/pet/hud-usage.json"（必须写绝对路径）；或者用 pet-emit --statusline 包一层你的状态栏命令（见仓库的 docs/pet.zh-CN.md）。没有新鲜的数据就不显示。每个开着的 session 都会写入它自己最后一次调用 API 时的数字，所以显示的是最后出现的那组读数，不是最大的那组：手动重置额度之后会跟着降下来。合盖睡眠、重启小猫后新旧顺序依然记得；只有小猫从没见过的读数（第一次运行，或它关着、睡着期间新写进来的）一开始分不出新旧，会先显示较高的那组，等某个正在工作的 session 的数字再变一次就对了。
  • Filter tasks…：Focus、All、Needs you 三个页面都按它筛选。任务按编号、标题、关联、分类、项目匹配；Needs you 里的问题和待办还会匹配它们自己的文字（比如搜 PR #78 能找到写着它的待办）。Focus 右边那栏 session 也只留匹配任务的。筛选时列表上方会写"显示 几 / 几"，点 清除 就恢复全部；从别处跳到一个被筛掉的任务时，筛选会自动清掉。
  • 新建任务：新建任务，选分类，工作目录可以手填或从建议里选（也可以不填，绑定 session 时会自动记上），并可立即绑定一个 session。
  • ?：打开本说明。
  • 删除 / 解绑都要点两下：解绑 session、从任务移除以前的 session、删关联链接、待办的 ✕（不做）、Focus 卡片的 ✕、删项目目录、删空的项目或分类——第一下按钮变成红色的"Unbind?""Remove?"等，4 秒内再点一下才执行，不点就恢复原样。

Needs you（第三个标签页）

  • Asks：所有还没回应的问题，最早的排在最上面。session 把同一个还没回应的问题再问一遍时，不会多出一条。每条可以先在说明框里写几句（多行也行，最多显示 5 行，超出滚动），再选回答：
    按钮含义
    可以（Yes）好 / 可以 / 按你的建议来。写了说明就表示"我的回答就是说明里的内容"（如"A+C"、"跑一次"），session 收到的是 "Answer: …"
    以后都可以（Yes, always）回答"可以"，而且以后这类事情不用再问：点开一个小编辑框，写好这条授权的措辞——session 在问题末尾带了建议（[grant: …]）就预填建议，没带就预填问题原文；下面是常用预设（用相同参数重跑验证、review 出的问题修完推到同一个 PR、排查完的测试环境直接删……），点一下填进去。点 可以，并授权：问题答成"可以"，授权写进任务卡的 ## 授权 一节，session 收到的回答后面多一句 "— and from now on, without asking: ‹措辞› (a standing grant)"。同样措辞的授权已经有了就不重复加。Undo 会重新打开问题，并撤掉这次新加的授权。合并 PR、改共享环境或凭证、以你的名义发消息这类事，最好还是每次问
    不要（No）不做 / 不要；说明里可以写原因或者换成什么
    转待办（To todo）这不是要回答的问题，是我自己要去做的事（比如"PR 合并后把消息发给 Ping"）：在这个任务里加一条 @me 待办（说明会接在后面），问题关掉，并告诉 session 我会自己做、别再问。Undo 会把这条待办标成已放弃并重新打开问题
    稍后（Later）先不回答：问题留着，从 Needs you 和小猫的红点里隐去，第二天自动回来；session 会收到"用户稍后再答，先做不依赖它的事"。被推迟的问题收在一行"N 条稍后再答 · 明天回来"里，点开可以直接回答
    ⋯ → 不了解背景（No context）不了解背景、答不上来，先归档（不常用，收在 ⋯ 里）
    送达：提出问题的 session 还在运行、而且在 Orca、iTerm2 或 Terminal 里（或者是两轮之间的后台 session）时，按钮下方有 现在发给 ‹session›（session 空闲时默认勾上）：回应会立刻作为一条消息发给它，它马上接着干。消息里只带问题编号和问题开头的几个字（如 T-012.3 "再跑一次 release_test 验证删机器吗？参…": Do — 不用了），不把整条问题再发一遍，省 token 也好读；只发编号不行，因为 session 自己并不知道编号。不勾、或者 session 不在线时，回应在它下一轮开始时送达；session 正停在一个确认或问题上（等你授权 / 等你回答）时也不会立刻发，回应下面会写明，同样在它下一轮送达。已经发出去的消息无法撤回，Undo 只会重新打开这个问题。
    一个任务有好几个 session 时：回应只送给提问的那个 session，同一任务下的其他 session 收不到，不会两边做同一件事；它们看到的"未回应的问题"里，别人问的会标注 "asked by another session on this task"。只有提问的 session 已经结束或者解绑了，回应才交给这个任务下一个开始新一轮的 session（只交给一个）。
    说明里带图片：在说明框里 Cmd+V 粘贴截图，或把图片拖到这条问题上（PNG / JPEG / GIF / WebP，≤ 20MB），下方显示缩略图（✕ 去掉）；回应时图片路径附在说明后面，Claude 会读取它。
    一个任务有多条问题时一起回应：同一任务下有两条以上未回应的问题时，按钮变成"选择"——点一下整个按钮填上颜色（可以 绿、以后都可以 青绿（下面展开同样的授权编辑框）、不要 红、稍后 黄、不了解背景 灰、转待办 蓝；再点取消，可以改选），不会马上发出；在某条的说明框里打字会自动选上"可以"（删光文字就取消；你手动选过的不会被改）；每条都选好后，点底部的 发送 N 个回答，全部记下，并合成一条消息发给提问的 session。底部只有一个 现在发给 ‹session› 勾选框，管这一组。没选的问题留着，下次再答。Undo 会把这一批全部重新打开。
  • Your todos：所有任务里 @me 的待办，最新的在最前，每条标着已经等了多久（超过 3 天变黄）。点方框 = 做完；点 ✕ = 不做。
  • Needs you 是一栏：上面是 Claude is asking（没有问题时只剩一行"Claude has nothing waiting on an answer from you."），下面是 Your todos（放了 3 天以上的，右边的时间变成橙色）。分工是：Asks = 需要你回答的问题；Your todos = 需要你去做的事（所有任务里的 @me 待办）。session 需要你动手时会加 @me 待办，需要你回答时会提 ask。
  • 点条目的文字会打开上下文窗口（见下）；点任务编号标签会在 All 页的任务列表里定位到这个任务（所在的项目组折叠着、或被搜索过滤掉时会自动展开、清除）。
  • 点错了可以撤销：勾选、✕、回应、Handled 之后，底部会出现带 撤销 的提示（8 秒）；勾掉的待办还会划线留在列表里 1 小时，旁边有 Undo。更久之后要反悔，点开任务，在方框上再点一下即可恢复；每次改动都记在任务卡的日志里。勾选按待办的文字认准是哪一条：看板刷新前 session 在前面插了新待办也不会勾错；那条待办已被删掉或改写时会提示你刷新。

上下文窗口

回答"这一项到底是什么、从哪来、去哪看"：

  • 问题（ask）：显示提出这个问题的那条 Claude 回复原文，以及是哪个 session 提的；可以直接打开那个 session 的对话。（这个功能上线之前记录的问题没有原文，可以打开对话去看。）
  • 待办：显示任务的状态、下一步、任务卡全文（含日志）。
  • 都会列出这个任务相关的 session：正在运行的可以看对话、跳转；已经结束的也能点 History 查看历史对话。
  • Show task 在 All 页的任务列表里定位并展开这个任务；打开任务卡 用编辑器打开任务卡。

Tasks（All 的左列）

  • 标题旁的 项目 | 仓库 | 状态 切换分组方式（会记住）：
    • 项目（默认）：按项目分组，所有项目都会显示（还没有任务的项目显示"没有进行中的任务"和 + 新建任务，直接在该项目下新建），点整条组标题折叠或展开，拖动组标题调整项目顺序（在任务栏任意位置松手都行，以最近的组标题为准；拖动时各组临时只显示标题；已完成 / 已放弃的项目不能拖，"无项目"排在进行中的项目之后）；勾选 活跃的在前（默认勾上）时，有运行中 session 的项目（绑定到它的任务，或在它的目录里干活）排在最前，按最近活动时间倒序，组名旁显示绿点和时间，其余按你拖出的顺序；组名旁显示任务数、"N 等你"（这个项目里未回应的问题加你的待办，黄）和运行中的 session 数（绿）；组内先按状态（等你 → 阻塞 → 进行中），每行带状态标签。没有项目的任务归在 无项目。
      有 PROJECT.md 的项目，组标题显示 title（显示名）和类型标签 目标 / 职责，暂停的再加一个 暂停：目标后面是截止日期和剩几天（7 天内变黄，过期标红写"过期 N 天"）以及进度条"完成数 / 总数"（已放弃的不算）；职责后面是"N 进行中 · 本周完成 M"（最近 7 天完成的，职责的总数只会一直涨，所以不显示）。状态是已完成 / 已放弃的项目排在"无项目"之后、变灰、默认收起，点开会记住。
      点项目名打开项目面板（只读）：显示名、类型、状态、截止日期、目标（职责写"职责范围"）、完成标准（职责写"健康标准"）、简报、项目授权（每条可 ✕ 撤销，提示里能撤销这次撤销）、Jira epic 和 fix version、它进行中的任务（点编号跳到那个任务，所在的组会自动展开）、默认目录；右上角 打开 PROJECT.md 用默认编辑器打开文件。内容要在 PROJECT.md 里改。还没有 PROJECT.md 的项目，面板里提示用 hq project set 名字 kind=goal（或 kind=duty）建一份。
    • 仓库：按任务第一个工作目录所在的 git 仓库分组（worktree 算回它的主仓库，比如 claude-pet-T079 算 claude-pet；不是 git 仓库就用目录名），进行中任务多的仓库在前，没有工作目录的在最后。组名旁显示任务数、仓库里有几个项目的任务（不止一个时才显示）、未回应问题数和运行中的 session 数；组内先按状态，每行带项目标签。一个仓库可以有好几个项目的任务（比如 claude-pet 里既有 claude-pet 也有 hq-v2）。
    • 状态：按 等你处理 / 阻塞中 / 进行中 分组，每行带项目标签。
  • 全部收起 / 全部展开：按项目或仓库分组时一键收起或展开所有组；按状态分组时一键收起所有点开的任务。
  • 勾 show closed 显示已完成和已放弃。
  • 组内排序：有正在运行的 session 的排最前 → 绑定过 session 的 → 其余；同一档里有未回应问题的靠前，再按最后更新时间。
  • 行尾黄色数字 = 未回应的 ask 数，绿色数字 = 正在为它工作的 session 数。
  • 状态 = 任务行左边那根竖条的颜色，也是任务编号的颜色（看板上和小猫列表里都一样）：橙 = 等你处理、珊瑚红 = 阻塞、绿 = 进行中、蓝 = 已完成、灰 = 已放弃；悬停显示状态名。

Sessions（All 的右列）

  • 标题旁 List | Project 切换视角（会记住）：List 平铺所有 session，每张卡带项目名（蓝色）；Project 按项目分组、可折叠，顺序与 All 页的任务列表一致。session 的项目：绑定了任务的跟随任务的项目，没绑定的按所在目录匹配。
  • 每张卡三行：状态点和名字，右边是 Bind…（绑定到任务；绑定后显示任务编号，点它定位任务）；项目和状态，右边三个图标；最后一条回复。
    状态文字后面是这个会话带着多少 context（如 210k · 70% ctx），和小猫列表里的一样：前面是 token 数——每一轮都要把这么多重新送给模型一次，会话越长越费 5 小时额度；百分比是相对自动 compact 门槛算的：门槛是你用 /autocompact 200k 设的值（只读用户级 ~/.claude/settings.json，项目里的设置不算；没设就是模型的整个窗口）。100% 就是门槛本身，Claude Code 通常在到达之前就会压缩。压缩完（包括你手动 /compact）、还没有新回复时，显示压缩后的估计大小，不会停在压缩前的数字：压缩记录只写了对话本身有多大，每次请求还要带上系统提示、工具定义和重新附上的文件（通常 25–55k），所以再加上上一次压缩后实际多出来的那部分（还没压缩过的会话，按它第一条回复的大小算，最多 60k）。下一条回复一到，就换成实际值。到门槛的 2/3（67%）起变色，这时小猫会提醒一次“可以 /compact 或开新会话”；80% 起变红。提醒只在会话越过 2/3 那一刻发：小猫启动或暂停恢复时已经超过的会话不提醒；压缩到门槛一半以下、再次越过时，会再提醒一次。状态点和状态文字都和小猫列表里的完全一样（状态文字如 "Working"、正在跑的命令、"1 in background"、"Answered"；圆点悬停有说明）：绿色呼吸 = 在干活；转圈的弧 = 在等它派出去的 agent；绿色带珊瑚红小角 = 在干活但最近几次调用都失败了；灰绿色带向外扩散的圈 = 这一轮结束了，但它启动的命令 / 进程还在后台跑；珊瑚红菱形 = 等你授权；橙色空心圈 = 等你回答；灰色 = 空闲；灰色虚线圈 = 那一轮被打断了（Claude Code 自己说 idle），或很久没有动静。系统开了"减少动态效果"时不动，只靠形状区分。
  • 在看板上批准：session 卡在权限确认上（珊瑚红菱形）时，它那一行会出现 Approve 框：下面是它要做的事的完整内容（整条命令、完整路径或网址、其他工具的参数），右上是 Allow / Deny。Allow 要点两下：第一下变成 Allow?，在同一个确认上再点一下才批准，6 秒内不点就取消——看板几秒刷新一次，行的位置可能变，这样点不到别人的确认上；鼠标停在 Approve 框上时看板也不会刷新。Deny 点一下就生效。和小猫弹出来的 Allow / Deny 是同一个机制：终端里的确认框照常出现，谁先回答算谁的；你在终端先答了，这边的点击就不起作用。只在小猫还挂着这个确认时显示——小猫没在运行时弹出的确认，或者已经等了将近 10 分钟（挂起时间到了）的确认，只能回终端答。同一个 session 同时有好几个确认（比如几个 subagent 一起要权限）时，这里只能回答最新的那一个，其余的回终端答。
  • 后台 session（带蓝色 background 标记）没有终端：Attach（终端图标）在你选的终端里打开 claude attach，就能直接交互；停止（方块图标，点两次确认）停止它，对话保留，之后 Attach 可以继续。两轮之间可以直接发消息：看板先停掉它，再用 claude --bg --resume 带着你的消息在原目录里接着跑（id 不变，沿用看板的 skip permissions 设置）；它正在跑一轮时不能发，等这一轮结束或 Attach 进去。
  • 停止终端里的 session：终端里的 session 一行也有 停止（方块图标，点两次确认）：结束它的 Claude Code 进程，对话保留。看板开的标签页随之关闭（看板启动命令末尾带 ; exit 0，session 一结束 shell 就退出——Stop、/exit、连按两次 Ctrl-C 都一样），标签页不会越积越多；之后 ↻ Resume 新开一个。Orca 和 iTerm2 默认就会关；Terminal 要在 设置 → 描述文件 → Shell 里把 shell 退出时 设成 如果 shell 完全退出则关闭。你自己在终端里起的 session 停掉后标签页仍留在 shell 提示符，Resume 会优先回到这个标签页。在看板上把任务状态改成 done 或 abandoned、它还有 session 在跑时，会弹窗问要不要一起停掉（列出这些 session；对话保留，之后可以 Resume）。勾上 记住我的选择 以后就不再问，按记住的做；在 设置 → Sessions → 结束任务时 可以改回 每次问 / 停掉它的 session / 不停。按 Esc 或点窗外 = 这次不停，也不记住。session 自己在 hq-update 里把任务改成 done 或 abandoned 也一样处理：等它这一轮回复完（它起的后台任务也跑完），按同一个设置弹窗问、直接停掉或不停。之后你只要又给它发了消息，就不再算数，不会把你正在聊的 session 停掉；看板没开时，10 分钟内打开看板仍会处理，更早的只显示下面的黄色提示条。这种自动弹出的窗口，默认选中的是 不停，免得你正在别处打字时一个回车把 session 停了；设成直接停掉时，这个任务的其他 session 若正在干活或在等你回答，也不去动它们。同时有几个任务这样结束时，一个一个问。用 hq set 结束的任务不会弹窗。任务已完成还有 session 在跑：这个任务的卡片顶上会出现黄色提示条，全部停止（点两次）把它们全部停掉；右栏 Sessions 顶上也会汇总所有挂在已完成任务上的 session，全部停止 一次停完。

  • 红色 new 标记 = 小猫的红点：这个 session 干完了一轮，你还没看过结果。下面这些都算"看过"，标记和小猫的红点一起消失：👁 打开对话、↗ 跳到终端、从看板给它发消息（包括回应 ask 时勾了 send to … now）、在终端里直接给它发下一条。只是打开看板、扫到摘要、展开任务卡片不算。

对话窗口（Peek）

  • 显示这个 session 最近 30 条消息，Claude 的回复按 Markdown 排版。只有你和 Claude 说的话算条数，中间的工具调用一起显示但不占名额；截图（它们在对话记录里占很大地方）不会让条数变少——Peek 会往回多读，直到凑满 30 条，最多读对话记录最后 64MB。不论你是在看板上发的，还是直接在终端里打的（包括 session 正忙时打进去排队的），都会显示。窗口跟着 session 自动更新：你在滚动时新内容会等你停下约 1 秒再刷进来，不会打断滑动；只是 token 数、用时这类数字变了，就只更新顶上的状态行，下面的对话不动。点窗口外面或按 Esc 关闭；从上下文窗口打开时，左上角 ← 返回。

  • 看详情：点工具行展开它的输入（命令、文件路径、Agent 的 prompt……）和输出（Edit / Write 显示改动的 diff，绿增红删）。长输出只显示前 4000 字，点 全部显示 看全部；两边各有 复制 复制完整内容（特别长的输入只取前 10 万字、输出前 20 万字）。工具还在跑时打开，结果回来后会自动更新。
  • 实时状态：窗口顶部一行写着 session 现在在干什么——"正在运行 Bash …"/"思考中…"、在等你回答什么，或者空闲——后面是本轮已用时间（一直在走；空闲时显示上一轮用了多久，按 Esc 打断的那一轮算到打断为止）、本轮输出的 token 数和当前 context 大小（刚 compact 完是压缩后的估计大小，算法同上）。
  • Claude 的待办：Claude 用 TodoWrite（或 TaskCreate / TaskUpdate）列了清单时，状态行下面显示"Claude 的待办 3/7 · 正在做的那一项"，点开看整个清单（☑ 完成、◐ 进行中、☐ 未开始）。这些工具调用本身不再单独占一行。
  • 复制：选中文字 Cmd+C；每条消息悬停有 Copy；顶部 Copy all 复制整段对话。
  • 链接：网页链接点击用浏览器打开；文件路径（.md、.html、代码文件、目录……）点击用默认程序打开，相对路径按该 session 的目录解析。脚本、可执行文件和 App 只会在访达里定位，不会直接运行。
  • Claude 回复里的 hq-asks / hq-resolved / hq-update 块显示成"Asked you"/"Answers recorded"/"Card updated"列表，里面的链接可以点。"Asked you"一直展开；"Answers recorded"和"Card updated"只是记账，默认折叠成一行（写着记了几条回答、改了卡片的哪些字段，比如 state ×2 · log），点一下展开，再点收起，看板刷新也保持；普通代码块里的网址也可以点。

定时任务（Scheduled）

顶栏的 定时任务 / Scheduled 标签页：按时间表跑一段 Claude prompt 或一条 Shell 命令，并且能看到一共有几个任务、每次跑得怎么样。这一页的文字有中英文两版，跟随右键 Settings → Language · 语言 的设置。

  • 谁在跑：每个打开的任务对应一个 macOS LaunchAgent（~/Library/LaunchAgents/local.claudepet.job.<id>.plist），到点由 launchd 启动 ~/.claude/pet/pet-emit --run-job <id>。所以猫关着也照跑；Mac 睡着时错过的那次，醒来后补跑一次（错过多次也只补一次）。第一次加任务时 macOS 可能提示"已添加后台项目"，这是正常的。
  • 从模板开始：还没有任务时，这一页列出三个模板——每天早上汇总昨晚的 CI（Claude · 每个工作日 09:00）、每小时看 PR 有没有新评论（Claude · 每小时）、每周清一次缓存（Shell · 每周日 03:00）。点一个就打开填好名称、类型、prompt 或命令和时间的新建表单，改一改再保存。
  • 新建 / 编辑：右上角 新建定时任务。表单是一页"左边问题、右边答案"：做什么（顶部切换 Claude prompt / Shell 命令，再填名称和 prompt 或命令）、在哪跑（工作目录，从这里启动，会读这里的 CLAUDE.md；选择… 打开文件夹选择框）、什么时候跑、能做什么（只有 Claude 任务有）、跑完告诉我（连同"开着"开关）、更多（模型、单次最长、额度保护、session 怎么续，写成几句话，空格里直接改）。底部一直停着 取消 / 保存并立即跑一次 / 保存。
    • Prompt 每次原样发给 claude -p。和终端里一样，开头写 /技能名 参数 就调用那个技能；不写也行，Claude 会按描述自己挑。你的 MCP 服务器、插件、hooks 照常加载。
    • 命令 用你的登录 shell 跑（zsh -lic），PATH 和终端里一样。
    • 能做什么（权限）：跑的时候没人点"允许"，所以先选好——只用已允许的（默认；只用你在设置里已允许的，其他一律拒绝并记在运行结果里）、还能改文件（acceptEdits）、全部允许（跳过所有权限检查，只给完全信任的 prompt 用）。
    • Session（在"更多"里）：每次开新 session（默认，干净、便宜；只保留最近 N 次运行的 session，更早的从 ~/.claude/projects 删掉，填 1 就只留最新一次）或 每次接着同一个 session（claude -p --resume，适合需要记住上次的任务；上下文用到设定的百分比（默认 50%，按模型的上下文窗口算）时先 /compact；列表里会显示这个 session 现在用了多少上下文）。注意：Claude Code 的 /clear 本身就是开新 session，所以"同一个 session 里先清空再跑"等于"每次新开、只保留 1 次"。
    • 单次最长：超时就停掉整组进程。
    • 额度保护：每次跑之前看一眼订阅额度，周额度或 5 小时额度已经用到设定的百分比（默认都是 90%，0 = 不检查）就跳过这次，记成"跳过——周额度已用 94%"，把剩下的额度留给你自己用。额度读数来自猫已有的读数（状态栏）和上一次任务运行时 Claude 报告的额度，取其中较高、且所在窗口还没重置的那个。
    • 什么时候跑：写成一句话，空格里直接选，比如"[每个工作日] 的 [09:00] 跑一次"。可选每个工作日、每天、每周（点选周几）、每小时、每隔几分钟，或 cron 表达式（分 时 日 月 周，支持 */15、1-5、MON）。下面用小标签实时列出接下来 3 次的时间；写错了会直接告诉你哪里不对。
    • 跑完告诉我：失败时（默认）、每次跑完、不提醒。旁边的开关决定保存后任务是否开着。

  • 详情：一次运行的输入、Claude 的回复（Markdown 排版）或命令的输出、"过程"（每次工具调用和结果，被拒绝的标红）和日志。对话 打开这次运行的完整 session 记录（和看 session 一样）；接着聊 在终端里 claude --resume 这个 session（勾了 stay on board 就留在看板上聊）。

秘书

顶栏的 秘书 打开一个常驻的对话窗口，对面是一个了解这个看板的 Claude。可以问它"T-072 和 T-071 怎么样了、卡点是什么""有什么在等我""哪些看着卡住了"。它每次都先现查任务卡和 session（hq status、hq asks、hq board……）再回答，等你处理的事用 ⚑ 标出来。它只管"信息 → 看板 → 你的注意力"这条线，自己不干活：要做的事，它会告诉你属于哪个任务，你在那个任务上点 ▶ 新开 session。

  • 第一次：点 秘书 会先列出要创建哪些东西，点 设置 才真正创建。已有的文件一律保留，不会覆盖。会创建：任务根目录下的 .claude/agents/secretary.md（它的身份和规矩，可以直接改）；记忆文件 secretary/profile.md、people.md、playbooks.md；它自己的任务卡"秘书"；定时任务 页里一个不定时的任务"秘书"。
  • 对话窗口就是 Peek。发一条消息就是把这个任务跑一次，消息就是这次的 prompt；回复和工具调用照常显示。它回复期间，发送按钮是灰的，状态行写"回复中"，旁边有 停止。上一条失败了，或者因为额度被跳过，状态行会写明原因。这里没有斜杠命令。
  • 始终是同一个 session：每条消息都接着上一次的对话（--resume）。上下文超过任务设的阈值（默认 50%）时先 compact；周额度或 5 小时额度用到设定的比例（默认 90%）时跳过，不会把额度用光。这两项和模型、单次最长时间一样，在 定时任务 页编辑"秘书"就能改；也可以给它加个时间表，比如每天早上让它把看板看一遍。工作目录、agent、"接着同一个 session"和允许的工具是秘书离不开的设置，改了也会在下次发消息时改回来。
  • 它能做什么：它在后台跑，没人在旁边批准，所以只预先允许三样：读文件（Read / Grep / Glob）、运行 ~/.claude/hq/bin/hq、改 secretary/ 下的文件。其他操作都会被拒绝，除非你在 Claude Code 设置里另外允许了。外部系统它只读；消息和邮件只起草，写在回复里。
  • 它的建议，在它的窗口里或 Needs you 里回答：建任务、给任务记一笔、加待办（比如 @me 把回复发给 Atul）、关任务、改它的记忆，都会作为问题出现在秘书窗口底部的"它在问你"里（就在输入框上方），同时也出现在 Needs you，标着绿色的 秘书，点它打开秘书窗口。两边是同一批问题，在哪边回答都行。你点 Yes、No 或 Later，可以附说明，说明会修改或替换它的建议。点了 Yes，它大约 10 秒后自己醒来照做（比撤销按钮在的时间长，点了 撤销 它就不做），每条做完用一行汇报，打开秘书窗口就能看到；它要是正在回复，就等这一轮结束再做。点了 No 它就不做，没有新情况也不会再提。点 转待办 表示这件事你自己做：它变成你的 @me 待办，秘书不会去做。
  • 记忆：秘书窗口标题下的 记忆：profile · people · playbooks 点一下就用编辑器打开对应文件。profile.md 记你是谁、用什么语言、各个项目看重什么；people.md 记同事是谁、负责什么；playbooks.md 记常做的流程，比如发版测试、RCA。每次对话开头它都会读这三个文件。你可以随时直接改。它自己要改，会先在回复里给出 diff，再问"按上面的 diff 更新 secretary/people.md？"，你同意后才写。它用 profile.md 里写的语言回复；没写的话，就用你说话的语言。
  • 它自己的任务卡"秘书"是它的笔记本：它的 hq-update 写在这里，记着它在替你盯什么，这几行显示在秘书窗口顶部的"它在替你盯的事"。这张卡不算你的工作：All、Focus 和它们的计数里都没有它；它的问题照样在 Needs you 里。指向这张卡的链接（比如它的问题转成的待办上的编号）会打开秘书窗口。秘书的问题不提供"以后都可以"：授权从来不给秘书。

和小猫的联动

  • 列表里显示任务：单击小猫弹出的 session 列表，每一行的第二行用暗灰色显示它绑定的任务（"标题 · 编号"），只有任务需要注意时末尾才加一个带颜色的状态词（needs you / blocked / done）。没装 HQ 或没绑定任务时，第二行和以前一样。
  • 问题也会提醒：未回应的问题计入小猫的角标（小猫会做出"有事找你"的样子），并列在小猫列表最上面的 Asks 分组里，点一下打开看板并定位到那个任务；出现新问题时，小猫上方弹出"T-012 asks: …"，点击跳到提问的 session。

session 和看板怎么联动

session 绑定任务后，三个 hook 会让它遵守下面的规则：

  1. 先读卡，再干活，干完写回：状态、下一步、待办、日志都写回任务卡。session 不再一条条跑 hq log / hq set 这些命令，而是在回复末尾写一个 hq-update 块，由 Stop hook 写进卡片。每多一次工具调用就要把整段对话再读一遍，这样能省掉这部分 token。只认回复末尾的那个块——正文中间引用或举例的块不算，模板里 <…> 这样的占位行也不算。块里只要有一行写不进去（状态拼错、找不到那条待办、待办有歧义……），整块都不写，退回给 session 改一次（会列出候选待办）；所以重发整块不会重复添加。同一条待办、日志、ref 已经有了就不再加。冒号用全角也行。一轮干了两分钟以上却没动任务卡，会被提醒一次去更新。 
    ```hq-update
status: blocked
next: 等 infra 给 token
state: 构建已通过，等 token
todo: @me 发 token 申请
done: 重跑测试
log: 选方案 v2，因为更便宜
ref: PR #9 https://github.com/…/pull/9
```
    只写变了的行；todo / done / drop / log / ref / workdir 可以写多行；state 会替换卡片的"当前状态"一节；done / drop 按待办的文字匹配；project: 名字 把任务移到已有的项目（没有这个项目就整块退回——项目只能由你建）。什么都没变就只写一行 touch。
  2. 需要你确认的事会被记下来：session 把问题放在回复末尾一个 hq-asks 块里，每行一件事。它们会变成看板上的 ask（编号如 T-012.3）。 
    ```hq-asks
- 方案 v2 可以吗？
- 要不要找 Chengjie 要数据集？
```
  3. 没回应的问题不会被当成"不做"：每一轮都会把还没回应的 ask 重新提醒给 session。
  4. 授权过的事不再问：绑定的 session 每次启动（新开、resume、/clear、compact 之后）都会收到这个任务当前生效的授权（最多 10 条、约 1500 字；从看板绑定的 session 跟着第一次注入一起收到）。规则是：授权是许可，不是让它现在去做什么；只在绑定这个任务时，本来要问、而某条授权明确覆盖的那一步直接做，并在回复里点名是哪条授权；每条都从窄理解，更大、更有风险或不一样的事照常问。之后每一轮只在授权变了时多注入一行（"+ granted：…（是许可，不是现在就做）" / "- revoked：…，这类事情重新要问"），没变就什么都不加，所以每轮的注入很小；"以后都可以"产生的授权跟着回答说一次，不重复。resume / compact 时先列出 session 上次看到之后被撤销的授权（旧对话里还留着旧列表）；session 改绑到别的任务，会被告知旧任务的授权在这里不算数。会反复出现的、常规且可撤回的那类问题，session 可以在问题末尾带一个建议措辞 [grant: …]（删除、发送、花钱、合并、force-push 永远不带）；看板把它从问题里拿掉，预填进 以后都可以 的编辑框。授权只能由你加：session 被要求不加、不放宽、不改写授权，hq grant add 和 ask resolve --grant 在 Claude Code session 里会直接拒绝（看板和你自己的终端可以；撤销 session 也能做）；state: 行不能是标题，所以 hq-update 也写不出一个授权小节。
  5. session 记得自己的待办：绑定了任务的 session 每次启动（新开、resume、/clear、compact 之后）都会收到卡上 Claude 的未完成待办（原文照抄，最多 20 条、约 2000 字，更早的只说省略了几条），并被要求对照现状，在下一个 hq-update 里用 done: 勾掉做完的、用 drop: 去掉过时的。只在启动时给一次（从看板绑定的 session 在绑定后的第一条消息里也给一次），不会每轮都塞进去；要它中途再核对一遍，用待办旁边的 整理待办。
  6. session 知道任务属于哪条工作线：任务所在的项目有 PROJECT.md 时，绑定的 session 每次启动（新开、resume、/clear、compact 之后，以及 hq bind）都会收到一段项目说明：属于哪个项目、是目标还是长期职责、截止时间、目标的第一行，再加上 简报 全文（最多 2000 字，超出的部分截掉，提示它去读 PROJECT.md）。简报是空的就什么都不说。不管 session 在哪个仓库里干活都一样。之后只在这段说明变了（改了简报、标题、类型、状态、截止时间或目标第一行，或者任务换了项目）时，在下一条消息里再给一次；简报没了也会告诉它之前那段不再适用。项目的 授权 一节对这个项目的所有任务都有效，注入时列在"From project …"下面。
  7. 两边都能回应：
    • 在看板上点按钮 → session 下一轮收到"用户在看板上回应了 …"；
    • 在 session 里直接回答 → session 用 hq-resolved 块记下来，看板上那条随之关闭。
  8. 草稿不等于完成：session 替你起草、需要你去发的东西，会变成一条 @me 待办，直到你勾掉。

什么时候用哪边：要看全局、批量处理问题、改状态，用看板；跟某个 session 深入讨论，在它的终端里直接聊，绑定之后它说的、问的同样会出现在看板上。

命令在 ~/.claude/hq/bin/hq。看板上的每个操作背后都是这些命令，所以在终端里或让 Claude 调用，效果完全相同。

在 Claude Code 里还可以用三个 slash 命令：/task T-012（绑定，或 /task 新任务标题 新建并绑定）、/board（显示看板）、/hq-onboard（从已有 session 初始化）。

从已有 session 开始

刚装好时，本机通常已经有很多 Claude Code session 和历史对话。两步把它们变成看板：

  1. 项目：⚙ 设置 → Projects 里点 Suggest from sessions（看板为空时任务列表里也有这个入口）。它扫描最近 60 天的对话，按 git 仓库（不在仓库里的按目录）列出候选项目和 session 数，默认一个都不勾，勾选后点 Create。命令行：hq scan（只读）、hq scan --apply-projects --only 名字,名字。
  2. 任务：在任意 Claude Code session 里输入 /hq-onboard。Claude 会读这些 session，起草任务卡（状态、下一步、你的待办、相关链接、置信度），按项目列成表给你确认，确认之前不会创建任何东西；创建后，正在运行的 session 会绑定到对应任务，已结束的记在任务卡上、可以在看板上查看历史。

之后任何地方都能改：在看板上直接改，或者在 session 里让 Claude 改。从推断得来的状态在任务日志里标了"请核实"。

项目

  • 项目是一条工作线，不是一个目录：要么是有终点的目标（kind: goal，比如"发布 hq-v2"），要么是长期职责（kind: duty，比如"客户 RCA""Release 回归测试"）。一个任务只属于一个项目。目录（仓库）只是任务的属性（工作目录），用来开 session、Resume、匹配 session。分类说的是"哪类工作"，和项目互不影响。
  • PROJECT.md：每个项目一个 <任务根目录>/projects/<名字>/PROJECT.md。frontmatter 是 title（显示名）、kind（goal / duty）、status（active / paused / done / abandoned）、due（截止日期，目标才有）、jira（关联 epic）、fixVersions；正文几节：目标（职责写"职责范围"）、完成标准（职责写"健康标准"）、简报（交给这个项目每个任务的 session：背景、约定、常用命令、要避开的坑）、授权（和任务卡同样的格式）、决策记录。标题中英文都认（## 目标、## Goal、## 目标 / Goal…）；每节一直到下一个这几种标题为止，简报里自己加的 ## 常用命令 之类的小标题算在简报里。职责的状态只有 active / paused。名字只差大小写的两个项目不允许（macOS 上会是同一个文件夹）。name 用短英文 id（命令行和卡片 project: 用它），显示名放 title。没有 PROJECT.md 的项目照样能用，只是没有类型、目标和简报。
  • 目录只是默认建议：hq.json 里还是记着项目的名字、顺序和目录；新建任务或绑定 session 时，任务还没有项目就按目录给一个默认值（目录嵌套时取最深的）。只给专属某个项目的仓库配目录；几个项目共用的仓库不配，在那里新建的任务先归到"无项目"，再手动分。之后可以在任务详情里改，session 也可以用 hq-update 的 project: 改。
  • ⚙ 设置 → Projects：新增项目（名字 + 目录，同时生成一份 PROJECT.md 草稿）、改名（修改后点 Save，所有任务卡和 PROJECT.md 的文件夹都跟着改）、增删目录（+ directory）、拖动 ⠿ 调整顺序、删除（有任务时先选移到哪个项目或"无项目"；PROJECT.md 的文件夹不删，移到 projects/.removed/）；有未归属的任务时，Assign by directory 一键按目录归属。
  • 命令行：hq project list | show 名字 | brief 名字 | add 名字 [--kind goal|duty] [--title 显示名] [--due 日期] [--path 目录] | set 名字 kind=… status=… due=… title=… jira=A,B fixVersions=… | paths 名字 目录… | rename 旧 新 | remove 名字 --to 其他 | auto | order 名字…。list 带上每个项目的进行中、已完成和等你的数目；show 显示内容和任务统计（进行中、已完成、最近 7 天完成、等你的）；brief 打印 session 实际会收到的那段文字。目标、完成标准、简报直接编辑 PROJECT.md。

分类与工作目录

分类

  • 每个任务根目录有自己的分类列表，存在 hq.json 里。新装的默认是一组通用分类：feature、bug、investigation、review、ops、docs、other，可以随意改。
  • 在 ⚙ 设置 → Categories 里：改名 = 改输入框里的名字后按回车；删除 = 点 ✕；底部输入框回车 = 新增。命令行用 hq category …。
  • 分类只是写在每张任务卡上的一个标签，所以：
    • 改名会同时改写所有用到它的任务卡；
    • 删除没人用的分类直接删；删除有任务在用的分类，必须先选这些任务移到哪个分类（或"不分类"），每张被改的卡都会在日志里记一笔；
    • 手动编辑任务卡写了不在列表里的分类，看板照样显示，并标成"not in list"，可以在 Categories 里一键"Add to list"。

工作目录（workdirs）

不需要手动维护：把 session 绑定到任务时，会自动把这个 session 所在的目录记到任务卡上（不记你的主目录和任务根目录）。新建任务时也可以手填。看板据此在 session 的"Bind to task…"下拉里把相关任务排在前面。

关联资源的链接规则

Resources 里的完整网址直接可点。像 QA-9519、bigtest#3248 这样的简写，在任务根目录的 hq.json 里加 links 规则就能变成链接，适用于任何工单系统（Jira、Linear、GitHub Issues……）。按顺序匹配，第一条命中的生效；$1、$2 是正则里的分组：

"links": [
  {"match": "^([\\w.-]+/[\\w.-]+)#(\\d+)", "url": "https://github.com/$1/pull/$2", "kind": "pr"},
  {"match": "^([\\w.-]+)#(\\d+)",            "url": "https://github.com/your-org/$1/pull/$2", "kind": "pr"},
  {"match": "\\b([A-Z][A-Z0-9]+-\\d+)\\b",      "url": "https://your-site.atlassian.net/browse/$1", "kind": "ticket"},
  {"match": "^(ENG-\\d+)$",                   "url": "https://linear.app/your-team/issue/$1", "kind": "ticket"}
]

添加资源时推荐写成"标题 + 网址"，比如 2026-11 QA AWS key leak – action items https://…：看板只显示标题（截断到两三个词），悬停可看完整标题和网址。绑定的 session 也会按这个格式记录。

kind 决定分组：ticket（工单）、pr、doc（文档）、link（其他）。完整网址会按域名自动分类。

负责人（lead）

把任务根目录下的 templates/lead.md 复制到 .claude/agents/bench-lead.md，写清楚它负责的范围，然后在任务根目录运行 claude --agent bench-lead，跟它说"继续 T-020"。负责人会绑定任务、把重活交给后台 subagent、保持自己的上下文精简，并按固定格式汇报。小任务不需要负责人，绑定的 session 自己就是负责人。

注意事项

  • 只有绑定了任务的 session，提的问题才会进台账。
  • 后台 session 只能在信任过的目录里启动（在那个目录里正常打开过一次 Claude Code 并同意信任即可）；否则看板会提示原因。
  • 看板上的回应：勾选 send now 时立刻送达（Orca / iTerm2 / Terminal / 两轮之间的后台 session）；否则在 session 下一轮送达。
  • 直接发消息支持 Orca、iTerm2 和 macOS 自带的 Terminal（第一次发到 iTerm2 / Terminal 时 macOS 会请求授权，允许 Claude Pet 控制它；拒绝了可以在 系统设置 → 隐私与安全性 → 自动化 里再打开）。发到 iTerm2 / Terminal 后 5 秒内没开始处理（session 也没在忙），会提示你去那里按一下回车；/ 命令和 ! 开头的消息不会开始新一轮，发出去就算成功。session 在等你确认或回答时不能发——先跳到终端处理。Ghostty、VS Code 等其他终端的输入框会置灰，只能 Jump。

What HQ is

With a dozen Claude Code sessions open, the hard part is no longer the work — it is remembering what each session was doing, what it asked you, and whether you ever answered. HQ moves that state out of the conversations and into files:

ConceptWhat it isLives
Projecta line of work: a goal with an end ("ship hq-v2") or a standing duty ("customer RCAs") — not a directory. Written up in projects/<name>/PROJECT.md, whose brief every session on one of its tasks is givena goal until it is done; a duty for good
Task cardtasks/T-012-slug/TASK.md: goal, status, next step, todos, loguntil the task is done
Asksomething a session needs you to decide or do, kept in asks.jsonl until you answerwith the task
Sessiona working thread bound to one task; close it any timeas long as you like
Leadoptional agent role that owns a category of taskslong-term

The one rule: the card is the truth, not the conversation. When a session is closed, the next one binds to the same task, reads the card and carries on.

Getting started

  1. Install once, from the claude-pet repo: hq/install.sh --root ~/claude-hq (any directory for your cards). It lists every change first and asks before doing anything; add --no-hooks to get the board without touching Claude's settings. Needs python3. See What install changes.
  2. Open the board: double-click the pet (double-click again to hide it), or right-click → Task Board…. While the board is open the pet shows in the Dock and in Cmd-Tab, so you switch back to it like any window (clicking the Dock icon works too, and restores it when minimised); closing the board takes the icon away. In the menu bar, Close Task Board (Cmd-W) closes it; Quit Claude Pet has no Cmd-Q on purpose, so a stray shortcut can't take the pet away with it.
  3. In the Sessions column, bind a running session to a task — or click New task to create one and bind it.
  4. From then on, work through Needs you and message sessions straight from the board.

Sessions that were already running when HQ was installed should be restarted once so the hooks load.

Once it has compacted (your own /compact too), the number is the compacted size estimated straight away, not the old one until the next reply: the compaction records only how big the conversation is, and every request also sends the system prompt, the tools and the files attached again (usually 25–55k), so what that came to after the last compaction is added (in a session that has not compacted before, its first reply's size, at most 60k). The next reply replaces it with the real figure. From two thirds (67%) the number changes colour and the pet says "/compact or a new session saves quota"; red from 80%. It speaks when a session crosses two thirds: not for one already past it when the pet starts or resumes from a pause, and again only after a compaction takes it under half and it crosses once more. The dot and the status word are exactly the pet list's (the word: "Working", the command it is running, "1 in background", "Answered"…; hover the dot for words): green, breathing = working; a turning arc = waiting on an agent it sent off; green with a coral corner = working, but the last several calls failed; grey-green with a ring going out = turn over, but a command or process it started still runs in the background; a coral diamond = waiting for your approval; an amber ring = waiting for your answer; grey = idle; a dashed grey ring = gone quiet: the turn was interrupted (Claude Code says idle), or nothing heard for a while. With Reduce motion on nothing moves, and the shapes alone tell them apart.
  • Approve from the board: a session stuck on a permission prompt (coral diamond) shows an Approve box on its row: what it wants to do in full (the whole command, the whole path or URL, another tool's arguments), with Allow / Deny. Allow takes two clicks: the first turns it into Allow?, a second on the same prompt approves, and it disarms after 6 seconds — the board refreshes every few seconds and rows can move, so a click can never land on another session's prompt; while the pointer rests on an Approve box the board does not refresh. Deny takes one. The same mechanism as the pet's Allow / Deny: the terminal's prompt still appears and the first answer wins; if you answered in the terminal first, the click does nothing. Shown only while the pet is still holding that prompt — one that came up while the pet was not running, or has waited close to 10 minutes (the hold ran out), is answered in the terminal. When one session has several prompts up at once (subagents asking together, say), only the newest can be answered here; answer the rest in the terminal.
  • Background sessions (blue "background" tag) have no terminal: Attach (terminal icon) opens claude attach in your chosen terminal so you can talk to it; Stop (square icon, click twice) stops it — the conversation is kept and Attach resumes it. Between turns you can message one: the board stops it and continues it with your message via claude --bg --resume in its folder (same id, with the board's skip-permissions choice). Not while it is in the middle of a turn — wait for the turn to end, or Attach.
  • Stopping a terminal session: a session in a terminal has a Stop too (square icon, click twice): it ends the Claude Code process and keeps the conversation. A tab the board opened closes with it (the board's command ends in ; exit 0, so the shell exits when the session ends — Stop, /exit or Ctrl-C twice alike), so tabs don't pile up; ↻ Resume then opens a new one. Orca and iTerm2 close it out of the box; in Terminal set Settings → Profiles → Shell → When the shell exits to Close if the shell exited cleanly. A session you started yourself in a terminal leaves its tab at the shell prompt, and Resume goes back into that tab. Setting a task to done or abandoned on the board while it has live sessions asks whether to stop them too (it lists them; conversations are kept and Resume picks them up). Tick Remember my answer and it won't ask again, doing what you chose; Settings → Sessions → Finishing a task sets it back to Ask each time / Stop its sessions / Leave them running. Esc or a click outside leaves them running this once, remembering nothing. A session that sets its own task to done or abandoned in its hq-update is handled the same way: once its reply is finished (and any background work it started), the same setting asks, stops or leaves them. Sending it another message afterwards cancels that, so a session you are still talking to is never stopped; if the board was closed, opening it within 10 minutes still does it, and an older one only gets the amber bar below. A question that pops up this way has Leave them running selected, so a Return meant for a box you were typing in stops nothing; set to stop without asking, it leaves the task's other sessions alone while they are working or waiting on you. Several tasks finished this way are asked about one at a time. A task finished with hq set doesn't ask. A finished task with sessions still running gets an amber bar at the top of its card — Stop all (two clicks) ends them; the Sessions column sums up every session on a finished task at its top, and Stop them ends them all.
  • Icons: 👁 Peek opens the conversation window; ↗ Jump goes to its terminal; 💬 Message shows the message box (hidden by default; it stays open while it holds a draft; Esc hides an empty one).
  • Messages: only Send sends — Enter is a new line. Text that arrives in one go — pasted, or from a dictation app such as Typeless — has its line breaks made plain and keeps at most one empty line in a row, counting a line of only spaces as empty (a paragraph break used to turn into four or five empty lines). It is tidied once the text has landed, so it holds even when the paste event doesn't report the line breaks; line breaks you type yourself are left alone, and Cmd-Z still undoes it. While it is on its way the button reads Sending… and is locked, so a message never goes twice. It arrives exactly as if you typed it. Slash commands: start the box with / and a list opens — the skills this session can run (from the list Claude Code itself writes into the transcript, so each project and plugin set gets its own, nothing guessed; skills and commands marked disable-model-invocation: true are missing from that list — it holds only what Claude may call — yet you can still type them, so they are added from ~/.claude, the project's .claude (the session's folder and the folders above it, up to your home) and the plugins enabled for that project (not ones its settings turn off) — a /grill-me you installed yourself, say), plus the built-in /compact and /clear. Typing filters by name (from three letters, descriptions too); ↑↓ chooses, Tab or Return fills in /name (add arguments after it), or click one. A match found only in a description isn't preselected: press ↑↓ to choose it first, otherwise Return is still a new line. After Esc closes the list it stays closed through board refreshes until you type again. Keys held with Cmd, Ctrl, Option or Shift (Shift+Tab, Cmd+Return) are left to their usual job. Picking only fills the box — Send still sends. Commands that open a menu in the terminal (/model, /config, /resume) are left out, and so are ones whose output shows only in the terminal, where Peek can't see it (/context, /cost). Before the session has listed its skills, only the two built-ins show; if the list's footer says it couldn't read this session's skills, the hq CLI is likely out of date — run hq/install.sh --yes. To an idle session the button waits (up to 5 s) until Claude starts on it; a busy session queues it, so the button is back as soon as the terminal takes it, with "Delivered — queued…" (no five-second wait). Images: paste a screenshot (Cmd+V) or drop an image into the box (PNG / JPEG / GIF / WebP, up to 20 MB); thumbnails show (✕ removes). On send each image is saved as a file and its path goes at the end of the message, and Claude reads it. Drafts are kept: unsent text in the message, ask-note, todo, new-task and other boxes, the images you added, and answers picked on a group of asks are stored on this machine — they survive a refresh, closing the window and the pet restarting, and clear once sent or answered (or when that ask is answered somewhere else). A box grows to five lines and scrolls past that; it stays where you scrolled it when the board refreshes or a new message arrives, rather than jumping back to the first line. Sessions in Orca, iTerm2 or Terminal, and background sessions between turns; elsewhere 💬 is greyed out and its tooltip says why. You can't send to a session waiting on a prompt (a coral diamond or an amber ring, "Needs approval" / "Awaiting reply"): the Return that submits a message would pick the highlighted option there (say, "Yes") and approve something you never saw. Send is greyed out and a line below says to answer it in the terminal first (↗ Jump); a permission prompt can also be answered with the row's Allow / Deny. Your draft stays.
  • A red new tag is the pet's red dot: the session finished a turn and you haven't looked at it yet. Any of these counts as looking, and clears it here and on the pet: 👁 opening the conversation, ↗ jumping to the terminal, messaging it from the board (an ask answer with send to … now included), or typing your next message in its terminal. Just having the board open, reading the one-line summary or opening the task card does not.

Conversation window (Peek)

  • The session's last 30 messages, Claude's replies rendered as Markdown. Only what you and Claude said counts toward the 30; the tool calls between them show too but take no place, and screenshots (which make a transcript large) don't cut the 30 short: Peek reads further back until it has them, up to the transcript's last 64 MB. What you typed in the terminal shows too, including messages typed while the session was busy and queued, not only those sent from the board. It follows the session as it goes: new content waits until you have stopped scrolling for about a second, so it never cuts a scroll short, and when only numbers change (tokens, time) just the status line at the top updates and the conversation stays put. Click outside or press Esc to close; opened from a context window, ← goes back.
  • Tool calls: each tool Claude calls is one row — Bash: kubectl get pods…, Edit board.js +12 −3, Agent: perf-repro — with an icon for how it went: ✓ done, ✗ failed, a spinner = running (its timer keeps ticking), ⧗ = sent to the background and not back yet, ■ = stopped (by TaskStop, or still running when its session ended), ? = waiting for you to approve it in the terminal, – = cut off before a result came. Finished rows show how long they took. Consecutive tool calls fold by default into "N earlier steps · Bash ×4 · Edit ×2 · 1 failed", leaving only the newest row and any still running; click to show them all (when every call in the run is still going, they all show anyway and it just says "N steps"). They don't drown Claude's text.
  • Details: click a tool row for its input (the command, the file path, an Agent's prompt, …) and its output (Edit / Write show the diff, additions green, removals red). Long output shows its first 4000 characters — Show all for the rest — and each side has Copy for the full text (very long ones stop at 100,000 characters of input and 200,000 of output). Opened while the tool is still running, it updates when the result comes back.
  • Live status: a line at the top says what the session is doing now — "Running Bash: …" / "Thinking…", what it's waiting on you for, or idle — then the time this turn has taken (ticking; when idle, how long the last turn took — up to the Esc, if you interrupted it), the tokens it has written this turn and the current context size (just after a compaction, the estimated compacted size, as above).
  • Claude's todos: when Claude keeps a list with TodoWrite (or TaskCreate / TaskUpdate), a line under the status reads "Claude's todos 3/7 · what it's on now"; click it for the whole list (☑ done, ◐ in progress, ☐ not started). Those tool calls don't get rows of their own.
  • Copy: select and Cmd+C; hover a message for Copy; Copy all for the whole conversation.
  • Links: web links open in your browser; file paths (.md, .html, source files, folders, …) open in their default app, relative paths resolved against the session's directory. Scripts, executables and apps are only shown in Finder, never run.

"Asked you" stays open; "Answers recorded" and "Card updated" are bookkeeping, so they fold to one line saying how many answers or which card fields changed (say state ×2 · log) — click to open, click again to fold, and it stays that way across refreshes; URLs inside ordinary code blocks are clickable too.
  • Reply from the box at the bottom; after sending, the window stays at the bottom. While you are scrolled up reading, the message you are on stays where it is when new ones arrive. Ended sessions are history-only.

Scheduled jobs

The Scheduled tab in the top bar: a Claude prompt or a shell command run on a timetable, with how many jobs there are and how each run went. This page's text comes in English and Chinese, following right-click Settings → Language · 语言.

  • What runs them: each job that is on has a macOS LaunchAgent (~/Library/LaunchAgents/local.claudepet.job.<id>.plist); launchd starts ~/.claude/pet/pet-emit --run-job <id> on time. So a job runs with the pet closed, and a run missed while the Mac slept happens once when it wakes (once, however many were missed). macOS may say a background item was added the first time — that is expected.
  • Start from a template: with no jobs yet, the page offers three — Summarise last night's CI every morning (Claude · weekdays 09:00), Check my PRs for new comments every hour (Claude · every hour), Clear caches once a week (Shell · Sun 03:00). A click opens the new-job form with the name, kind, prompt or command and schedule filled in, to adjust and save.
  • New / Edit: New job at the top right. The form is one page of questions on the left and answers on the right: What (switch between Claude prompt and Shell command at the top, then a name and the prompt or command), Where (the folder it starts in, whose CLAUDE.md it reads; Choose… opens a folder picker), When it runs, What it may do (Claude jobs only), Tell me (with the On switch), and More (model, time limit, quota guard, how the session carries on — written as a few sentences with the blanks to change inline). Cancel / Save and run now / Save stay at the bottom.
    • The prompt goes to claude -p as written, every run. As in the terminal, start it with /skill-name args to use a skill — or just describe the work and Claude picks one. Your MCP servers, plugins and hooks load as usual.
    • A command runs in your login shell (zsh -lic), with the PATH your terminal has.
    • What it may do (permissions): nobody is there to click Allow, so choose now — Only what's allowed (the default; only what your settings already allow; anything else is refused and noted in the run), Also edit files (acceptEdits), Everything (skips every permission check; only for prompts you fully trust).
    • Session (under More): each run starts a new session (the default; clean and cheap; only the newest N runs keep their session — older ones are deleted from ~/.claude/projects, and 1 keeps only the latest) or continues the same session (claude -p --resume, for work that needs to remember; it is compacted first once its context is as full as the percentage you set — 50% by default, of the model's context window; the list shows how full the session is now). Note: Claude Code's /clear itself starts a new session, so "clear the same session, then run" is "new session every run, keep 1".
    • Time limit: past it, the whole process group is stopped.
    • Quota guard: before each run it looks at your subscription's limits, and when the weekly or the 5-hour quota is already used past the percentage you set (90% for both by default; 0 = don't check) it skips the run — recorded as "Skipped — weekly quota at 94%" — leaving the rest for your own work. The reading is the higher of the pet's own (from your statusline) and the one Claude reported during the last job run, as long as its window hasn't reset.
    • When it runs: one sentence with its blanks inline, e.g. "Run [every weekday] at [09:00]". Choose every weekday, every day, on some days (click the days), every hour, every few minutes, or by cron (minute hour day month weekday; */15, 1-5, MON work). The next three times show below as small chips while you type; a mistake says what is wrong.
    • Tell me: when it fails (default), after every run, or never. The switch beside it decides whether the job is on once saved.
    Save and run now saves and runs it once, to try it.
  • The list: next to the title, how many jobs there are and how many are on (and any running or failing). A row per job, separated by hairlines: the name with a Claude / Shell tag, and under it, faintly, the prompt or command · folder; the schedule in words (e.g. "Weekdays 09:00") with "Next …" or "Paused" under it; the last 12 runs as small bars (green = succeeded, taller for longer runs; red = failed / timed out / interrupted, full height; amber = succeeded with a tool refused; blue = running; a short grey stub = skipped or stopped), with the last run's time, result and duration under them (red if it failed); the quota the last run used (Claude jobs; plus the session's context when it continues one session); then the switch, Run now (Stop while it runs), Edit and Delete (two clicks). A job that is off has its name and schedule faded. When the last run failed, its last lines of output show across the row on a faint red ground. In a narrow window the quota column folds away.
  • Runs: click a job's name for its last 30 runs: when it started (manual runs are marked), result, time taken, quota used (how much the weekly and 5-hour quotas rose during the run, e.g. "week +1%", or "<1% of the week"; hover for the API list price in dollars), and a summary (the reply's first line, or the command's last output line). A run due while the previous one is still going is recorded as skipped, rather than two runs fighting over one session.
  • Details: one run's input, Claude's reply (rendered) or the command's output, "What it did" (each tool call with its result; refused ones in red) and the log. Conversation opens the run's whole session, as for any session; Continue runs claude --resume on it in a terminal (with stay on board ticked, you carry on here).
  • With the cat: a scheduled Claude run never shows in the pet's or the board's session lists, and never makes the cat wait for an approval (the hook sees CLAUDE_PET_JOB and leaves it alone). When a job fails, "Scheduled job failed: …" pops up above the cat — a click opens this tab; failures you haven't seen count toward the badge and are listed under Scheduled in the cat's list (running jobs too). Opening this tab counts as seeing them.
  • Files: one folder per job, ~/.claude/pet/jobs/<id>/: job.json (its settings), runs.jsonl (a line when each run starts and ends; the newest 100 runs), state.json (the session id for "same session", …), logs/ (each run's output; Claude runs also keep their stream-json). Uninstalling Claude Pet switches every job's agent off and keeps these files.
  • Can't read a folder? If a job fails reading ~/Documents, the Desktop or another protected place, allow pet-emit in System Settings → Privacy & Security (Files and Folders, or Full Disk Access).

Secretary

Secretary in the top bar opens a standing conversation with a Claude that knows this board. Ask it "How are T-072 and T-071 doing, and what is blocking them?", "What is waiting on me?" or "What looks stuck?". It looks up the cards and sessions every time before it answers (hq status, hq asks, hq board…), and it marks what waits on you with ⚑. Its job is the path information → board → your attention, and it doesn't do the work itself: it tells you which task a piece of work belongs to, and you start it there with ▶ New session.

  • The first time, Secretary lists what it would create, and nothing is created until you click Set up. Files that are already there are always kept. It creates:
    • .claude/agents/secretary.md in the task root: who it is and its rules. You can edit it freely.
    • its memory files: secretary/profile.md, people.md and playbooks.md;
    • its own task card, "Secretary";
    • a job called "Secretary" on the Scheduled page, with no schedule.
  • The window is Peek. Each message you send is one run of that job, with your message as its prompt; replies and tool calls show as usual. While it replies, Send is greyed out, and the status line says it is replying, with a Stop button. If the last message failed, or was skipped because of quota, the status line says why. There are no slash commands.
  • One session: every message continues the same conversation (--resume).
    • Past the job's context threshold (50% by default), the conversation is compacted first.
    • When the weekly or 5-hour quota is used past the job's limit (90% by default), the message is skipped, so the secretary can't use up your quota.
    • To change these, the model or the time limit, edit "Secretary" on the Scheduled page. You can also give it a schedule, for example a look over the board every morning.
    • Its folder, agent, same-session mode and allowed tools are what make it the secretary. If you change them, they are put back at the next message.
  • What it may do: it runs in the background with nobody there to approve a step, so only three things are allowed up front:
    • reading files (Read, Grep, Glob);
    • running ~/.claude/hq/bin/hq;
    • editing files under secretary/.
    Anything else is refused, unless your Claude Code settings allow it anyway. It only reads outside systems; messages and emails are only drafted, in its reply.
  • Answer its proposals in its window, or in Needs you. Creating a task, adding a note or a todo to a task (such as @me send the reply to Atul), closing a task, or changing its memory: each shows up as a question under "It asks you" at the bottom of the secretary's window, just above the message box. The same questions are in Needs you too, labeled with a green Secretary that opens its window; answer them in either place. Answer with Yes, No or Later; a note you add changes or replaces the proposal.
    • After a Yes, it wakes up about 10 seconds later and carries it out, then reports one line per proposal in its window. The wait outlasts the Undo button, and after an Undo it does nothing. If it is replying at the time, it waits until that reply ends.
    • To todo means you'll do it yourself: it becomes your @me todo, and the secretary leaves it alone.
    • After a No, it leaves it, and doesn't propose it again unless something changed.
  • Memory: it reads all three files at the start of every conversation. memory: profile · people · playbooks, under the window's title, opens each file in your editor.
    • profile.md: who you are, your language, what matters in each project.
    • people.md: your colleagues, who they are and what they own.
    • playbooks.md: recurring processes, such as release tests and RCAs.

  • Its own card, "Secretary", is its notebook: its hq-update blocks land there and record what it is keeping an eye on for you, which the window shows at the top as "Keeping an eye on". The card isn't part of your work: All, Focus and their counts leave it out; its questions still show in Needs you. Links to the card (such as the id on a todo made from one of its questions) open the secretary window. Its questions have no "Yes, always": grants are never given to the secretary.

How sessions and the board connect

Once bound, three hooks make the session follow these rules:

  1. Read the card, work, write back — status, next, todos and log go back to the card. Instead of running hq log / hq set … one call at a time, the session ends its reply with an hq-update block and the Stop hook writes it to the card. Every extra tool call re-reads the whole conversation, so this saves those tokens. Only the block at the end of the reply counts — one quoted or shown as an example mid-reply does not, nor do template lines like <…>. If any line cannot be applied (a misspelt status, a todo it cannot find or that matches several, …), nothing in the block is written and it is sent back to the session once to fix, with the candidate todos listed — so resending the whole block never adds anything twice. A todo, log line or ref already on the card is not added again. A turn longer than two minutes that never touched the card is sent back once to update it. 
    ```hq-update
status: blocked
next: wait for infra's token
state: build is green; waiting on the token
todo: @me send the token request
done: rerun the suite
log: picked plan v2 because it is cheaper
ref: PR #9 https://github.com/…/pull/9
```
    Only the lines that changed; todo / done / drop / log / ref / workdir may repeat; state replaces the card's Status section; done / drop find the todo by its text; project: NAME moves the task to an existing project (no such project: the block goes back — only you make projects). Nothing changed: a block holding just touch.
  2. Questions for you are tracked — the session ends its reply with an hq-asks block, one item per line; each becomes an ask on the board (T-012.3, …). 
    ```hq-asks
- Approve plan v2?
- Ask Chengjie for the dataset?
```
  3. An unanswered ask is never a "no" — open asks are reminded to the session every turn.
  4. Granted steps aren't asked again — whenever a bound session starts (new, resumed, after /clear or a compaction) it gets the task's grants in force (at most 10 and about 1500 characters; a session bound from the board gets them with its first injection). The rule: grants are permissions, not requests to act now; while bound to the task, a step the session would otherwise ask about that a grant clearly covers is taken without asking and the grant named in the reply; each is read narrowly, and anything bigger, riskier or different is asked as usual. After that a turn only carries a line when the grants changed ("+ granted — a permission from now on, not a request to act now: …" / "- revoked — ask again before doing this: …"), nothing otherwise, so the per-turn injection stays tiny; a grant made by Yes, always is stated once, with the answer. On resume or compact the session first hears what was revoked since it last saw the grants (the old conversation still holds the old list); a session re-bound to another task is told the old task's grants don't apply there. For a routine, reversible kind of step that will come up again, the session may end the ask with a suggested wording, [grant: …] (never for deleting, sending, spending, merging or force-pushing); the board takes it off the question and pre-fills the Yes, always editor with it. Only you add grants: sessions are told never to add, widen or reword one, and hq grant add and ask resolve --grant refuse to run inside a Claude Code session (the board and your own terminal can; a session may still revoke); a state: line can't be a heading, so an hq-update can't write a grants section either.
  5. The session sees its own todos — whenever a bound session starts (new, resumed, after /clear or a compaction) it gets Claude's open todos from the card, word for word (at most 20 and about 2000 characters; older ones are only counted), and is asked to check them against how things stand and, in its next hq-update, tick finished ones with done: and drop obsolete ones with drop:. Only at start (and, for a session bound from the board, once with its first message after binding), not every turn; to have it check again mid-way, use Tidy todos by the todos.
  6. The session knows its line of work — when the task's project has a PROJECT.md, a bound session gets a note on it whenever it starts (new, resumed, after /clear or a compaction, and on hq bind): the project, goal or duty, its deadline, the first line of its goal, then the whole Brief (at most 2000 characters; past that it is cut and pointed at PROJECT.md), whatever repo the session works in. An empty brief: nothing is said. After that it hears again, with its next message, only when this note changes (the brief, title, kind, status, deadline or first line of the goal is edited, or the task moves to another project); a brief that is gone is reported as no longer applying. The project's Grants section holds for every task in it; they are listed under "From project …".
  7. Answer on either side — on the board (delivered next turn), or in the chat (the session records it with an hq-resolved block and the board updates).
  8. Drafts are not done — anything the session drafted for you to send becomes an @me todo until you tick it.

Use the board for the overview, batches of answers and status changes; talk in the session's terminal for a deep discussion — once bound, what it asks there shows up here too.

Start from existing sessions

A fresh install usually meets a machine full of Claude Code sessions and history. Two steps turn them into a board:

  1. Projects: Suggest from sessions in ⚙ Settings → Projects (an empty board offers it too). It scans the last 60 days of transcripts and lists candidate projects — one per git repository, or per directory outside one — with their session counts. Nothing is pre-selected; tick and Create. From a shell: hq scan (read-only), hq scan --apply-projects --only name,name.
  2. Tasks: run /hq-onboard in any Claude Code session. Claude reads those sessions, drafts task cards (status, next step, your todos, links, confidence), shows them per project and creates nothing until you confirm; then live sessions are bound to their tasks and ended ones are recorded on the cards, their history one click away.

Change anything afterwards — on the board, or by asking Claude in any session. Inferred statuses are flagged "verify" in each task's log.

Projects

  • A project is a line of work, not a directory: a goal with an end (kind: goal — "ship hq-v2") or a standing duty (kind: duty — "customer RCAs", "release regression"). A task belongs to one project. A directory (repo) is just a task's workdir: where sessions open, resume and are matched. Category says what kind of work it is; it is independent of the project.
  • PROJECT.md: one per project, <root>/projects/<name>/PROJECT.md. Frontmatter: title (display name), kind (goal / duty), status (active / paused / done / abandoned), due (a goal's deadline), jira (epics), fixVersions. Sections: Goal (a duty: its scope), Done when (a duty: what running well looks like), Brief (given to every session on one of its tasks: background, conventions, commands, pitfalls), Grants (same format as a card's), Log. Headings in either language (## Goal, ## 目标, ## 目标 / Goal …); a section runs to the next of these headings, so a ## Commands of your own inside the brief stays in the brief. A duty's status is active or paused. Two projects whose names differ only in case are refused (on macOS they would be one folder). The name is a short id (used by the CLI and a card's project:); the display name goes in title. A project without a PROJECT.md still works — it just has no kind, goal or brief.
  • Directories only suggest: hq.json still keeps each project's name, order and directories; creating a task or binding a session gives a task with no project a default from its directory (the deepest match wins). Give directories only to repos that belong to one project; leave shared repos out, and tasks started there land in "No project" for you to sort. Change it any time in the task; a session can move it with hq-update's project:.
  • ⚙ Settings → Projects: add one (name + directory; a draft PROJECT.md comes with it), rename it (edit, then Save — every card and the PROJECT.md folder follow), add or remove directories (+ directory), drag ⠿ to reorder, remove it (if tasks use it, pick where they go or "no project"; its PROJECT.md folder is not deleted but moved to projects/.removed/); while some tasks have no project, Assign by directory sorts them in one go.
  • From a shell: hq project list | show NAME | brief NAME | add NAME [--kind goal|duty] [--title T] [--due DATE] [--path DIR] | set NAME kind=… status=… due=… title=… jira=A,B fixVersions=… | paths NAME DIR… | rename OLD NEW | remove NAME --to OTHER | auto | order NAME…. list gives each project's open, done and waiting-on-you counts; show prints it with task counts (open, done, done in the last 7 days, waiting on you); brief prints exactly what sessions are given. Goal, done-when and the brief: edit PROJECT.md.

Categories and workdirs

Categories

  • Each task root keeps its own list in hq.json. New roots start with a generic set — feature, bug, investigation, review, ops, docs, other — change it freely.
  • In ⚙ Settings → Categories: rename by editing a name and pressing Enter; ✕ removes; the bottom box adds. From a shell: hq category ….
  • A category is just a label on each card, so:
    • renaming rewrites every card that uses it;
    • removing an unused one just removes it; removing one that tasks use first asks where those tasks go (another category or none), and every moved card logs the change;
    • a card with a category that is not in the list (say, hand-edited) still shows, marked "not in list" — "Add to list" in Categories adopts it.

Workdirs

They maintain themselves: binding a session to a task records the session's directory on the card (never your home folder or the task root). You can also type one when creating a task. The board uses them to list matching tasks first in a session's "Bind to task…" menu.

Link rules for resources

Full URLs in Resources are clickable as they are. Shorthand like QA-9519 or bigtest#3248 becomes a link once you add links rules to hq.json in your task root — for any tracker (Jira, Linear, GitHub Issues, …). Rules are tried in order and the first match wins; $1, $2 are the regex groups:

"links": [
  {"match": "^([\\w.-]+/[\\w.-]+)#(\\d+)", "url": "https://github.com/$1/pull/$2", "kind": "pr"},
  {"match": "^([\\w.-]+)#(\\d+)",            "url": "https://github.com/your-org/$1/pull/$2", "kind": "pr"},
  {"match": "\\b([A-Z][A-Z0-9]+-\\d+)\\b",      "url": "https://your-site.atlassian.net/browse/$1", "kind": "ticket"},
  {"match": "^(ENG-\\d+)$",                   "url": "https://linear.app/your-team/issue/$1", "kind": "ticket"}
]

When adding a resource, prefer "title + URL", e.g. 2026-11 QA AWS key leak – action items https://…: the board shows the title, cut to a few words, with the full title and URL on hover. Bound sessions record resources the same way.

kind picks the group: ticket, pr, doc or link. Full URLs are grouped by their host automatically.

Leads

Copy templates/lead.md from your task root to .claude/agents/bench-lead.md, describe its scope, then run claude --agent bench-lead in the task root and say "continue T-020". A lead binds to the task, delegates heavy work to background subagents, keeps its own context small and reports in a fixed shape. Small tasks don't need one — the bound session is the lead.

Good to know

  • Only sessions bound to a task have their questions tracked.
  • A background session can only start in a folder you have trusted (open Claude Code there once and accept); otherwise the board says so.
  • Board answers: with send now ticked they arrive at once (Orca / iTerm2 / Terminal / a background session between turns); otherwise at the session's next turn.
  • Messaging works for Orca, iTerm2 and macOS's own Terminal (iTerm2 and Terminal ask for Automation permission the first time — allow Claude Pet to control it; if you said no, turn it on in System Settings → Privacy & Security → Automation). If a message typed into iTerm2 or Terminal hasn't started a turn within 5 seconds (and the session isn't busy), the board says so — press Return there; a / command or a ! line starts no turn, so it counts as sent once typed. A session waiting on a prompt can't be sent to — answer it in the terminal first. In other terminals (Ghostty, VS Code, …) the box is greyed out — Jump only.
  • The Sessions column relies on Claude Pet's hooks; sessions started before the pet was installed don't appear.
