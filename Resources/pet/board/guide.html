HQ 是什么

同时开着十几个 Claude Code session 时，难的不再是干活本身，而是记住每个 session 在做什么、它问过你什么、你有没有回答。HQ 把这些状态从对话里搬到文件里：

概念是什么存在多久
项目（project）一条工作线：一个目标（有终点，比如"发布 hq-v2"）或一项长期职责（比如"客户 RCA"），不是一个目录。内容写在 projects/<名字>/PROJECT.md，里面的简报会交给它每个任务的 session目标到完成为止；职责长期
任务卡tasks/T-012-xxx/TASK.md：目标、状态、下一步、待办、日志到任务完成
待回应事项（ask）session 问过你、需要你决定或去做的事，记在 asks.jsonl，直到你回应跟随任务
session绑定到某个任务的一条工作线程，随时可以关随你
负责人（lead）可选。负责某一类任务的 agent 角色长期

核心原则：任务卡才是真实状态，对话不是。session 关了没关系，下一个 session 绑定到同一个任务、读卡就能接着做。

开始使用

  1. 安装（一次）：在 claude-pet 仓库里运行 hq/install.sh --root ~/claude-hq（任务卡放在哪个目录都行）。它会先列出要做的每一项改动，确认后才执行；只想要看板、不想动 Claude 的设置，加 --no-hooks。需要 python3。详见安装会改什么。
  2. 打开看板：双击桌宠（再双击收起），或者右键桌宠 → Task Board…。看板开着时，Dock 和 Cmd-Tab 里会出现桌宠图标，像普通窗口一样切回来（点 Dock 图标也行，最小化了也会恢复）；关掉看板图标就消失。菜单栏里 关闭任务看板（Cmd-W）关窗口，退出 Claude Pet 故意不配 Cmd-Q，免得误按把桌宠也退掉。
  3. 点底部状态栏的 session 数打开 session 列表，给正在跑的 session 选一个任务绑定，或点 新建任务 新建任务并顺手绑定。
  4. 之后就在看板上处理 Needs you 里的事情；点任务卡片打开详情侧栏，在里面直接给它的 session 发消息。

装好 HQ 之前就已经开着的 session，最好重开一次，hook 才会生效。

四个页面 · Focus：正在关注的任务

顶栏左边的 Focus · 项目与职责 · Needs you 切换页面（会记住），每个标签上都带着数字。Focus 是工作台，只放你正在关注的任务——不按天清空，一直留着直到你把它拿掉；项目与职责 是所有项目，每张卡上列出在等你和在跑的任务，数字是进行中的任务数（见项目与职责）；Needs you 分三列：要你回答的问题、要你去做的 @me 待办、记下的，标签上的数字是前两样加起来（只有它是亮的橙色，因为只有它在等你）。最后一个标签 定时任务 是按时间表自动跑的任务，见定时任务。

  • 四列：Focus 和项目页都把任务分成 等你、在跑、待推进、卡住 四列。列不是另存的状态，是从任务卡的 status、未回应的问题、待办和 session 的实时状态推出来的，按这个顺序取第一个符合的：等你——它的 session 停下来在等你（等你授权或回答）；在跑——有 session 在干活，或者它起的命令还在后台跑（session 这一轮结束时只剩一个在「等」的后台命令——Wait、Poll 这类——最多算 20 分钟；这时它的问题和你的待办照样显示在卡片上，只是还轮不到你，等它停下来再回到等你）；卡住——status 是卡住（在等别人：即使还有没回应的问题或你的 @me 待办——比如要等别人先动、你才能做的事——它们照样显示在卡片的黄底和 Needs you 里；session 在它上面提了新问题时，status 自动变回"等你"）；等你——有没回应的问题、有你的 @me 待办，或 status 是"等你"；待推进——其余进行中的任务，没有 session 在跑，开一个或接上一个就能继续。勾 Focus 标题旁的 最近完成（会记住）多出第五列：3 天内完成的任务。
  • 拖动卡片改状态：把卡片拖到别的列，就是把任务的 status 改成那一列的（status 就用列名称呼）：等你 → waiting-on-me，待推进 → active，卡住 → blocked，最近完成 → done。在跑 不能拖进去——那一列只看 session 在不在干活。拖进 卡住 时，即使还有问题或你的待办也会进去；只有 session 正停着等你授权或回答、或 session 在干活时它留在原处。改完卡片如果还留在 等你 或 在跑（比如还有没回应的问题、session 还在干活），底部会提示原因。在 Focus 里同一列内上下拖，调整你自己的顺序。
  • 状态和列用同一套名字：任务卡里存的 status 只有五个值，看板上都用它会落到的那一列来称呼——active 叫 待推进，waiting-on-me 叫 等你，blocked 叫 卡住，另外是 已完成、已放弃。在跑 不是 status：只要有 session 在干活任务就在这一列，停下来后回到它的 status 那一列。所以一个任务可能和它的 status 不在同一列：status 是 待推进，但有没答的问题或你的待办时在 等你，有 session 在干活时在 在跑。命令行里 hq set T-012 status=ready、status=needs-you 也可以。
  • 加进 Focus：顶部输入框输入编号或标题后点 添加；或者点任务卡片右上角的 ☆（变成 ★）。新建的任务自动加入 Focus。再点 ★ 把它从 Focus 拿掉，任务本身不变。
  • 任务卡片只放要一眼看到的：编号（颜色就是它所在的列）、项目（◆ 项目 / ↻ 职责）、标题；有要你处理的事时一块黄底：没回应的问题（?）、你的 @me 待办（方框可以直接勾），最多两条，多的写"还有 N 件 →"。每个问题下面有 可以 / 不要，点一下就回答了（不带说明，和 Needs you 里一样会发给它的 session，可以 Undo）；要写说明、选稍后或转待办，点 …、问题文字或"还有 N 件 →"，会打开详情侧栏并停在这个问题上。项目页的单行卡片上，鼠标移到问题上才显示这几个按钮；然后是下一步（卡住时写"在等"）；最底下一行是 session：一叠状态点、几个 session、在干活的写它最后一句话，空闲的写状态和多久前，右边 👁 打开它的对话窗口（Peek）。没有 session 时写"没有 session"，旁边是 Resume（续上最近那个）和 新开（新开一个）。
  • 详情侧栏：点卡片打开右边的详情侧栏；再点同一张卡片、点侧栏外的任何地方（点别的卡片是换成那张；浮在输入框上方的快捷短语条和 ; 短语列表不算外面，在侧栏里选短语不会关掉它）、点 ✕ 或按 Esc 关掉。顶部是编号、项目、☆、标题，下面一排 待推进 / 等你 / 卡住 / 完成：亮着的是它现在所在的列，点别的就把 status 改成那个（点亮着的那个不改，只说它为什么在这一列）；它因为问题、待办或在干活的 session 不在自己 status 那一列时，你设的那个按钮右上角有个小点，悬停说明原因；有 session 在干活时最前面多一个 ● 在跑 · N 个 session（只是标记，不能点）；⋯ 里是 放弃；有没回应的问题时，最上面是 Claude 在问，上面是提问时 Claude 的最后一段回复，回答方式和 Needs you 完全一样（在框里写回答、可以贴截图，留空就是按建议；✕ 不要，⋯ 里是稍后 / 转待办 / 不了解背景；几个问题一起发送）；侧栏宽 680 像素，长回复也好读；再往下是下一步、session、待办、日志和链接（见下面的点开一个任务）。从别处跳到一个任务（问题上的编号、上下文窗口的 Show task、小猫的列表……）也是打开这个侧栏。
  • ⚠ 异常标记：卡片标题下面的橙色 ⚠ 行，是卡片和 session 对不上的地方（来自 hq status，大约每分钟看一次）：卡片落后——session 在卡片最后一次写入 10 分钟以后还在调工具，卡片没跟上；空等——下一步或当前状态说在等某个构建 / 测试 / watcher，但已经 30 分钟没有 session 在干活、在等你或在后台跑任何东西（后台任务不管是多久以前启动的，只要还没结束都算）；太久没更新——没完成的任务 7 天没动（这一条不止 Focus：所有看板上这样的卡片，编号旁边都有一个橙色的 N 天没动，悬停看从哪天起；推进它、关掉它，或者把周期性的待办改成定时任务）；卡片超预算——超过 16 KB、30 个链接或 30 条待办。标记会随情况变化自己消失。（完成的任务离开 Focus，「完成了还有 session 在跑」只在 hq status 里看得到。）
  • 所有 session：点底部状态栏的 session 数，右边打开 session 列表（见Sessions），还没绑定任务的 session 在这里绑定。
  • Focus 列表存在任务根目录的 focus.json（以前按天存的旧文件会自动沿用最近一天的列表）。命令行：hq focus、hq focus add|remove T-012、hq focus order T-3 T-1 …（排序）。

顶栏 · Needs you · 项目与职责

顶栏

  • 顶栏只放能点的东西：左边切换 Focus · 项目与职责 · Needs you · 定时任务（标签上是各自的数字），旁边是 记一笔 输入框（见记一笔），右边是搜索框、秘书（见秘书）、＋ 新建、⚙ 设置、? 本说明。窗口不够宽（约 640–1080 像素）时顶栏分两行：记一笔和搜索框换到第二行，标签太多放不下时可以左右滑动；再窄（手机）就是手机的排法。看板每 4 秒自动刷新，不需要手动刷新按钮；页面上选中了文字（比如要从 Claude 的回复里复制一段）时先不刷新，取消选中后马上补上，最多等一分钟。读数据卡住（hq 超过 15 秒没响应）时，顶上显示错误，下一次刷新照常再试，不会从此停住。Mac 和几台手机同时开着看板时，2 秒内共用同一次读取；后台 session 的列表（claude agents）约 20 秒读一次，从看板新开或停下一个 session 后马上重读。只画正在看的那一页。session 每调用一次工具、换了在做的事、上下文占比变了，只就地改它的圆点、状态文字和"N 分钟前"，不重建页面（按着鼠标或选着文字时也先不改）；session 的先后顺序变了、说了新的话、出现要你处理的事，才整页重画。
  • 底部状态栏：有没看过的新回复时，最前面是红色的 N 条新回复（点一下看列表，见 Sessions）；有上次打开之后变过的卡时，接着是蓝色的 N 张卡有更新（点一下看列表，见下面的「有更新」）；session 有几个（在干活的、等你的；点一下打开 session 列表），问题、待办和没分拣的记录各几条（点一下跳到 Needs you），最右边是额度。任务数在标签上。
  • 浅色 / 深色：跟着系统外观走（系统设置 → 外观）。
  • 中文 / English：右键小猫 → Settings → Language · 语言，可选 跟随系统（默认，macOS 首选语言是中文就显示中文）、English、中文。小猫的菜单、列表、气泡，看板，本说明和连接状态窗口一起切换，切换后页面立刻重新加载，草稿不会丢。定时任务页也跟着这个设置走，没有单独的开关。中文界面里 session、todo、ask、Resume 这类术语保留英文。
  • ⚙ 设置（在哪个页面都能打开，Esc / 完成 / 点窗口外关闭）：新 session 开在哪、skip permissions、stay on board、在宠物上点击 session 时打开什么、结束任务时怎么处理它的 session、active first。项目的增删改都在项目与职责页上。
  • 在宠物上点击 session 时打开（⚙ 设置，或者右键桌宠 → 设置 → 点击 session 时打开，两处是同一个设置）：点完成气泡、点小猫列表里的 session 或已完成的一行、按"跳到等待中的 session"快捷键时去哪里。默认 它的终端；选 看板上它的任务 后，打开看板并打开这个 session 绑定的任务的详情侧栏——同时把这个 session 的那一行高亮、打开它的对话窗口（Peek），可以直接看回复、发消息；关掉对话窗口后高亮再留几秒。没绑定任务的 session 照旧跳终端。选了看板后，绑定了任务、但终端跳不过去的 session 在小猫列表里也能点了。
  • 额度：5h 和 week 两条——订阅的 5 小时额度和每周额度用了多少（70% 起变黄、90% 起变红），resets 后面是多久后重置。和悬停在小猫身上看到的是同一份数据。Claude Code 只把额度交给状态栏命令，所以要有状态栏把它存下来：用 claude-hud 的话，在 ~/.claude/plugins/claude-hud/config.json 的 display 里加 "externalUsageWritePath": "<你的主目录>/.claude/pet/hud-usage.json"（必须写绝对路径）；或者用 pet-emit --statusline 包一层你的状态栏命令（见仓库的 docs/pet.zh-CN.md）。没有新鲜的数据就不显示。每个开着的 session 都会写入它自己最后一次调用 API 时的数字，所以显示的是最后出现的那组读数，不是最大的那组：手动重置额度之后会跟着降下来。合盖睡眠、重启小猫后新旧顺序依然记得；只有小猫从没见过的读数（第一次运行，或它关着、睡着期间新写进来的）一开始分不出新旧，会先显示较高的那组，等某个正在工作的 session 的数字再变一次就对了。
  • Filter tasks…：每个页面都按它筛选。任务按编号、标题、关联、项目匹配；Needs you 里的问题和待办还会匹配它们自己的文字（比如搜 PR #78 能找到写着它的待办）。在项目与职责页，最上面会列出所有匹配的任务，已结束的（更早完成的、已放弃的）也在，方便找回来（见项目与职责）。筛选时列表上方会写"显示 几 / 几"，点 清除 就恢复全部；从别处跳到一个被筛掉的任务时，筛选会自动清掉。
  • ＋ 新建：新建任务、项目或职责，见项目与职责。建任务时工作目录可以手填或从建议里选（也可以不填，绑定 session 时会自动记上），并可立即绑定一个 session。
  • ?：打开本说明。
  • 删除 / 解绑都要点两下：解绑 session、从任务移除以前的 session、删关联链接、待办的 ✕（不做）、删项目的默认目录、删没有任务的项目——第一下按钮变成红色的"Unbind?""Remove?"等，4 秒内再点一下才执行，不点就恢复原样。

Needs you（第三个标签页）

  • 回答（第一列）：所有还没回应的问题，最早的排在最上面，同一个任务的问题排在一起。session 把同一个还没回应的问题再问一遍时，不会多出一条。
    Claude 的最后一段回复：每个任务的问题上面，是 Claude 提出这些问题的那一轮回复（Markdown 渲染，过长可以在框里滚动），不用再去终端翻它说了什么。点标题折叠，会记住；它再提新的问题、带来新的回复时，会重新展开。看板刷新时，框里滚到哪就停在哪。几条问题来自不同轮的回复时，显示最新的那段，并写明有几条来自更早的回复——点那条问题的文字就能看到它自己的那段。
    用文字回答：每条问题下面是一个输入框，怎么回答都写在框里（多行也行；回车换行，⌘回车发送，⌥回车也可以）。框是空的就发送，表示"可以，按你的建议来"——按钮上写着 ✓ 按建议做；写了字，按钮变成 发送回答，你写的就是回答（session 收到的是 "Answer: …"）。旁边两个小按钮：
    按钮含义
    ✕ 不要（No）不做 / 不要；框里可以写原因或者换成什么。点了变红，按钮变成"发送：不要"；再点一下取消
    ⋯ → 稍后（Later）先不回答：问题留着，从 Needs you 和小猫的红点里隐去，第二天自动回来；session 会收到"用户稍后再答，先做不依赖它的事"。被推迟的问题收在一行"N 条稍后再答 · 明天回来"里（session 用 later until 推迟到别的日子时，写最早回来的那天），点开可以直接回答
    ⋯ → 转待办（To todo）这不是要回答的问题，是我自己要去做的事（比如"PR 合并后把消息发给 Ping"）：在这个任务里加一条 @me 待办（框里写的会接在后面），问题关掉，并告诉 session 我会自己做、别再问。Undo 会把这条待办标成已放弃并重新打开问题
    ⋯ → 不了解背景（No context）不了解背景、答不上来，先归档
    ⋯ 里选了一项，⋯ 会亮起，发送按钮写着它（如"发送：稍后"）；再打开 ⋯ 点同一项取消。卡片左边的色条跟着回答变：黄色是按建议、绿色是你写了回答、红色是不要。
    送达：提出问题的 session 还在运行、而且在 Orca、iTerm2 或 Terminal 里（或者是两轮之间的后台 session）时，按钮下方有 现在发给 ‹session›（session 空闲时默认勾上）：回应会立刻作为一条消息发给它，它马上接着干。消息里只带问题编号和问题开头的几个字（如 T-012.3 "再跑一次 release_test 验证删机器吗？参…": Do — 不用了），不把整条问题再发一遍，省 token 也好读；只发编号不行，因为 session 自己并不知道编号。不勾、或者 session 不在线时，回应在它下一轮开始时送达；session 正停在一个确认或问题上（等你授权 / 等你回答）时也不会立刻发，回应下面会写明，同样在它下一轮送达。已经发出去的消息无法撤回，Undo 只会重新打开这个问题。
    一个任务有好几个 session 时：回应只送给提问的那个 session，同一任务下的其他 session 收不到，不会两边做同一件事；它们看到的"未回应的问题"里，别人问的会标注 "asked by another session on this task"。只有提问的 session 已经结束或者解绑了，回应才交给这个任务下一个开始新一轮的 session（只交给一个）。
    回答里带图片：在输入框里 Cmd+V 粘贴截图，或把图片拖到这条问题上（PNG / JPEG / GIF / WebP，≤ 20MB），下方显示缩略图（✕ 去掉）；回应时图片路径附在说明后面，Claude 会读取它。

  • 记下的（第三列）：用 记一笔 记下、还没分拣好的记录，以及最近两天分拣过的，见记一笔。
  • 去做（第二列）：所有任务里 @me 的待办，最新的在最前，每条标着已经等了多久（超过 3 天变黄，超过 7 天变红）。点方框 = 做完；点 ✕ = 不做。

  • 列表页：一眼看到每个项目在跑、在等你的任务。上面是 ◆ 项目（有终点：目标、完成标准，可以有截止日期和阶段），下面是 ↻ 职责（长期负责、时不时来活），一个一张卡：显示名、状态、目标的开头、四列各有几个任务，下面列出在等你和在跑的任务（编号 + 标题，等你的在前，最多 4 条，多的写"还有 N 个"；点一条打开它的详情侧栏，点卡片别处打开项目页）。项目卡上还有进度条（勾了几条完成标准；没写标准时按任务完成数）、截止和剩几天、归在哪个职责下（↻ 职责名）、分了几个阶段；职责卡上是本周完成数、健康标准几条、下次定期来活的时间、下面挂了几个项目（◆ N），以及每个"常见的活"一个 ＋ 名字 按钮，点一下就用这个模板建一个任务。还没定类型 一节列出 hq.json 里有、但 PROJECT.md 还没写 kind 的项目，点 ◆ 设为项目 / ↻ 设为职责 就建好 PROJECT.md。未归属 是没有项目的零散任务，下面同样列出在等你和在跑的；有没项目的任务、又有项目配了默认目录时，这一节标题旁有 按目录归属，一键把这些任务按工作目录归到对应项目（已结束的也归）。已结束（完成 / 放弃的项目）默认收起。标签上的数字是进行中的任务数。还没有任何任务时，最上面是"从已有的 session 开始"的引导，可以复制 /hq-onboard（见从已有 session 开始）。
  • 顺序：勾着 活跃的在前（⚙ 设置里，默认勾上）时，有运行中 session 的项目（绑定到它的任务，或在它的目录里干活）排在同一节的最前，按最近活动时间倒序，名字旁显示绿点和多久前；其余按你拖出的顺序；鼠标停在卡片区里时先不重排，移开后再排。拖动卡片调整顺序：项目只在项目之间、职责只在职责之间拖，以离松手处最近的卡片为准，落在它左边或右边；已结束的项目不能拖。session 列表按项目分组时也用这个顺序。
  • 筛选：顶栏的筛选框在这一页同时筛项目（按名字、标题、目标）和任务：最上面多一节 匹配的任务，列出所有匹配的任务——进行中的在前（写着它在哪一列），然后是已结束的（更早完成的、已放弃的也在），每条带项目和日期，点一条打开详情侧栏；最多列 30 条，再多就提示多输入几个字。筛选时没有匹配的项目或职责，那一节就不显示，未归属 也先收起来。
  • 项目页（点卡片进来；任务详情顶上的项目名也到这里）：顶部是面包屑（归在职责下的项目多一级职责）、显示名、状态切换（项目：进行中 / 暂停 / 完成 / 放弃；职责：进行中 / 暂停）、进度条（项目）或"进行中 · 本周完成 · 下次来活"（职责）、四列的数目、PROJECT.md（在阅读区打开）和 ＋ 新任务。左边一栏是 PROJECT.md 的内容，每节标题旁的 ✎ 就地编辑、保存回文件（✎ 平时是淡的，鼠标移到那一节上才亮）。最上面一行是 详情：只列填了的（截止、归在哪个职责下、阶段、Jira、fix version），都没填就写"都没填"；它的 ✎ 能改名字、标题和这些字段。下面分两组卡片：这个项目要做什么（职责写"这个职责管什么"）里是 目标（职责写"职责范围"，字大一点，最先读的就是它）、不管（哪些事不归它，颜色淡一些）、完成标准（职责写"健康标准"；一行一条，前面的方框直接勾，勾和取消都记进 PROJECT.md 的决策记录）；交给它的 session 里是 简报（超出一屏高度的先显示一部分，展开全部 看全文）、默认目录（家目录写成 ~；电脑上鼠标停上去看完整路径）。最底下是 删除这个项目…。改名：在 详情 的 ✎ 里改"名字"后保存——PROJECT.md 的文件夹、所有任务卡（包括已结束的）和它的定期来活都跟着改，页面跳到新名字。默认目录：点 ✎ 后每个目录后面有 ✕（点两下删），下面的输入框填一个目录（会提示 session 用过的目录）按回车或 添加。删除：没有任务时点两下就删；有任务（已结束的也算）时先选这些任务移到哪个项目或"不归项目"，再点 移走并删除，删完回到列表；PROJECT.md 的文件夹不删，移到 projects/.removed/。职责的定期来活不会跟着删，会留在定时任务页上、每次都失败，删除前会提醒，记得把它们也删掉。还没定类型的项目，这一栏是 设为项目 / 设为职责，以及名字、默认目录和删除。右边是任务：一行输入框（回车就在这个项目里建一个任务，分了阶段时旁边选阶段；更多… 打开完整的新建窗口），下面是这个项目的四列，最底下是已结束的任务：按最后一次活动的时间排，最近的在前——取决策记录（含 HISTORY.md）里最新一条带时间的记录和关闭的时刻中较晚的那个；都没有时按最后更新的日期。时间相同按编号，大的在前。显示最近 8 个，可展开全部。
  • 阶段：长一点的项目可以分阶段（在 详情 里按先后写，逗号隔开，比如 设计, 开发, 上线）。分了阶段，项目页的任务按阶段一行一行排，每行还是四列，没选阶段的在最后一行"未分阶段"。任务的阶段在详情侧栏的 编辑 里选（任务所在的项目分了阶段才有这个下拉框），选好后显示在侧栏底部的属性里；也可以 hq set 编号 phase=开发。
  • 职责怎么来活（职责页任务下面的 来活方式 一行：平时收起，只写着常见的活、定期来活各有几个、自动来活开了几个；点一下展开三个框，会按职责记住；正在编辑模板或添加定期来活时一直展开，这时点标题不会收起）：常见的活——反复会来的几类活，每类一个模板（标题可以带 {date} / {week}、目标、几条待办），点 ＋ 建 马上用它建一张写好标题、目标和待办的任务卡，✎ 编辑模板（还没有模板时会先填一份「周会准备」样例，改成你自己的再保存）。定期来活——点 ＋ 选模板和时间（每天 / 工作日 / 每周几，几点），到点自动用模板建任务（只建卡，不起 session；比如每周一 09:00 建「周会 {week}」）；它就是定时任务页里的一个 Shell job（运行 hq new --project … --template …），开关和 ✕ 在这里也能用；在看板上给职责改名，它的定期来活跟着改，模板改名或删掉了，那一行会标红（到点会失败，把模板改回来或删掉这个定期任务）。自动来活——开关记在 PROJECT.md 的 auto: 里。目前只有 GitHub 上请你 review 一个来源：打开开关，点框右上的 ✎ 写配置（存进 PROJECT.md 的 ## 自动来活 一节，第一次打开会给一份样例），之后 每 10 分钟扫描一次（定时任务页里的 Shell job「自动来活：扫描 GitHub」，跑 hq intake；打开 GitHub 开关时——或者新建职责时勾上它——会顺手打开它，这一行也能开关、立即扫描，上次扫描的结果写在下面，失败标红）。每个打开的 PR 只要请你 review（草稿不算）、又在配置的仓库里，就在这个职责下建一个任务：标题 Review 仓库#号：PR 标题，PR 链接挂在卡片上，加进 Focus。配置每行一个 键: 值：repos:（逗号分隔，* 表示任意仓库）、workdir:（session 在哪个目录跑，默认职责的第一个默认目录；写了但目录不存在会标红，也不会换到别的目录去跑）、run: yes（每建一个任务就在后台起一个 session，绑好任务，执行 prompt:；默认 no，这时任务直接等你处理）、permissions: review（这个 session 不问权限，但只能读：用 --permission-mode dontAsk 跑，只放行读文件（这台 Mac 上的任何文件都能读）、搜索、子 agent、/code-review 这一个 skill，以及对这个 PR 地址的 gh pr view / diff / checks；改文件、跑别的命令、用别的 skill、在 GitHub 上发东西都直接被拒，不会停下来问。它从不带 --dangerously-skip-permissions：PR 的标题、分支和 diff 都是请你 review 的人写的，里面可能藏着指令。以前的写法 skip 也按 review 处理。默认 ask，问权限时它会停在那里等你 Attach。repos: * 加 review 不允许：谁请你 review 都能让一个不问你的 session 跑起来）、done: manual（默认：只有你能关这个任务。session 一绑定就会被告知这一点；它写 status: done，或者在 session 里跑 hq set … status=done，都会被退回，做完了它会改成等你处理）或 auto（session 做完可以自己关）、title: / goal: / prompt:（prompt: 放最后，后面的行原样都算它的，直到下一个 ### 来源名；prompt 里不能有 ## 开头的行，那会结束整节；都可以用 {repo} {name} {number} {title} {url} {author} {branch} {base}）。默认的 prompt 让 session 用 /code-review 审，把意见写在卡上，问过你之后才发到 GitHub。同一个 PR 的任务还开着就不会再建（hq continue 接着做的新卡也算）；关掉之后，只有关掉以后 PR 又请你 review 了才再建一个。每次扫描最多建 3 个，其余的下次扫描再建。session 没起来（目录不受信任、找不到 claude……）会记在卡片的决策记录里，任务改成等你处理。职责页上 自动来活记录 列出自动建的任务：进行中的，和最近 14 天关掉的（session 自己关的会标出来），这样自动做完的也看得到。QA Hub CI 和 Jira 过滤器还不能建任务，看板上不显示（以前打开过的还会显示，好让你关掉）。职责页从上到下是：一行快速添加、它的任务、归在它下面的项目、来活方式、自动来活记录、已结束的任务。
  • ＋ 新建（顶栏右边）：一个窗口建三种东西，顶上切换 任务 / ◆ 项目 / ↻ 职责。任务：标题、目标（写进任务卡的"目标"）、归属（不选就按工作目录给默认值）、阶段（归属的项目分了阶段时）、从常见的活开始（归属是职责时：选一个模板，填好标题和目标、带上它的待办）、工作目录、绑定一个还没绑任务的 session、加进 Focus（默认勾上）；在标题里按回车或在任何地方按 ⌘回车就创建。项目：名字（短英文，也是文件夹名）、标题、目标、不管、完成标准、截止、归在哪个职责下、阶段、简报、默认目录（可不填）、先建的任务（一行一个，一起建好）。职责：名字、标题、职责范围、不管、健康标准、简报、默认目录（可不填）、常见的活、自动来活的开关。填了一半关掉，草稿会留着。

Sessions（session 列表）

  • 点底部状态栏的 session 数，右边打开所有 session 的列表（再点一下、✕ 或 Esc 关掉）。标题旁 列表 | 项目 切换视角（会记住）：列表 平铺所有 session，每张卡带项目名（蓝色）；项目 按项目分组、可折叠，顺序是你在项目与职责页拖出的顺序，勾着 活跃的在前 时最近有动静的项目在前。session 的项目：绑定了任务的跟随任务的项目，没绑定的按所在目录匹配。
  • 每张卡三行：状态点和名字，右边是 Bind…（绑定到任务；绑定后显示任务编号，点它定位任务）；项目和状态，右边三个图标；最后一条回复。
    状态文字后面是这个会话带着多少 context（如 210k · 70% ctx），和小猫列表里的一样：前面是 token 数——每一轮都要把这么多重新送给模型一次，会话越长越费 5 小时额度；百分比是相对自动 compact 门槛算的：门槛是你用 /autocompact 200k 设的值（只读用户级 ~/.claude/settings.json，项目里的设置不算；没设就是模型的整个窗口）。100% 就是门槛本身，Claude Code 通常在到达之前就会压缩。压缩完（包括你手动 /compact）、还没有新回复时，显示压缩后的估计大小，不会停在压缩前的数字：压缩记录只写了对话本身有多大，每次请求还要带上系统提示、工具定义和重新附上的文件（通常 25–55k），所以再加上上一次压缩后实际多出来的那部分（还没压缩过的会话，按它第一条回复的大小算，最多 60k）。下一条回复一到，就换成实际值。到门槛的 2/3（67%）起变色，这时小猫会提醒一次“可以 /compact 或开新会话”；80% 起变红。提醒只在会话越过 2/3 那一刻发：小猫启动或暂停恢复时已经超过的会话不提醒；压缩到门槛一半以下、再次越过时，会再提醒一次。状态点和状态文字都和小猫列表里的完全一样（状态文字如 "Working"、正在跑的命令、"1 in background"、"Answered"；圆点悬停有说明）：绿色呼吸 = 在干活；转圈的弧 = 在等它派出去的 agent；绿色带珊瑚红小角 = 在干活但最近几次调用都失败了；灰绿色带向外扩散的圈 = 这一轮结束了，但它启动的命令 / 进程还在后台跑；珊瑚红菱形 = 等你授权；橙色空心圈 = 等你回答；灰色 = 空闲；灰色虚线圈 = 那一轮被打断了（Claude Code 自己说 idle），或很久没有动静。系统开了"减少动态效果"时不动，只靠形状区分。
  • 在看板上批准：session 卡在权限确认上（珊瑚红菱形）时，它那一行会出现 Approve 框：下面是它要做的事的完整内容（整条命令、完整路径或网址、其他工具的参数），右上是 Allow / Deny。Allow 要点两下：第一下变成 Allow?，在同一个确认上再点一下才批准，6 秒内不点就取消——看板几秒刷新一次，行的位置可能变，这样点不到别人的确认上；鼠标停在 Approve 框上时看板也不会刷新。Deny 点一下就生效。和小猫弹出来的 Allow / Deny 是同一个机制：终端里的确认框照常出现，谁先回答算谁的；你在终端先答了，这边的点击就不起作用。只在小猫还挂着这个确认时显示——小猫没在运行时弹出的确认，或者已经等了将近 10 分钟（挂起时间到了）的确认，只能回终端答。同一个 session 同时有好几个确认（比如几个 subagent 一起要权限）时，按先后一个一个显示，最早的在前：在这里或小猫上答完它，或在终端里批准它的 Bash 命令，下一个马上接上来，不用等批准的命令跑完。在终端里批准的是别的工具（改文件、抓网页……），或者两个确认要跑的是同一条命令（分不清开始跑的是哪一个的）时，要等批准的那次调用跑完，下一个才接上。在终端里拒绝的会一直排在最前，直到那个 subagent 提下一个确认或这一轮结束；这期间后面的确认回终端答。
  • 后台 session（带蓝色 background 标记）没有终端：Attach（终端图标）在你选的终端里打开 claude attach，就能直接交互；停止（方块图标，点两次确认）停止它，对话保留，之后 Attach 可以继续。两轮之间可以直接发消息：看板先停掉它，再用 claude --bg --resume 带着你的消息在原目录里接着跑（id 不变，沿用看板的 skip permissions 设置）；它正在跑一轮时不能发，等这一轮结束或 Attach 进去。后台 session 一律按没有终端处理：就算起它的桌宠或 hq 是从某个终端标签页里打开的，消息也不会打进那个标签页。
  • 在看板上回答提问、批准计划：session 在终端里弹出 Claude 的提问菜单（AskUserQuestion）或计划审批（plan mode 写完计划）时，它那一行出现一个蓝边的小框：提问是 回答…，计划是 看计划…（状态文字是"等你回答"/"等你批准计划"）。点开是一个对话框：提问——每个问题列出它给的选项（可多选的会标出来），点选，或者在下面的框里自己写（单选题自己写了就以你写的为准）；每个问题都有了回答，发送回答 才能点，回答直接交给 Claude Code，和你在终端里选的一样。计划——计划全文按 Markdown 显示；批准 是在它的终端里按一次回车，选对话框的第一项（"Yes"，开始执行；Claude Code 不接受 hook 替你批准计划，所以只能按键，也只支持 Orca 和 iTerm2）；在下面的框里写要改什么，点 继续规划，就像终端里的"Tell Claude what to change"：它留在 plan mode 改计划，再拿来给你批。终端那边的对话框同时开着，哪边先答算哪边；在终端里答了，看板上的对话框会自己关掉。只在小猫开着时才有（和 允许/拒绝 一样，是小猫的 hook 在替你等着）。
  • 中断这一轮（Esc）：Orca 或 iTerm2 里正在干活的 session，一行里（👁 和 ↗ 之间）多一个 Esc 按钮：点一下，就在它的终端里按一次 Esc，和你自己在终端里按一样——这一轮马上停下，session 还开着，对话也在，接着在消息框里告诉它改做什么就行。只在它正在干活时才有（空闲时按 Esc 没用，连按两次还会打开 Claude Code 的回退菜单）；点过之后按钮先藏起来约 12 秒，等小猫看到这一轮已经停下，所以不会连按。Terminal 的 do script 总会多带一个回车，所以 Terminal 里的 session 没有这个按钮，请 ↗ 跳过去按。
  • 停止终端里的 session：终端里的 session 一行也有 停止（方块图标，点两次确认）：结束它的 Claude Code 进程，对话保留。看板开的标签页随之关闭（看板启动命令末尾带 ; exit 0，session 一结束 shell 就退出——Stop、/exit、连按两次 Ctrl-C 都一样），标签页不会越积越多；之后 ↻ Resume 新开一个。Orca 和 iTerm2 默认就会关；Terminal 要在 设置 → 描述文件 → Shell 里把 shell 退出时 设成 如果 shell 完全退出则关闭。你自己在终端里起的 session 停掉后标签页仍留在 shell 提示符，Resume 会优先回到这个标签页。在看板上把任务状态改成 done 或 abandoned、它还有 session 在跑时，会弹窗问要不要一起停掉（列出这些 session；对话保留，之后可以 Resume）。勾上 记住我的选择 以后就不再问，按记住的做；在 设置 → Sessions → 结束任务时 可以改回 每次问 / 停掉它的 session / 不停。按 Esc 或点窗外 = 这次不停，也不记住。session 自己在 hq-update 里把任务改成 done 或 abandoned 也一样处理：等它这一轮回复完（它起的后台任务也跑完），按同一个设置弹窗问、直接停掉或不停。但如果卡上还有没答的问题（常见的是同一条回复里最后问一句“要不要删掉旧 worktree？”），任务先不关：它停在「等你」，详情里写着 session 已经说做完了；你回答后，要等提问的那个 session 收到回答、处理完那一轮，才标为完成，再按上面的设置处理 session，免得你答了“可以”而 session 已经被停掉。它在忙别的事的那一轮、或这个任务的其他 session 一轮结束，都不会把任务关掉。如果答的是“不用”而那个 session 已经不在了，就直接关（之前答过的“可以”还没送到它的话除外）。本来已经完成的任务，不会为此重新打开。期间你自己改了状态，就以你改的为准。之后你只要又给它发了消息，就不再算数，不会把你正在聊的 session 停掉；看板没开时，10 分钟内打开看板仍会处理，更早的只显示下面的黄色提示条。这种自动弹出的窗口，默认选中的是 不停，免得你正在别处打字时一个回车把 session 停了；设成直接停掉时，这个任务的其他 session 若正在干活或在等你回答，也不去动它们。同时有几个任务这样结束时，一个一个问。用 hq set 结束的任务不会弹窗。任务已完成还有 session 在跑：这个任务的卡片顶上会出现黄色提示条，全部停止（点两次）把它们全部停掉；session 列表顶上也会汇总所有挂在已完成任务上的 session，全部停止 一次停完。

  • 消息：点 Send 或按 ⌘回车（Ctrl+回车也行）发送，回车只是换行；秘书的对话框、计划下面的 继续规划、日志的 保存备注、问题的回答框也一样可以用 ⌘回车；粘贴或用语音输入（如 Typeless）一次性塞进来的文字，换行会统一成普通换行，连续的空行最多留一行、只有空格的行也算空行（以前一个段落间隔会变成四五个空行）——文字落进框里之后再整理一遍，所以就算粘贴事件没报全换行也能收住；你自己敲的换行不动，Cmd-Z 照样能撤销；点了发送，输入框马上清空，消息先出现在对话下面的发件区里，在后台一条一条地发出去（同一个 session 一次只打一条进终端，免得几条混在一起），所以你打完一点发送就可以不管了：发件区里依次显示 等待发送 / 发送中… / 已送达（它在忙时是 已送达，排队等这一轮结束），等对话里出现这条消息后它就从发件区消失。发不出去时分两种：没发出去（红色：session 已经结束、终端标签页没了、它正停在确认上……）可以 重发、放回输入框 改一改，或 删除（提示里能撤销）；可能没提交（黄色：文字已经打进终端，但 5 秒内没看到它开始新的一轮，或者终端 45 秒都没回应）不会自动重发，免得它收到两遍——点 跳转 去终端看一眼，有的话点 已收到，没有再 重发。有红色或黄色的消息时，后面的消息先等着，不会越过它；等着的消息也能 放回输入框 或 删除，放回输入框时它后面等着的几条会一起放回（顺序不变），免得改完重发时被后面的抢先。后台 session 要等它这一轮结束才发下一条。在侧栏的 session 行上点 放回输入框 会打开它的 Peek 窗口。这个 session 在侧栏、任务卡和 session 列表里会多一个红点或黄点，关掉对话窗也看得到。宠物退出时还没发出去的消息会留着（最多一周），下次打开看板时标成没发出去（正在发的那条标成可能没提交；秘书的标成没发出去），不会自己再发。效果和你在终端里亲手输入完全一样。斜杠命令：框里第一个字打 / 会弹出命令列表——这个 session 自己能用的 skill（取自 Claude Code 写在对话记录里的那份清单，所以每个项目、每套插件各不相同，不靠猜；标了 disable-model-invocation: true 的 skill 和 command 不在那份清单里——它只列 Claude 自己能调用的——但你照样能输入，所以会另外从 ~/.claude、项目的 .claude（session 所在文件夹及上层文件夹，到你的主目录为止）和对这个项目启用的插件（项目设置里关掉的不算）里找出来补上，比如你自己装的 /grill-me 这类），外加内置的 /compact、/clear、/model（换模型，后面要接模型名，如 /model opus、/model sonnet；不带名字会在终端里打开菜单，看板不会发，会提示你补上）。接着打字按名字筛选（打满三个字也搜说明），↑↓ 选择，Tab 或回车填入 /名字 （后面可以接着写参数），也可以直接用鼠标点。只靠说明匹配上的结果不会预先选中，要先按 ↑↓ 选一条，Tab/回车才会填；否则回车照常换行。按 Esc 关掉后，看板刷新也不会再弹出来，直到你再打字。带 Cmd、Ctrl、Option 或 Shift 的组合键（如 Shift+Tab、Cmd+回车）不归列表管，保持原来的作用。选中只是填进框里，还是要点 Send 才发。/config、/resume 这类会在终端里打开菜单的命令不在列表里；/context、/cost 这类结果只显示在终端里、Peek 看不到的命令也不在。session 还没列出过 skill 时，只有这三个内置命令；如果列表底部提示"读不到这个 session 的 skill"，多半是 hq 命令行没更新，跑一下 hq/install.sh --yes。快捷短语：常发的回复（「继续」「合并了，安装吧」……）存在 设置 → 快捷短语 里，这台 Mac 和配对的手机共用一份。光标进到 session 的消息框（侧栏、对话窗口、秘书）或问题的回答框时，框的上方浮出一排短语（浮在上面、不挤动页面），点一下就插到光标处——框里已经有字时接在后面、隔一个空格——不会直接发出，还要点 Send（或 ⌘回车）；点的时候光标留在框里，手机键盘也不会收起来。最后那个 ✎（还没有短语时是 ＋ 常用短语）打开设置里的短语列表。用键盘的话，在框的开头或空格后面打 ;（中文的 ； 也行）会弹出短语列表，接着打几个字筛选（只打了 ;   • 回复模板：回复里有两种代码块不当代码显示，而是由看板画出来（模型只给内容，HTML 由看板自己生成，模型写的 HTML 一律当文字显示）。```diff（或 ```patch）画成 GitHub 那样的文件对比：每个文件一个框，标题是文件名（可以点开）和 +/− 行数，左边两列是旧、新行号，删掉的行红底、加的行绿底，一对改动行里变了的字再加深；连续 8 行以上没改的折成一行"展开 N 行未改动"，点一下展开。```draft 画成一张消息草稿：开头几行 to:（发给谁）、via:（Zulip、邮件……）、subject:、cc:（中文写 收件人 / 渠道 / 主题 / 抄送 也行），空一行后是正文；复制 只复制正文。秘书改记忆文件、起草消息时就用这两种块；任何 session 的回复、任务卡和阅读区里的文档也都按同样的方式画。
  • Claude 回复里的 hq-asks / hq-resolved / hq-update 块显示成"Asked you"/"Answers recorded"/"Card updated"列表，里面的链接可以点。"Asked you"一直展开；"Answers recorded"和"Card updated"只是记账，默认折叠成一行（写着记了几条回答、改了卡片的哪些字段，比如 state ×2 · log），点一下展开，再点收起，看板刷新也保持；普通代码块里的网址也可以点。
  • 底部可以直接回复，发出后窗口停在最下面；你往上翻着看时，新消息进来，你正在看的那条消息原地不动。已经结束的 session 只能看历史。

定时任务（Scheduled）

顶栏的 定时任务 / Scheduled 标签页：按时间表跑一段 Claude prompt 或一条 Shell 命令，并且能看到一共有几个任务、每次跑得怎么样。这一页的文字有中英文两版，跟随右键 Settings → Language · 语言 的设置。

  • 谁在跑：每个打开的任务对应一个 macOS LaunchAgent（~/Library/LaunchAgents/local.claudepet.job.<id>.plist），到点由 launchd 启动 ~/.claude/pet/pet-emit --run-job <id>。所以猫关着也照跑；Mac 睡着时错过的那次，醒来后补跑一次（错过多次也只补一次）。第一次加任务时 macOS 可能提示"已添加后台项目"，这是正常的。
  • 从模板开始：还没有任务时，这一页列出三个模板——每天早上汇总昨晚的 CI（Claude · 每个工作日 09:00）、每小时看 PR 有没有新评论（Claude · 每小时）、每周清一次缓存（Shell · 每周日 03:00）。点一个就打开填好名称、类型、prompt 或命令和时间的新建表单，改一改再保存。
  • 新建 / 编辑：右上角 新建定时任务。表单是一页"左边问题、右边答案"：做什么（顶部切换 Claude prompt / Shell 命令，再填名称和 prompt 或命令）、在哪跑（工作目录，从这里启动，会读这里的 CLAUDE.md；选择… 打开文件夹选择框）、什么时候跑、能做什么（只有 Claude 任务有）、跑完告诉我（连同"开着"开关）、更多（模型、单次最长、额度保护、session 怎么续，写成几句话，空格里直接改）。底部一直停着 取消 / 保存并立即跑一次 / 保存。
    • Prompt 每次原样发给 claude -p。和终端里一样，开头写 /技能名 参数 就调用那个技能；不写也行，Claude 会按描述自己挑。你的 MCP 服务器、插件、hooks 照常加载。
    • 命令 用你的登录 shell 跑（zsh -lic），PATH 和终端里一样。Shell 任务能在 Mac 上跑任何命令，所以只能在 Mac 的看板上新建和修改：手机上的表单只有 Claude prompt，模板只列 Claude 的，Shell 任务没有 编辑，但照样可以开关、立即跑、停止和删除。
    • 能做什么（权限）：跑的时候没人点"允许"，所以先选好——只用已允许的（默认；只用你在设置里已允许的，其他一律拒绝并记在运行结果里）、还能改文件（acceptEdits）、全部允许（跳过所有权限检查，只给完全信任的 prompt 用）。
    • Session（在"更多"里）：每次开新 session（默认，干净、便宜；只保留最近 N 次运行的 session，更早的从 ~/.claude/projects 删掉，填 1 就只留最新一次）或 每次接着同一个 session（claude -p --resume，适合需要记住上次的任务；上下文用到设定的百分比（默认 50%，按模型的上下文窗口算）时先 /compact；列表里会显示这个 session 现在用了多少上下文）。注意：Claude Code 的 /clear 本身就是开新 session，所以"同一个 session 里先清空再跑"等于"每次新开、只保留 1 次"。
    • 单次最长：超时就停掉整组进程。
    • 额度保护：每次跑之前看一眼订阅额度，周额度或 5 小时额度已经用到设定的百分比（默认都是 90%，0 = 不检查）就跳过这次，记成"跳过——周额度已用 94%"，把剩下的额度留给你自己用。额度读数来自猫已有的读数（状态栏）和上一次任务运行时 Claude 报告的额度，取其中较高、且所在窗口还没重置的那个。
    • 什么时候跑：写成一句话，空格里直接选，比如"[每个工作日] 的 [09:00] 跑一次"。可选每个工作日、每天、每周（点选周几）、每小时、每隔几分钟，或 cron 表达式（分 时 日 月 周，支持 */15、1-5、MON）。下面用小标签实时列出接下来 3 次的时间；写错了会直接告诉你哪里不对。
    • 跑完告诉我：失败时（默认）、每次跑完、不提醒。旁边的开关决定保存后任务是否开着。
    保存并立即跑一次 保存后马上跑一次，方便试。
  • 列表：标题旁是一共几个、几个开着（有在跑或最近失败的也会写出来）。每个任务一行，行与行之间只有细线：名称和类型标签（Claude / Shell），下面一行淡色写 prompt 或命令 · 工作目录；时间（人话，如"每个工作日 09:00"），下面是"下次 …"或"已暂停"；最近 12 次运行的小竖条（绿 = 成功，越高跑得越久；红 = 失败 / 超时 / 中断，满格；黄 = 成功但有工具被拒绝；蓝 = 运行中；灰色矮条 = 跳过或停止），下面是上次的时间、结果和耗时（失败时标红）；上次用掉的额度（Claude 任务；接着同一个 session 时还有 session 上下文）；开关、立即运行（运行中变成 停止）、编辑、删除（点两下）。关掉的任务名称和时间变淡。最近一次失败时，整行下面摊开一块淡红底的输出最后几行。窗口窄时"用掉的额度"一栏收起。
  • 运行历史：点任务名称展开，列出最近 30 次：开始时间（手动跑的带"手动"标记）、结果、耗时、用掉的额度（这次运行前后周额度、5 小时额度各涨了多少，例如"周 +1%"；不到 1% 时显示"不到周额度的 1%"；悬停能看到按 API 价格折算的美元）、摘要（回复的第一行，或命令输出的最后一行）。上一次还没跑完时到点的那次会记成"跳过"，不会两次抢同一个 session。例外是接着同一个 session、在固定时间跑的任务（比如秘书的定时报告）：它会先等上一次跑完，最多等 10 分钟，等不到才记成跳过。
  • 详情：一次运行的输入、Claude 的回复（Markdown 排版）或命令的输出、"过程"（每次工具调用和结果，被拒绝的标红）和日志。对话 打开这次运行的完整 session 记录（和看 session 一样）；接着聊 在终端里 claude --resume 这个 session（勾了 stay on board 就留在看板上聊）。
  • 和小猫：定时跑的 Claude session 不会出现在小猫和看板的 session 列表里，也不会让猫举手等你批准（hook 看到 CLAUDE_PET_JOB 就不管它）。任务失败时小猫上方弹出"Scheduled job failed: …"，点一下打开这一页；没看过的失败计入角标，并列在小猫列表的 Scheduled 分组里（运行中的也在这里）。打开这一页就算看过。
  • 文件：每个任务一个目录 ~/.claude/pet/jobs/<id>/：job.json（设置）、runs.jsonl（每次开始、结束各一行，保留最近 100 次）、state.json（接着同一个 session 时的 session id 等）、logs/（每次运行的输出；Claude 任务另有 stream-json 记录）。卸载 Claude Pet 会关掉所有任务的 LaunchAgent，但保留这些文件。
  • 读不到文件夹？如果任务要读 ~/Documents、桌面等受保护的位置而失败，到"系统设置 → 隐私与安全性"给 pet-emit 授权（"文件与文件夹"或"完全磁盘访问权限"）。

阅读区

看板上任何指向本地 Markdown 或文本文件（.md、.markdown、.txt）的链接，都在看板右边的阅读区打开，不跳到别的 App：对话里的文件路径、任务卡和 PROJECT.md 的 打开任务卡 / PROJECT.md、秘书的记忆文件和报告。

  • 多个文档，一个一个标签：每个文件一个标签，点标签切换；同一个文件只开一次，再点它的链接就切到那个标签。标签一直留着，要你自己关：标签上的 ✕，或者鼠标中键点标签。看板重新加载、下次打开，开着的标签都还在。
  • 看板让出位置：阅读区占右边一栏，看板、任务详情侧栏、对话窗口和秘书窗口都挪到它左边，所以可以一边聊一边看文档。秘书窗口变窄时右栏收起，"替你盯着"挪到对话上面一行。拖阅读区的左边缘调宽度（记住）；右上角的 › 把阅读区收成窗口右边的一个小标签（📄 和开着的文档数），文档不关，点它再展开。在阅读区里点过之后按 Esc 不会关掉左边的窗口。
  • 文档里的链接：指向别的 .md / .txt 的相对链接在当前标签里打开，用 ‹ › 前进后退；按住 ⌘ 点开在新标签里。网页链接用浏览器打开，#标题 跳到文档里的那一节，其他文件用默认程序打开。图片显示成一个链接，点开用默认程序看。
  • 修改：阅读区只读。用编辑器打开 用默认程序打开这个文件去改；阅读区每 3 秒看一次文件，改过就重新显示，滚动位置不变（选着文字时不刷新）。复制路径 复制完整路径。
  • 怎么显示：Markdown 用 markdown-it（开源，MIT） 解析（标题、列表、勾选框、表格、引用、代码块），文件开头的 YAML 头（比如任务卡的 frontmatter）显示成一张小表，HTML 注释显示成一块灰字说明，其他 HTML 当文字显示，不会执行。代码块里的 ```diff、```draft 按回复模板画。.txt 原样显示，网址可以点。超过 4 MB 的文件不显示。

秘书

顶栏的 秘书 打开一个常驻的对话窗口，对面是一个了解这个看板的 Claude。可以问它"T-072 和 T-071 怎么样了、卡点是什么""有什么在等我""哪些看着卡住了"。它每次都先现查任务卡和 session（hq status、hq asks、hq board……）再回答，像同事那样用几句话说清楚：先说结论，再说要紧的细节，等你的事直说（"从周一起就在等你"），不念步骤、少用编号列表。它只管"信息 → 看板 → 你的注意力"这条线，自己不干活：要做的事，它会告诉你属于哪个任务，你在那个任务上点 ▶ 新开 session。

  • 第一次：点 秘书 会先列出要创建哪些东西，点 设置 才真正创建。已有的文件一律保留，不会覆盖。会创建：任务根目录下的 .claude/agents/secretary.md（它的身份和规矩，可以直接改）；记忆文件 secretary/profile.md、people.md、playbooks.md；它自己的任务卡"秘书"；定时任务 页里的任务"秘书"（时间表是工作日 18:30 写报告，先关着，见下面的报告）。
  • 顶栏按钮上是你当前形象（⚙ 里选的猫或修士）的脸。它在回复时脸外有一圈呼吸的光环；一个多小时没说话，换成睡着的样子；右上角的数字是它还在等你回答的建议有几条。
  • 对话窗口像和一个人聊天，不是普通 session 的 Peek：
    • 每一轮只显示你说的话和它最后的回复，中间的工具调用和过程输出都不显示。它干活时，对话里显示它的脸和跳动的三个点，下面一行写它正在做什么（"在看看板…""在翻任务卡…""在写回复…"）。
    • 标题栏是它的脸、名字和状态：在、正在做什么、在休息（多久前回过话），上一条失败或因为额度被跳过时写明原因。
    • 定时运行、点了"现在写一份"、在看板上回答了它的建议，这些不是你打的字，显示成居中的一行小字（"定时：写今天该写的报告""你回应了它的建议"）。两轮之间隔了半小时以上，中间标出时间。
    • 输入框上方是常用问题（"有什么在等我？""哪些看着卡住了？""今天做了什么？""帮我起草消息"），点一下直接发出，"帮我起草消息"只填进输入框。它回复期间，发送按钮旁边多一个 停止；这时也可以继续发，消息先在对话下面的发件区里等着（标着 它回完就发），它回完一条就发下一条。悬停在它的回复上可以 复制；⋯ 菜单里有 复制整段对话。这里没有斜杠命令。
  • 始终是同一个 session：每条消息都接着上一次的对话（--resume）。上下文超过任务设的阈值（默认 50%）时先 compact；周额度或 5 小时额度用到设定的比例（默认 90%）时跳过，不会把额度用光。这两项和模型、单次最长时间一样，在 定时任务 页编辑"秘书"就能改；它的时间表就是定时报告的时间，也在那里改。定时运行如果碰上它正在回复，会等这一轮结束（最多 10 分钟）再开始，不会跳过。工作目录、agent、"接着同一个 session"和允许的工具是秘书离不开的设置，改了也会在下次发消息时改回来。
  • 它能做什么：它在后台跑，没人在旁边批准，所以只预先允许三样：读文件（Read / Grep / Glob）、运行 ~/.claude/hq/bin/hq、改 secretary/ 下的文件。其他操作都会被拒绝，除非你在 Claude Code 设置里另外允许了。外部系统它只读；消息和邮件只起草，写在回复里。
  • 窗口：左边是对话，右边一栏是一张张卡片，每张带图标，点标题收起或展开（看板记住你的选择）。上面是要你看的：替你盯着（每条一张小卡，开头的任务编号可以点，打开那个任务；文字超过两行时点一下看全文）和 待回应（有建议在等你时才出现，可以直接点 可以 / 不要；要写说明就在对话里的建议卡片上写），默认展开。下面是 报告和设置，默认收起，收起时标题后面显示一行摘要：报告（摘要是最新一份，✎ 让它现在写一份，展开是最近几份，点一下在阅读区打开）、自动做的事（摘要是三个小圆点，亮的是开着的，红的是上次没跑成；展开是 傍晚写报告、扫 Zulip · Jira、自动勾完成的待办 三行，每行一个开关，后两行有 ↻ 现在跑一次；你在定时任务里给秘书写了自己的 prompt 时，第一行写着 在跑你自己的 prompt，打开它的开关会改成傍晚写报告、替换掉那个 prompt，上次跑的结果和红点都在 ↻ 的悬停提示里，多久跑一次和具体做什么在名字的悬停提示里）、它记得的（几个记忆文件，点一下在阅读区打开）。这些和标题栏 📄、⋯ 菜单里的是同一批东西；窗口窄于 900px 时右栏收起，这些都还在菜单里。
  • 它的建议，在它的窗口里或 Needs you 里回答：建任务、给任务记一笔、加待办（比如 @me 把回复发给 Atul）、关任务、改它的记忆，都会作为建议卡片出现在对话里，紧跟在提出它的那条回复下面（不在哪条回复里的，列在对话最后"这些还在等你回应"下面），同时也出现在 Needs you，标着绿色的 秘书，点它打开秘书窗口。两边是同一批问题，在哪边回答都行。在它的窗口里点 Yes、No 或 Later，在 Needs you 里和别的问题一样用输入框回答（留空就是 Yes，✕ 是 No，⋯ 里有稍后），都可以附说明，说明会修改或替换它的建议；回答过的卡片留在对话里，写着你的回答。点了 Yes，它大约 10 秒后自己醒来照做（比撤销按钮在的时间长，点了 撤销 它就不做），每条做完用一行汇报，打开秘书窗口就能看到；它要是正在回复，就等这一轮结束再做。点了 No 它就不做，没有新情况也不会再提。点 转待办 表示这件事你自己做：它变成你的 @me 待办，秘书不会去做。

session 和看板怎么联动

session 绑定任务后，三个 hook 会让它遵守下面的规则：

  1. 先读卡，再干活，干完写回：状态、下一步、待办、日志都写回任务卡。session 不再一条条跑 hq log / hq set 这些命令，而是在回复末尾写一个 hq-update 块，由 Stop hook 写进卡片。每多一次工具调用就要把整段对话再读一遍，这样能省掉这部分 token。只认回复末尾的那个块——正文中间引用或举例的块不算，模板里 <…> 这样的占位行也不算；不过回复里只有一个 hq-update、后面却还有文字时，它不会被悄悄跳过，而是退回给 session，让它放到最后再发一次。块里只要有一行写不进去（状态拼错、找不到那条待办、待办有歧义……），整块都不写，退回给 session 改一次（会列出候选待办）；所以重发整块不会重复添加。同一条待办、日志、ref 已经有了就不再加。冒号用全角也行。一轮干了两分钟以上却没动任务卡，会被提醒一次去更新。 
    ```hq-update
status: blocked
next: 等 infra 给 token
state: 构建已通过，等 token
todo: @me 发 token 申请
done: 重跑测试
change: 合并 #12 => 合并 #12、#13
log: 选方案 v2，因为更便宜
ref: PR #9 https://github.com/…/pull/9
```
    只写变了的行；todo / done / drop / log / ref / workdir 可以写多行；state 会替换卡片的"当前状态"一节；done / drop / change 按待办的文字匹配；change: 原文 => 新文字 原地改写一条没做完的待办（位置、谁来做、创建时间都不变，HISTORY.md 里记一笔）；ref: 记的如果是某次构建、run 或某条评论，写进 HISTORY.md 而不是卡片，要卡片留住就写 ref!:；project: 名字 把任务移到已有的项目（没有这个项目就整块退回——项目只能由你建）。什么都没变就只写一行 touch。
  2. 需要你确认的事会被记下来：session 把问题放在回复末尾一个 hq-asks 块里，每行一件事。它们会变成看板上的 ask（编号如 T-012.3）。只有顶格的 - 或 1. 开头的行才算一个新问题；下面缩进的行（比如 a) b) 选项）都归上面那个问题。几个 session 同时提问也不会撞号、丢问题。 
    ```hq-asks
- 方案 v2 可以吗？
- 索引用哪种？
  a) btree
  b) hash
```
  3. 没回应的问题不会被当成"不做"：每一轮都会把还没回应的 ask 重新提醒给 session。
  4. session 记得卡上的待办：绑定了任务的 session 每次启动（新开、resume、/clear、compact 之后）都会收到卡上没做完的待办，你的（@me）在前，Claude 的在后（各自原文照抄，最多 20 条、约 2000 字，更早的只说省略了几条）。Claude 的，它要对照现状，在下一个 hq-update 里用 done: 勾掉做完的、用 drop: 去掉过时的；你的，它看到做完了（比如它刚替你装好）就勾掉，事情有变化时用 change: 改写那一条，不再加一条新的。只在启动时给一次（从看板绑定的 session 在绑定后的第一条消息里也给一次），不会每轮都塞进去；要它中途再核对一遍，用待办旁边的 整理待办。
  5. 你的待办不重复：规则要求 session 一条 @me 待办只写一件你能一次做完的事——要 review 和合并的 PR 合成一条，安装另起一条；Claude 的待办只记这一轮做不完、要等别的事（CI、合并、你）的活，正在做的不记。session 新加的 @me 待办和一条没做完的重复时，整块退回给它，附上那条的原文，让它用 change: 改写那条，或在同一块里先 done: / drop: 掉。算重复的有三种：两条都是"从 main 安装"；两条都是 review / 合并、又提到同一个 PR；提到的编号完全相同、文字几乎一样。措辞像但 PR 号不同（"合并 #110"和"合并 #111"）不算。确实是另一件事时，session 写 todo!: 照样加。你在看板上或用 hq addtodo 加的不检查。PR 合并后自动勾掉待办见完成的待办。
  6. session 知道任务属于哪条工作线：任务所在的项目有 PROJECT.md 时，绑定的 session 每次启动（新开、resume、/clear、compact 之后，以及 hq bind）都会收到一段项目说明：属于哪个项目、是目标还是长期职责、截止时间、目标的第一行，再加上 简报 全文（最多 2000 字，超出的部分截掉，提示它去读 PROJECT.md）。简报是空的就什么都不说。不管 session 在哪个仓库里干活都一样。之后只在这段说明变了（改了简报、标题、类型、状态、截止时间或目标第一行，或者任务换了项目）时，在下一条消息里再给一次；简报没了也会告诉它之前那段不再适用。
  7. 两边都能回应：
    • 在看板上点按钮 → session 下一轮收到"用户在看板上回应了 …"；
    • 在 session 里直接回答 → session 用 hq-resolved 块记下来，看板上那条随之关闭。你说"以后再说"时它写 later：和看板上的 稍后 一样，问题留着、藏到明天；later until 2026-12-05: 等 Ping 回来 就藏到那天，看板上那行写"12月5日回来"，问题下面写为什么推迟。读不懂的行、编号不存在的行、推迟一个已经回答了的问题，都不会被悄悄扔掉，会退回给 session 改。
  8. 草稿不等于完成：session 替你起草、需要你去发的东西，会变成一条 @me 待办，直到你勾掉。

什么时候用哪边：要看全局、批量处理问题、改状态，用看板；跟某个 session 深入讨论，在它的终端里直接聊，绑定之后它说的、问的同样会出现在看板上。

从已有 session 开始

刚装好时，本机通常已经有很多 Claude Code session 和历史对话。在任意 Claude Code session 里输入 /hq-onboard（看板为空时，项目与职责 页的引导里有个按钮可以复制它），Claude 会把它们变成看板：

  1. 读 session、起草任务：扫描最近 60 天的对话（/hq-onboard 30 改天数），读每个 session 在干什么，一件事一个任务（几个 session 做同一件事就合成一个，一次性问答不建任务），带上状态、下一步、现状、待办、相关链接和置信度。每条待办都要写明谁做（@me 你、@claude session、或某个人的名字），没写的 hq import 会退回——不然它既不在 Needs you 里，也不归任何 session。已经绑定了任务的 session 跳过。
  2. 归到工作线：项目是一条工作线，不是一个目录——一个仓库里常有好几条，所以按任务在做什么归：能放进已有项目的就放进去，新的就起草成职责（长期负责）或项目（有终点，可以归在某个职责下），写上一句话目标；只有整个仓库都属于它时才配默认目录。
  3. 给你确认：先列工作线，再按工作线列任务，确认之前不会创建任何东西。可以改名、合并、改归属、删掉；拿不准是职责还是项目的会问你。
  4. 一次写入：确认后 Claude 把整个方案写成一个 JSON，用 hq import 文件 --dry-run 检查并预览，没问题再 hq import 文件 一次建完：项目带 PROJECT.md（类型、目标、上级职责），任务卡带状态、待办和链接；正在运行的 session 绑定到对应任务，已结束的记在任务卡上、可以在看板上查看历史。方案里有任何一处不对（名字重复、session 已经属于别的任务……），整份都不写，并列出每个问题。

之后任何地方都能改：在看板上直接改，或者在 session 里让 Claude 改。从对话推断出来的状态在任务日志里写了"请核实"。

项目

  • 项目是一条工作线，不是一个目录：要么是有终点的目标（kind: goal，比如"发布 hq-v2"），要么是长期职责（kind: duty，比如"客户 RCA""Release 回归测试"）。一个任务只属于一个项目。目录（仓库）只是任务的属性（工作目录），用来开 session、Resume、匹配 session。
  • PROJECT.md：每个项目一个 <任务根目录>/projects/<名字>/PROJECT.md。frontmatter 是 title（显示名）、kind（goal / duty）、status（active / paused / done / abandoned）、due（截止日期，目标才有）、parent（目标可以归在某个职责下）、phases（目标的阶段，按先后）、auto（职责的自动来活开关：github-review，配置在 自动来活 一节；qahub-ci、jira-filter 也认，但还不会建任务）、jira（关联 epic）、fixVersions；正文几节：目标（职责写"职责范围"）、不管（Out of scope）、完成标准（职责的标题是 健康标准 / Healthy when；一行一条 - ，达成的写 - [x] ）、常见的活（Templates：每个模板一个 ### 名字，下面 title:、goal:、- [ ] @owner 待办）、自动来活（Auto intake：每个来源一个 ### github-review，下面 键: 值，见上面的"职责怎么来活"）、简报（交给这个项目每个任务的 session：背景、约定、常用命令、要避开的坑）、决策记录。标题中英文都认（## 目标、## Goal、## 目标 / Goal…）；每节一直到下一个这几种标题为止，简报里自己加的 ## 常用命令 之类的小标题算在简报里。职责的状态只有 active / paused。名字只差大小写的两个项目不允许（macOS 上会是同一个文件夹）。name 用短英文 id（命令行和卡片 project: 用它），显示名放 title。没有 PROJECT.md 的项目照样能用，只是没有类型、目标和简报。
  • 目录只是默认建议：hq.json 里还是记着项目的名字、顺序和目录；新建任务或绑定 session 时，任务还没有项目就按目录给一个默认值（目录嵌套时取最深的）。只给专属某个项目的仓库配目录；几个项目共用的仓库不配，在那里新建的任务先归到"无项目"，再手动分。之后可以在任务详情里改，session 也可以用 hq-update 的 project: 改。
  • 在看板上管理：全在项目与职责页——＋ 新项目 / ＋ 新职责 新建（可以顺带填一个默认目录），拖卡片调整顺序，项目页侧栏里改名、增删默认目录、删除，列表页的 按目录归属。从已有 session 建项目见从已有 session 开始。
  • 命令行：hq project list | show 名字 | brief 名字 | add 名字 [--kind goal|duty] [--title 显示名] [--due 日期] [--parent 职责] [--path 目录] | set 名字 kind=… status=… due=… title=… parent=… phases=A,B auto=… jira=A,B fixVersions=… | section 名字 goal|out|done_when|templates|brief [文字] | check 名字 N [done|open] | paths 名字 目录… | rename 旧 新 | remove 名字 --to 其他 | auto | order 名字…。list 带上每个项目的进行中、已完成和等你的数目；show 显示内容和任务统计（进行中、已完成、最近 7 天完成、等你的）；brief 打印 session 实际会收到的那段文字。section 改写 PROJECT.md 的一节（不给文字就从标准输入读），check 勾上（或取消）第 N 条完成标准并记进决策记录；也可以直接编辑 PROJECT.md，或在项目页里点 ✎。只有目标能归在职责下；职责下面还挂着项目时不能改成目标，改名或删掉职责时，下面的项目跟着改挂或不再归属。

在手机上用看板

手机或 iPad 和 Mac 连着同一个 Wi-Fi 时，可以在手机浏览器里打开这个看板，用法和 Mac 上一样：回答问题、勾待办、看对话和回复 session、批准权限请求和计划、开新 session 或 Resume。数据都在 Mac 上，手机只是另一个窗口。

  • 打开：在 Mac 的看板里点 设置（⚙）→ 手机访问，勾上在手机上打开看板。宠物（Claude Pet）会在局域网上开一个小网页服务（默认端口 8790），下面列出手机能用的地址（VPN 的地址不列）。第一次打开时 macOS 防火墙可能会问「是否允许 ClaudePet 接受传入的网络连接」，要选允许；每次重新安装宠物后可能会再问一次。如果手机连不上，先看这一步。
  • 配对：点配对手机，会出现一个二维码和一个 8 位的配对码（比如 K7QM-3XPA）。用手机相机扫二维码，在 Safari 里打开就配对好了。一个码只能用一次，15 分钟内不用就失效：手机用它的那一刻，Mac 会给这台手机换一个它自己的 token，这个码随即作废，被别人看到也没用。
  • 添加到主屏幕：在 Safari 里点 分享 → 添加到主屏幕，看板就像一个 App 一样全屏打开。全屏时页面延伸到状态栏下面，iOS 会把状态栏那一条（比状态栏本身略宽一点）做成模糊效果；看板的顶栏在 iPhone 和 iPad 上都让到这条模糊带下面，标签页不会被它盖住。iOS 给主屏幕上的 App 单独一份存储，Safari 里的配对不一定带得过去；App 里出现配对页时，在 Mac 上再点一次配对手机，把 8 位配对码输进去就行（大小写、横线都无所谓）。扫码总是打开 Safari，配对不了主屏幕 App。也可以跳过 Safari：直接在 Safari 里打开设置里列出的地址，先添加到主屏幕，再在 App 里输码配对。
  • 出门在外：通过 Tailscale：Mac 和手机都装了 Tailscale、登录同一个账号时，在 设置 → 手机访问 里再勾上也通过 Tailscale 访问。下面会出现一个 Tailscale 地址（http://你的Mac名.xxx.ts.net:8790），点用 Tailscale 配对，按上面的方法配对一次：iPhone 把不同的地址当成不同的网站，局域网地址上的配对带不过来，主屏幕上也要为这个地址另加一个图标。手机开着 Tailscale 时，这个地址在家和在外面都能用（在家时 Tailscale 会自己走局域网直连），所以以后只留这一个图标就够了。
    • 只放进和这台 Mac 登录同一个 Tailscale 用户的设备：每个连进来的设备，宠物都先用 tailscale whois 问清楚是谁的，别人的设备、带标签的服务器和网关一个字节都不读。公司的 tailnet 谁能连到你的 Mac 由管理员的规则决定，所以多了这一道；配对码和 token 照样要。
    • Tailscale 一路用 WireGuard 加密，局域网那种「同一个 Wi-Fi 能抓包」的问题在这里没有。
    • 第一次打开可能要等很久：手机和 Mac 打不通直连时，Tailscale 会绕道它的中继服务器，有时在半个地球之外。页面文件会压缩着传，手机会缓存起来，之后再打开就快了；看板没变化时，每次刷新也只回一句「没变」。Tailscale 的 App 里能看到走的是直连还是中继（relay）。
    • Mac 上要开着 Tailscale。设置里写出 Tailscale 没装、没连上，或者这台 Mac 是带标签的设备（那样就没有「你的设备」可言）时，这条路走不通。
  • 已配对的手机列在同一个地方，写着最近一次来访的时间和地址；点移除，那台手机就再也打不开看板，除非重新配对。手机上在 设置 → 这台手机 里也可以自己取消配对。
  • 跟 Mac 上不一样的地方：session 还是开在 Mac 上（终端、Orca 或后台），手机上看它的对话窗口。Jump 在手机上打开对话窗口，不去跳终端。对话窗口、任务详情都占满整个屏幕，用右上角的 ✕ 关掉（手机上没有 Esc，也没有「外面」可点）。Attach、「用编辑器打开」这些要在 Mac 屏幕上开东西的按钮在手机上不显示。选目录变成手动输入路径。发消息的地方多了一个照片按钮，可以从相册选图片发给 session。跳过权限确认、新 session 开在、结束任务时（要不要停掉它的 session）和快捷短语跟 Mac 上的看板是同一份设置，哪边改了另一边都跟着变：在 Mac 上记住了「停掉它的 session」，在手机上把任务改成 done 也会停掉它在 Mac 上的 session。「留在看板上」在手机上默认是开的。
  • 安全：配对过的手机几乎能做看板能做的一切（例外见下），包括开 session、批准权限请求，也就是相当于能操作这台 Mac 上的 Claude。所以：
    • 只回应局域网里的设备：私有地址（192.168.x、10.x 等），以及和 Mac 在同一个网段的 IPv6 地址（家里的路由器有 IPv6 时手机会用到）。路由器转发进来的公网请求、VPN 过来的连接、用别的域名指过来的网页都会被拒绝；Tailscale 只在打开了也通过 Tailscale 访问时、而且只对你自己的设备例外（见上）。
    • 每台手机一个 256 位的随机 token，Mac 上只存它的哈希；没有 token 的请求什么都做不了，连发过来的数据都不收。一个地址（IPv6 按它所在的 /64 网段算）连续猜错 20 次，会被挡 10 分钟。配对码虽然只有 8 位，但同一时间只有一个，用一次、15 分钟就失效；不管从多少个地址来猜，一共猜错 100 次这个码就作废，设置里会写出来。收起二维码也会作废还没用过的码。Mac 只答应手机做手机版看板用得到的操作（按一张允许清单）：手机不能再去配对别的手机，不能改手机访问的设置，也不能在 Mac 屏幕上打开文件、链接或终端、跳终端，不能改 Mac 的剪贴板，不能新建或修改 Shell 定时任务（Mac 上建好的照样能开关、立即跑）；看板以后新加的操作，默认也只有 Mac 能用。
    • 局域网里传的是明文 HTTP：同一个 Wi-Fi 上有人抓包就能看到内容、偷走 token。只在家里这种你信得过的网络上打开它，在公司、咖啡店这种公共网络上关掉；怀疑 token 泄露了，就在 Mac 上移除那台手机再重新配对。
  • Mac 睡着时手机连不上。端口被占用时设置里会写出来；要换端口，在终端里跑 defaults write local.claudepet boardServerPort 8791，再关掉、打开一次手机访问。

工作目录与链接

旧版本的任务卡上可能还有 category:（分类）这一行。分类已经不用了——任务按项目和职责归类；看板不再显示和编辑它，新建的任务也不再写它。旧卡上的这一行留着不动，不影响任何东西。

工作目录（workdirs）

不需要手动维护：把 session 绑定到任务时，会自动把这个 session 所在的目录记到任务卡上（不记你的主目录和任务根目录）。新建任务时也可以手填。看板据此在 session 的"Bind to task…"下拉里把相关任务排在前面。

关联资源的链接规则

Resources 里的完整网址直接可点。像 QA-9519、bigtest#3248 这样的简写，在任务根目录的 hq.json 里加 links 规则就能变成链接，适用于任何工单系统（Jira、Linear、GitHub Issues……）。按顺序匹配，第一条命中的生效；$1、$2 是正则里的分组：

"links": [
  {"match": "^([\\w.-]+/[\\w.-]+)#(\\d+)", "url": "https://github.com/$1/pull/$2", "kind": "pr"},
  {"match": "^([\\w.-]+)#(\\d+)",            "url": "https://github.com/your-org/$1/pull/$2", "kind": "pr"},
  {"match": "\\b([A-Z][A-Z0-9]+-\\d+)\\b",      "url": "https://your-site.atlassian.net/browse/$1", "kind": "ticket"},
  {"match": "^(ENG-\\d+)$",                   "url": "https://linear.app/your-team/issue/$1", "kind": "ticket"}
]

添加资源时推荐写成"标题 + 网址"，比如 2026-11 QA AWS key leak – action items https://…：看板只显示标题（截断到两三个词），悬停可看完整标题和网址。绑定的 session 也会按这个格式记录。

kind 决定分组：ticket（工单）、pr、doc（文档）、link（其他）。完整网址会按域名自动分类。

哪些算过程链接（不上卡片、写进 HISTORY.md）：除了内置的 Jenkins 构建、GitHub Actions run、GitHub / Jira 评论，还可以在 hq.json 里加 "process_links": ["/releases/runs/"]，每项是一个正则，在完整网址里搜索。

What HQ is

With a dozen Claude Code sessions open, the hard part is no longer the work — it is remembering what each session was doing, what it asked you, and whether you ever answered. HQ moves that state out of the conversations and into files:

ConceptWhat it isLives
Projecta line of work: a goal with an end ("ship hq-v2") or a standing duty ("customer RCAs") — not a directory. Written up in projects/<name>/PROJECT.md, whose brief every session on one of its tasks is givena goal until it is done; a duty for good
Task cardtasks/T-012-slug/TASK.md: goal, status, next step, todos, loguntil the task is done
Asksomething a session needs you to decide or do, kept in asks.jsonl until you answerwith the task
Sessiona working thread bound to one task; close it any timeas long as you like
Leadoptional agent role that owns a kind of taskslong-term

The one rule: the card is the truth, not the conversation. When a session is closed, the next one binds to the same task, reads the card and carries on.

Getting started

  1. Install once, from the claude-pet repo: hq/install.sh --root ~/claude-hq (any directory for your cards). It lists every change first and asks before doing anything; add --no-hooks to get the board without touching Claude's settings. Needs python3. See What install changes.
  2. Open the board: double-click the pet (double-click again to hide it), or right-click → Task Board…. While the board is open the pet shows in the Dock and in Cmd-Tab, so you switch back to it like any window (clicking the Dock icon works too, and restores it when minimised); closing the board takes the icon away. In the menu bar, Close Task Board (Cmd-W) closes it; Quit Claude Pet has no Cmd-Q on purpose, so a stray shortcut can't take the pet away with it.
  3. Click the session count in the status bar at the bottom to open the session list, and bind a running session to a task there — or click New task to create one and bind it.
  4. From then on, work through Needs you; click a task card to open its drawer and message its sessions right there.

Sessions that were already running when HQ was installed should be restarted once so the hooks load.

Four pages · Focus

Focus | Projects & duties | Needs you at the top left switches pages (remembered); each tab carries its count. Focus is the workbench: only the tasks you keep in view — it doesn't reset each day; a task stays until you take it off. Projects & duties is every project, each card naming the tasks waiting on you and the ones running; its number counts open tasks (see Projects & duties). Needs you has three columns: questions to answer, @me todos to do, and what you jotted; the number on its tab counts the first two (it is the only lit one, since only it waits on you). The last tab, Scheduled, holds jobs that run on a timetable — see Scheduled jobs.

  • Four lanes: Focus and a project's page both sort tasks into Needs you, Running, Ready and Blocked. A lane isn't a status stored anywhere: it is worked out from the card's status, its unanswered asks and todos, and its sessions' live state, taking the first that fits, in this order: Needs you — a session of it stopped waiting on you (a prompt to approve or answer); Running — a session working on it, or a command it started still running in the background (a turn that ended with only a waiting command left — a Wait or a Poll — counts for 20 minutes at most; its asks and your todos still show on the card; they aren't your move yet, and it goes back to Needs you once it stops); Blocked — status blocked (waiting on someone else: even with unanswered asks or @me todos — say, work of yours that can only start once someone else has moved — which still show on the card's amber block and in Needs you; when a session asks something new on it, its status goes back to waiting-on-me by itself); Needs you — an unanswered ask, an @me todo, or status waiting-on-me; Ready — every other active task: nothing is running, and starting or resuming a session carries it on. Tick recently done by Focus's title (remembered) for a fifth lane: tasks done in the last 3 days.
  • Drag a card to change its status: dropping a card in another lane sets the task's status to that lane's (statuses go by the lane names): Needs you → waiting-on-me, Ready → active, Blocked → blocked, recently done → done. Running takes no drops — only sessions at work put a task there. Dropped in Blocked, it goes there even with asks or todos of yours open; it stays put only while a session waits on you (a prompt to approve or answer) or is working. When a card stays in Needs you or Running after the change (an ask is still open, a session is still working…), a toast at the bottom says why. In Focus, drag a card up or down within its lane to set your own order.
  • Statuses and lanes share their names: a card stores one of five statuses, and the board calls each by the lane it puts a task in — active is Ready, waiting-on-me is Needs you, blocked is Blocked, plus Done and Abandoned. Running is no status: a task is there while a session works on it, and back in its status's lane once it stops. So a task can sit in another lane than its status's: status Ready, but in Needs you while it has an open ask or a todo of yours, or in Running while a session works. From the CLI, hq set T-012 status=ready and status=needs-you work too.
  • Add to Focus: type an id or title in the box at the top and Add, or click ☆ at a card's top right (it turns ★). New tasks join automatically. Click ★ again to take it off Focus; the task stays.
  • A task card holds only what you need at a glance: the id (its colour is the lane it is in), the project (◆ project / ↻ duty) and the title; when something waits on you, an amber block with the unanswered asks (?) and your @me todos (tick the box right there), two at most, then "N more →". Each ask has Yes / No under it: one click answers it (no note; it goes on to the session as from Needs you, and Undo takes it back). For a note, Later or To todo, click …, the question or "N more →": the drawer opens at that ask. Secretary

Secretary in the top bar opens a standing conversation with a Claude that knows this board. Ask it "How are T-072 and T-071 doing, and what is blocking them?", "What is waiting on me?" or "What looks stuck?". Your todosomething personal that belongs to no task ("call the dentist"): an @me todo on the secretary's card, so it shows in Your todos. Not offered until the secretary is set up

Links in the note are added to that task's refs; screenshot paths go along with what is written. When the model is sure (confidence ≥ 0.7) the note is filed at once; when it isn't, or the note is too short to act on, it stays unsorted and waits for you in Needs you.

  • After you jot: a toast at the bottom of the board says where it went ("Filed: T-012 todo @me"), with Undo; from the shortcut, the cat says it. Sorting takes a few seconds, while the note shows "Sorting…".
  • Quick notes in Needs you: unsorted ones are marked amber. Under each are the model's guess and alternatives; click one to file it there. How sessions and the board connect

Once bound, three hooks make the session follow these rules:

  1. Read the card, work, write back — status, next, todos and log go back to the card. Instead of running hq log / hq set … one call at a time, the session ends its reply with an hq-update block and the Stop hook writes it to the card. Every extra tool call re-reads the whole conversation, so this saves those tokens. Only the block at the end of the reply counts — one quoted or shown as an example mid-reply does not, nor do template lines like <…>. But when the reply's only hq-update has text after it, it isn't skipped silently: it goes back to the session to send again, last. If any line cannot be applied (a misspelt status, a todo it cannot find or that matches several, …), nothing in the block is written and it is sent back to the session once to fix, with the candidate todos listed — so resending the whole block never adds anything twice. A todo, log line or ref already on the card is not added again. A turn longer than two minutes that never touched the card is sent back once to update it. 
    ```hq-update
status: blocked
next: wait for infra's token
state: build is green; waiting on the token
todo: @me send the token request
done: rerun the suite
change: merge #12 => merge #12 and #13
log: picked plan v2 because it is cheaper
ref: PR #9 https://github.com/…/pull/9
```
    Only the lines that changed; todo / done / drop / log / ref / workdir may repeat; state replaces the card's Status section; done / drop / change find the todo by its text; change: old text => new text rewrites an open todo in place (same spot, owner and creation time; HISTORY.md notes it); a ref: to one build, run or comment goes to HISTORY.md rather than the card — ref!: keeps it on the card; project: NAME moves the task to an existing project (no such project: the block goes back — only you make projects). Nothing changed: a block holding just touch.
  2. Questions for you are tracked — the session ends its reply with an hq-asks block, one item per line; each becomes an ask on the board (T-012.3, …). Only a line starting at the left with - or 1. starts a new question; indented lines under it (options a) b), say) belong to it. Several sessions asking at once never share an ask number or lose a question. 
    ```hq-asks
- Approve plan v2?
- Which index?
  a) btree
  b) hash
```
  3. An unanswered ask is never a "no" — open asks are reminded to the session every turn.
  4. The session sees the card's todos — whenever a bound session starts (new, resumed, after /clear or a compaction) it gets the card's open todos, yours (@me) first, then Claude's (each word for word, at most 20 and about 2000 characters; older ones are only counted). Claude's it checks against how things stand and, in its next hq-update, ticks finished ones with done: and drops obsolete ones with drop:; yours it ticks when it sees them done (it just installed for you, say) and, when one moves on, rewrites with change: instead of adding another. Only at start (and, for a session bound from the board, once with its first message after binding), not every turn; to have it check again mid-way, use Tidy todos by the todos.
  5. Your todos don't repeat — sessions are told to make an @me todo one step you can do in one go: PRs to review and merge are one todo, installing is another; and to keep Claude's todos for work the turn won't finish (waiting on CI, a merge, you), never for what it is doing now. A new @me todo from a session that repeats an open one sends the block back with the open one's text, to rewrite it with change: or close it with done: / drop: in the same block. A repeat is: both about installing from main; both about reviewing or merging a PR they share; or the same numbers and nearly the same words. Alike words with other PRs ("merge #110", "merge #111") are not. When it really is a separate step, the session writes todo!: to add it anyway. Todos you add on the board or with hq addtodo are not checked. Ticking todos whose PR merged: see Finished todos.
  6. The session knows its line of work — when the task's project has a PROJECT.md, a bound session gets a note on it whenever it starts (new, resumed, after /clear or a compaction, and on hq bind): the project, goal or duty, its deadline, the first line of its goal, then the whole Brief (at most 2000 characters; past that it is cut and pointed at PROJECT.md), whatever repo the session works in. An empty brief: nothing is said. After that it hears again, with its next message, only when this note changes (the brief, title, kind, status, deadline or first line of the goal is edited, or the task moves to another project); a brief that is gone is reported as no longer applying.
  7. Answer on either side — on the board (delivered next turn), or in the chat (the session records it with an hq-resolved block and the board updates). "Not now" in the chat is later, the board's Later: the ask stays, hidden until tomorrow; later until 2026-12-05: Ping is back then hides it until that day — the board's line says "back Dec 5" and the reason shows under the question. A line that can't be read, names no ask, or puts off one already answered isn't dropped silently: it goes back to the session to fix.
  8. Drafts are not done — anything the session drafted for you to send becomes an @me todo until you tick it.

Use the board for the overview, batches of answers and status changes; talk in the session's terminal for a deep discussion — once bound, what it asks there shows up here too.

Start from existing sessions

A fresh install usually meets a machine full of Claude Code sessions and history. Run /hq-onboard in any Claude Code session (an empty board has a button on Projects & duties that copies it) and Claude turns them into a board:

  1. Reads the sessions and drafts tasks: the last 60 days of transcripts (/hq-onboard 30 for another span), one task per piece of work (several sessions on the same work make one; a one-off question makes none), with status, next step, where it stands, todos, links and a confidence. Every todo names who does it (@me you, @claude a session, or a person's name); hq import refuses one that doesn't — it would show in neither Needs you nor any session's list. Sessions already bound to a task are skipped.
  2. Groups them into lines of work: a project is a line of work, not a directory — one repository often carries several — so tasks are grouped by what they are about: into an existing project where one fits, otherwise into a new duty (a standing responsibility) or project (with an end, maybe under a duty), each with a one-line goal. A default directory only when the whole repository belongs to it.
  3. Asks you: the lines of work first, then the tasks under each. Nothing is created until you confirm; rename, merge, move or drop anything, and it asks about any line it couldn't tell was a duty or a project.
  4. Writes it in one go: Claude writes the whole plan as one JSON file, checks and previews it with hq import FILE --dry-run, then hq import FILE creates everything: projects with a PROJECT.md (kind, goal, parent duty), cards with status, todos and links; live sessions are bound to their tasks and ended ones are recorded on the cards, their history one click away. If anything in the plan is wrong (a name taken, a session that already belongs to a task …) nothing at all is written, and every problem is listed.

Change anything afterwards — on the board, or by asking Claude in any session. Inferred statuses are flagged "verify" in each task's log.

Projects

  • A project is a line of work, not a directory: a goal with an end (kind: goal — "ship hq-v2") or a standing duty (kind: duty — "customer RCAs", "release regression"). A task belongs to one project. A directory (repo) is just a task's workdir: where sessions open, resume and are matched.
  • PROJECT.md: one per project, <root>/projects/<name>/PROJECT.md. Frontmatter: title (display name), kind (goal / duty), status (active / paused / done / abandoned), due (a goal's deadline), parent (the duty a goal sits under), phases (a goal's, in order), auto (a duty's switches for work that comes in by itself: github-review, set up in the Auto intake section; qahub-ci and jira-filter are accepted but make no tasks yet), jira (epics), fixVersions. Sections: Goal (a duty: its scope), Out of scope, Done when (a duty's heading is Healthy when; one - line each, - [x] once it holds), Templates (a ### name each, then title:, goal: and - [ ] @owner todo lines), Auto intake (a ### github-review per source, then key: value lines — see "How a duty gets work" above), Brief (given to every session on one of its tasks: background, conventions, commands, pitfalls), Log. Headings in either language (## Goal, ## 目标, ## 目标 / Goal …); a section runs to the next of these headings, so a ## Commands of your own inside the brief stays in the brief. A duty's status is active or paused. Two projects whose names differ only in case are refused (on macOS they would be one folder). The name is a short id (used by the CLI and a card's project:); the display name goes in title. A project without a PROJECT.md still works — it just has no kind, goal or brief.
  • Directories only suggest: hq.json still keeps each project's name, order and directories; creating a task or binding a session gives a task with no project a default from its directory (the deepest match wins). Give directories only to repos that belong to one project; leave shared repos out, and tasks started there land in "No project" for you to sort. Change it any time in the task; a session can move it with hq-update's project:.
  • On the board: all on Projects & duties — ＋ New project / ＋ New duty (a default directory can come along), drag the cards to reorder, rename, add or remove default directories and delete from a project's side panel, and Assign by directory on the list. Projects from your existing sessions: Start from existing sessions.
  • From a shell: hq project list | show NAME | brief NAME | add NAME [--kind goal|duty] [--title T] [--due DATE] [--parent DUTY] [--path DIR] | set NAME kind=… status=… due=… title=… parent=… phases=A,B auto=… jira=A,B fixVersions=… | section NAME goal|out|done_when|templates|brief [TEXT] | check NAME N [done|open] | paths NAME DIR… | rename OLD NEW | remove NAME --to OTHER | auto | order NAME…. list gives each project's open, done and waiting-on-you counts; show prints it with task counts (open, done, done in the last 7 days, waiting on you); brief prints exactly what sessions are given. section rewrites one section of PROJECT.md (no TEXT: read from stdin); check ticks (or unticks) criterion N of done-when and logs it. Or edit PROJECT.md, or ✎ on the project's page. Only a goal sits under a duty; a duty with projects under it can't become a goal, and renaming or removing a duty moves its projects along or frees them.

The board on your phone

With a phone or iPad on the same Wi-Fi as the Mac, the board opens in the phone's browser and works as it does on the Mac: answer asks, tick todos, read and reply to sessions, approve permission prompts and plans, start a session or resume one. Everything stays on the Mac; the phone is one more window onto it.

  • Turn it on: on the Mac's board, Settings (⚙) → Phone access, tick Open the board from a phone. Claude Pet starts a small web server on the local network (port 8790) and lists the addresses a phone can use (not a VPN's). The first time, the macOS firewall may ask whether ClaudePet should accept incoming network connections: allow it. It may ask again after each reinstall of the pet. If a phone can't connect, check this first.
  • Pair a phone: press Pair a phone for a QR code and an 8-character pairing code (like K7QM-3XPA). Scan the QR code with the phone's camera and open it in Safari: that pairs it. A code works once and lapses after 15 minutes unused: when the phone uses it, the Mac trades it for a token of the phone's own and the code is spent, so someone who saw it pairs nothing.
  • Add to Home Screen: in Safari, Share → Add to Home Screen, and the board opens full screen like an app. Full screen, the page runs under the status bar, where iOS blurs a band a little deeper than the bar; the board's top bar starts below that band on an iPhone and an iPad alike, so the tabs stay clear of it. iOS gives a Home Screen app storage of its own, so Safari's pairing may not come along. When the app shows the pairing page, press Pair a phone on the Mac again and type the 8-character code (case and dashes don't matter). Scanning always opens Safari, so it can't pair the Home Screen app. You can also skip pairing Safari: open one of the addresses listed in Settings in Safari, add it to the Home Screen, and type a code in the app.
  • Away from home, over Tailscale: with Tailscale on both the Mac and the phone, logged in as the same user, also tick Also over Tailscale in Settings → Phone access. A Tailscale address appears below it (http://your-mac.xxx.ts.net:8790): press Pair over Tailscale and pair once more as above. iOS treats each address as a site of its own, so the pairing on the local address doesn't carry over, and the Home Screen needs an icon for this address too. With Tailscale on in the phone, this address works at home and away (at home Tailscale goes straight over the local network), so this one icon can be all you keep.
    • Only devices logged in as the same Tailscale user as this Mac get in: for each device that connects, the pet asks tailscale whois whose it is, and reads not a byte from other people's devices or from tagged servers and gateways. On a company tailnet the admins' rules decide who can reach your Mac, hence this extra check; the pairing code and token are still needed.
    • Tailscale encrypts the whole way (WireGuard): the local network's "anyone on the Wi-Fi can capture it" doesn't apply.
    • The first load can take a long while: when the phone and the Mac can't connect directly, Tailscale goes through one of its relays, sometimes half the world away. The page's files travel compressed and the phone keeps them, so later loads are quick; while the board hasn't changed, each refresh is answered with just "same". Tailscale's app shows whether the way is direct or through a relay.
    • Tailscale must be on in the Mac. Settings says so when Tailscale isn't installed or connected, or the Mac is a tagged device (then there's no user whose devices to let in).
  • Paired phones are listed in the same place, with when and from where each was last seen. Remove one and it can't open the board until paired again. On the phone, Settings → This phone → Unpair does the same from its side.
  • What's different on the phone: sessions still open on the Mac (in a terminal, Orca or the background), and you follow them in their conversation window on the phone. Jump opens the conversation instead of a terminal. A conversation or a task's details fill the screen: close them with ✕ at the top right (a phone has no Esc, and there's no outside to click). Buttons that open something on the Mac's screen (Attach, Open in editor) aren't shown. A folder is typed rather than picked. Message boxes get a photos button to send pictures from the phone. Skip permissions, New sessions open in, Finishing a task (whether to stop its sessions) and the Quick phrases are one setting shared with the Mac's board: change it on either and both follow — with “Stop its sessions” remembered on the Mac, setting a task to done on the phone stops its sessions on the Mac too. "Stay on board" is on by default on the phone.
  • Security: a paired phone can do almost anything the board can (exceptions below), starting sessions and approving permission prompts among them: in effect, it can drive Claude on this Mac. So:
    • Only devices on the local network get an answer: private addresses (192.168.x, 10.x …), and IPv6 addresses in the Mac's own network (what a phone uses when the home router has IPv6). Requests from a forwarded router port, connections over a VPN, and web pages that point another domain at the Mac are refused; Tailscale is the exception only when Also over Tailscale is on, and only for your own devices (see above).
    • Each phone has its own random 256-bit token; the Mac keeps only its hash. A request without one can do nothing; the Mac doesn't even take what it sends. An address (for IPv6, its /64 network) with 20 wrong tokens in a row is shut out for 10 minutes. A pairing code is only 8 characters, but there is one at a time, it works once and lapses in 15 minutes, and after 100 wrong tries in all, from however many addresses, it is cancelled (Settings says so). Hide the code cancels an unused one too. The Mac does only what the phone's board needs (a list of what's allowed): a phone can't pair other phones or change phone access, open a file, a link or a terminal on the Mac's screen, jump to a terminal, change the Mac's clipboard, or make or change a shell job (one made on the Mac can still be switched and run); an operation the board gains later is the Mac's alone until it's added to that list.
    • The local network carries it as plain HTTP: anyone capturing traffic on the same Wi-Fi can read it and take the token. Turn it on at home, on a network you trust, and off on shared ones (office, café). If a token may have leaked, remove that phone on the Mac and pair it again.
  • A sleeping Mac doesn't answer. A port already in use is reported in Settings; to use another, run defaults write local.claudepet boardServerPort 8791 and turn phone access off and on again.

Workdirs and links

Cards from earlier versions may still have a category: line. Categories are retired — projects and duties group tasks now: the board no longer shows or edits them, and new cards don't get one. The line on old cards is left as it is and affects nothing.

Workdirs

They maintain themselves: binding a session to a task records the session's directory on the card (never your home folder or the task root). You can also type one when creating a task. The board uses them to list matching tasks first in a session's "Bind to task…" menu.

Link rules for resources

Full URLs in Resources are clickable as they are. Shorthand like QA-9519 or bigtest#3248 becomes a link once you add links rules to hq.json in your task root — for any tracker (Jira, Linear, GitHub Issues, …). Rules are tried in order and the first match wins; $1, $2 are the regex groups:

"links": [
  {"match": "^([\\w.-]+/[\\w.-]+)#(\\d+)", "url": "https://github.com/$1/pull/$2", "kind": "pr"},
  {"match": "^([\\w.-]+)#(\\d+)",            "url": "https://github.com/your-org/$1/pull/$2", "kind": "pr"},
  {"match": "\\b([A-Z][A-Z0-9]+-\\d+)\\b",      "url": "https://your-site.atlassian.net/browse/$1", "kind": "ticket"},
  {"match": "^(ENG-\\d+)$",                   "url": "https://linear.app/your-team/issue/$1", "kind": "ticket"}
]

When adding a resource, prefer "title + URL", e.g. 2026-11 QA AWS key leak – action items https://…: the board shows the title, cut to a few words, with the full title and URL on hover. Bound sessions record resources the same way.

kind picks the group: ticket, pr, doc or link. Full URLs are grouped by their host automatically.

What counts as a process link (kept off the card, in HISTORY.md): besides the built-in Jenkins builds, GitHub Actions runs and GitHub / Jira comments, add "process_links": ["/releases/runs/"] to hq.json — each one a regex searched for in the full URL.

Leads

Copy templates/lead.md from your task root to .claude/agents/bench-lead.md, describe its scope, then run claude --agent bench-lead in the task root and say "continue T-020". A lead binds to the task, delegates heavy work to background subagents, keeps its own context small and reports in a fixed shape. Small tasks don't need one — the bound session is the lead.

Good to know

  • Only sessions bound to a task have their questions tracked.
  • A background session can only start in a folder you have trusted (open Claude Code there once and accept); otherwise the board says so.
  • Board answers: with send now ticked they arrive at once (Orca / iTerm2 / Terminal / a background session between turns); otherwise at the session's next turn.
  • Messaging works for Orca, iTerm2 and macOS's own Terminal (iTerm2 and Terminal ask for Automation permission the first time — allow Claude Pet to control it; if you said no, turn it on in System Settings → Privacy & Security → Automation). If a typed message hasn't started a turn within 5 seconds (and the session isn't busy), the outbox marks it "may not have gone in" — press Return there (Orca needs a recent version to tell); a / command or a ! line starts no turn, so it counts as sent once typed. A session waiting on a prompt can't be sent to — answer it in the terminal first. In other terminals (Ghostty, VS Code, …) the box is greyed out — Jump only.
  • The session list relies on Claude Pet's hooks; sessions started before the pet was installed don't appear.
